# Wishlist

Unordered ideas with zero commitment. Promotion is a human decision.

- **Authorized review before every State change** — Billy, 2026-07-30. The working agent delivers but cannot approve its own transition. A reviewer group inspects the delivery, its designated Approver or team lead alone authorizes the transition decision, and the Engine verifies that authority before it writes the next State. Keep these semantic reviewer roles distinct from ratmac's mechanical `Guard`; signer identity, group membership, quorum, and authorization mechanism remain undecided. On promotion, this explicitly revisits the revocable adopted default in [machine composition's reviewer-independence requirement](issue/archive/i-018-machine-composition/spec.md#requirement-records) that signer identity remains outside the Engine. Selected 2026-09-22; carried by [authorized review transitions](issue/i-062-authorized-review-transitions/index.md).
- **Make goal fingerprints stable across operating systems** — Advisor, 2026-08-03. Evidence: the goal revision hashes checked-out goal bytes, so the same text checked out with LF or CRLF gets a different fingerprint. Desired end: one canonical cross-platform serialization produces the same revision everywhere, while archived stamps remain valid under a documented forward-only compatibility rule. A human still must choose the canonical form and old-stamp policy; this wish owns line-ending policy rather than spawning a separate warning-cleanup item. Selected 2026-09-22; carried by [portable goal fingerprints](issue/i-055-portable-goal-fingerprints/index.md).
- **Bind self-development completion to the selected issue** — Advisor, 2026-08-04. Evidence: archive tag `trial-archive/trial-002-doctor-full-fingerprint` and durable log `trials/trial-002-doctor-full-fingerprint/trial-log.md` record a Run that reached `passed` from agent-writable `artifacts/release.txt`, while fresh feature tests, candidate output, and independent review were checked only by the human driver. Desired end: a self-development Run can pass only when its guards bind the selected issue to fresh red/green receipts and independent review, so an unrelated writable marker cannot certify completion. A human still must choose the exact receipts, guard, and reviewer-authority contract. Selected 2026-09-22; carried by [selected issue completion](issue/i-042-selected-issue-completion/index.md).
- **Write the Engine ignore rule at initialization** — Billy, 2026-08-06. Desired end: initializing ratmac in a folder records the ignore rule for the Engine root while keeping the Machine Class and receipts tracked, and re-initializing does not duplicate or fight a rule an operator already wrote. A human still must choose which command owns it, whether it edits a shared ignore file or a local one, and what happens when the operator's rule disagrees. Selected 2026-09-22; carried by [engine ignore initialization](issue/i-056-engine-ignore-initialization/index.md).
- **Record a spawned successor before it can be retired** - Advisor, 2026-08-06. In that interval the successor is admitted but unrecorded, and a concurrent abandon can retire a child nobody's ledger names. Independent review confirmed the classification as inherited respawn-locking debt. Desired end: no Run is reachable before the record that owns it exists, under the same root-before-Run discipline the lock split established. No ticket owns respawn locking today. Selected 2026-09-22; carried by [successor ownership](issue/i-048-successor-ownership/index.md).

- **Resolve each Engine root once per invocation** — Advisor, 2026-08-06. Evidence: an independent t-078 review found that `rtm status` for a child Run resolves the root in `src/cli.rs:281`, then again through `refuse_flat_residue` (`src/scheduler.rs:996,618`), `ensure_workspace_in_repository` (`src/scheduler.rs:1093`), the open path (`src/scheduler.rs:563,681`), and `Scheduler::status` (`src/scheduler.rs:3263,681`); `src/root.rs:87-145` falls back to the invoking checkout on any Git-query failure, so those answers can diverge within one report. A third independent review of t-078 on 2026-08-06 found the duplicate-resolution property untestable with any constructible fixture: swapping the root-threading call at `src/cli.rs:285` back to the path-taking `Scheduler::open_run`, or restoring a second `crate::root::resolve` in the argument-free doctor route at `src/cli.rs:667-679`, leaves every assertion green — the same reported root, findings, exit code, JSON bytes, and byte-identical tree — because both resolutions agree in every fixture that can be constructed. Only a resolver-call spy or a fixture whose resolution changes mid-invocation would go red, so the property currently rests on code shape and review alone. Desired end: an Engine invocation has one authoritative resolved root that every boundary and report must use, a route cannot compile if it resolves or renders a different root, and any repair makes a duplicate resolution either impossible to write or observable to a test. A human still must choose where that value lives across Engine entry points. Selected 2026-09-22; carried by [single root resolution](issue/i-059-single-root-resolution/index.md).
- **A runbook node that runs a skill itself powered by a ratmac runbook composes safely: each level owns its own Engine root, the parent consumes only the child Run's terminal receipt as evidence, and runaway recursion (a skill chain that reaches itself again) refuses by name instead of looping** — Billy, 2026-08-09. Desired end: a nested ratmac-powered program is an ordinary black-box invocation with a receipt — no shared state across levels, and a cycle or depth overrun is refused with the offending lineage named. Selected 2026-09-22; carried by [safe nested invocations](issue/i-060-safe-nested-invocations/index.md).
- **One opt-in trace channel for the decisions a debugger cannot replay** - Billy, 2026-08-10. Evidence: the Engine is a short-lived command, so the interesting moments - which edge a transition input selected, why a guard refused, which lock was taken and in what order, what the mint record read and wrote, which root a path resolved through - leave no trace unless they happen to end up in a refusal message. There are 24 direct `eprintln!`/stderr writes scattered across `src/`, each authored for one call site, and a test that wants to see a mid-operation decision has to compile in a pause point (`test-fault-injection`) and stop the process. Desired end: one module owns a trace channel that is off unless a caller asks for it by environment variable, writes to stderr only, never to stdout and never to a file, and emits one structured record per decision with the stable diagnostic code the refusal path already uses. Constraints that make it safe rather than another global: no timestamps, durations, or absolute host paths in the output, so two runs of the same input print the same bytes; no runtime state and no allocation on the off path; nothing a guard or gate may ever read - the trace is for a person reading a failure, never evidence; and the existing stderr writes move into it instead of living beside it. Open before promotion: whether the channel replaces the compiled-in pause points or stays beside them, and whether hidden lanes may assert on trace text at all (they should not - that would make prose a contract again). Selected 2026-09-22; carried by [deterministic trace channel](issue/i-061-deterministic-trace-channel/index.md).
