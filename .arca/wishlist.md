# Wishlist

Unordered ideas with zero commitment. Promotion is a human decision.

- **Use State, not Phase, for machine position** — Billy, 2026-07-30. Replace the public `Phase` term and the Runbook's `phases` vocabulary with `State`; “Phase” suggests a linear process and misstates a general state machine. Before promotion, resolve the existing collision with `State File` and its lifecycle `status` field so “state” does not ambiguously mean the graph position, the persisted artifact, and the whole runtime record. This is a product-language and schema cutover, not a local code rename. If this wish is promoted, settle it before the cycle-as-runbook issue (`i-015`), or the shop's real runbook will first be written in `Phase` vocabulary and later need a format migration; that ordering note does not promote it.
- **Authorized review before every State change** — Billy, 2026-07-30. The working agent delivers but cannot approve its own transition. A reviewer group inspects the delivery, its designated Approver or team lead alone authorizes the transition decision, and the Engine verifies that authority before it writes the next State. Keep these semantic reviewer roles distinct from ratmac's mechanical `Guard`; signer identity, group membership, quorum, and authorization mechanism remain undecided. On promotion, this explicitly revisits the revocable adopted default in [machine composition's reviewer-independence requirement](issue/archive/i-018-machine-composition/spec.md#requirement-records) that signer identity remains outside the Engine.
- **Engine-namespace split** — Billy, 2026-08-03. Move the files the Engine owns or consumes — the runbook, the runs roster, the lock, the receipts — out of `.arca/` into an engine-named root, and make the arca folder roots the contract guards read (`issue|ticket|residual|goal`) runbook data instead of Rust literals, retiring the hard-coded-path debt (R-016). Why: one folder with two writers forces a per-file ownership ledger in the schema; one folder per owner replaces that ledger with a single structural rule, and a second project can adopt `rtm` without minting a folder named after a methodology it does not run. On promotion this rewrites frozen goal text (run layout in FDC-004, receipt paths, the runbook location) and steering identity, so it enters only through a planning pass; its one ordering fact is on the Horizon — land before the cycle-as-runbook issue (`i-015`), or the self-hosting runbook welds the old paths into the shop's own loop. It deliberately leaves the concrete new root to the issue if a human promotes it.
- **Make goal fingerprints stable across operating systems** — Advisor, 2026-08-03. Evidence: the goal revision hashes checked-out goal bytes, so the same text checked out with LF or CRLF gets a different fingerprint. Desired end: one canonical cross-platform serialization produces the same revision everywhere, while archived stamps remain valid under a documented forward-only compatibility rule. A human still must choose the canonical form and old-stamp policy; this wish owns line-ending policy rather than spawning a separate warning-cleanup item.
- **Give executable contributor tools a lane** — Advisor, 2026-08-03. Evidence: `tools/check_links.py`, `tools/rtm.ps1`, and `tools/trial.ps1` execute workflow behavior, but the Program and Shop lane rules give them no explicit owner or carrier. Desired end: put them in either the Program lane or a dedicated tooling lane, with red-first proof or equally durable evidence for changes. A human still must choose the lane, carrier, and evidence standard.
- **Give issue validation its own subsystem** — Billy, 2026-08-04. Evidence: `.arca/schema.md` requires a newly created or selected issue in intake to be `pending`, while `src/contract.rs` and `tools/check_links.py` each enforce issue shape and reject `pending`; this duplicated checking authority creates the pending-status disagreement. Desired end: a standalone issue-validation subsystem, rather than the main RatMac state-machine runner, owns one authority for issue-shape rules and lets a complete pending intake bundle pass its applicable shape check, while RatMac invokes that subsystem through a defined boundary and records its result; unresolved intake still fails at its proper later gate. This wish owns where issue-shape rules live, the one checking authority, and how RatMac invokes and records it; **Engine-namespace split** owns making folder roots runbook data. A human still must choose the subsystem boundary, contract, result record, later gate, and migration.
- **Automate ticket and cycle housekeeping end to end** — Advisor, 2026-08-03. Evidence: each turn or cycle manually repeats worktree opening, private-lane copying, finish/merge/copy-back, archive and link rewrites, map restamping, and sync; only the repetition and time cost are proven, not copy-back data loss. Desired end: one lifecycle with dry-run, rollback or resume, and clear ownership. A human still must choose command boundaries and recovery ownership; if promoted, compose it after the engine-namespace split and with cycle-as-runbook rather than duplicating either.
- **Consolidate hidden-lane support without erasing history** — Advisor, 2026-08-03. Evidence: private regression crates repeat fixtures, process launching, snapshots, and fault setup, while every crate lengthens the full sweep. Desired end: shared fixtures, one process runner, shared snapshots and fault injection, one aggregate runner, disciplined environment isolation, and an explicit current-versus-history policy. A human still must choose shared ownership and the migration boundary; historical archives remain intact, and full-sweep growth belongs to this wish rather than a separate one.
- **Report the complete doctor Engine fingerprint** — Advisor, 2026-08-04. Evidence: [trial-002-doctor-full-fingerprint](../trials/trial-002-doctor-full-fingerprint/trial-log.md) found that argument-free `rtm doctor` prints only a 16-character prefix of the exact executable's SHA-256; a red-first regression passed when the report printed all 64 lowercase hexadecimal characters, matched an independent digest of the test-built executable, and remained write-free. Desired end: `rtm doctor` reports the complete SHA-256 of the exact Engine it runs so its displayed identity is unambiguous. The archived trial is evidence only; its implementation remains disposable under trial policy.
- **Bind self-development completion to the selected issue** — Advisor, 2026-08-04. Evidence: [trial-002-doctor-full-fingerprint](../trials/trial-002-doctor-full-fingerprint/trial-log.md) reached `passed` after an agent-authored `artifacts/release.txt` said `ready: true`; its guards did not read the red/green fingerprint test, candidate output, or independent review, and two false worker claims were caught only by manual rechecking. Desired end: a self-development Run can pass only when its guards bind the selected issue to fresh test evidence and independent review, so an unrelated writable marker cannot certify completion. This wish supplies acceptance evidence to the deferred cycle-as-runbook work; it does not create a second runbook carrier. A human still must choose the exact receipt, guard, and reviewer-authority contract.
