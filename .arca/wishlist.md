# Wishlist

Unordered ideas with zero commitment. Promotion is a human decision.

- **Authorized review before every State change** — Billy, 2026-07-30. The working agent delivers but cannot approve its own transition. A reviewer group inspects the delivery, its designated Approver or team lead alone authorizes the transition decision, and the Engine verifies that authority before it writes the next State. Keep these semantic reviewer roles distinct from ratmac's mechanical `Guard`; signer identity, group membership, quorum, and authorization mechanism remain undecided. On promotion, this explicitly revisits the revocable adopted default in [machine composition's reviewer-independence requirement](issue/archive/i-018-machine-composition/spec.md#requirement-records) that signer identity remains outside the Engine.
- **Make goal fingerprints stable across operating systems** — Advisor, 2026-08-03. Evidence: the goal revision hashes checked-out goal bytes, so the same text checked out with LF or CRLF gets a different fingerprint. Desired end: one canonical cross-platform serialization produces the same revision everywhere, while archived stamps remain valid under a documented forward-only compatibility rule. A human still must choose the canonical form and old-stamp policy; this wish owns line-ending policy rather than spawning a separate warning-cleanup item.
- **Give executable contributor tools a lane** — Advisor, 2026-08-03. Evidence: `tools/check_links.py`, `tools/rtm.ps1`, and `tools/trial.ps1` execute workflow behavior, but the Program and Shop lane rules give them no explicit owner or carrier. Desired end: put them in either the Program lane or a dedicated tooling lane, with red-first proof or equally durable evidence for changes. A human still must choose the lane, carrier, and evidence standard.
- **Automate ticket and cycle housekeeping end to end** — Advisor, 2026-08-03. Evidence: each turn or cycle manually repeats worktree opening, private-lane copying, finish/merge/copy-back, archive and link rewrites, map restamping, and sync; `.arca/log.md:310` records `git worktree remove --force` before `.arca-private/` copy-back, which destroyed t-076's only hidden-lane crate copy. Desired end: one lifecycle with dry-run, rollback or resume, clear ownership, and a single landing command that completes merge, copy-back, worktree removal, and the `main` hidden-lane rerun in order so copy-back cannot be skipped. A human still must choose command boundaries and recovery ownership; if promoted, compose it after the engine-namespace split and with cycle-as-runbook rather than duplicating either.
- **Consolidate hidden-lane support without erasing history** — Advisor, 2026-08-03. Evidence: private regression crates repeat fixtures, process launching, snapshots, and fault setup, while every crate lengthens the full sweep. Desired end: shared fixtures, one process runner, shared snapshots and fault injection, one aggregate runner, disciplined environment isolation, and an explicit current-versus-history policy. A human still must choose shared ownership and the migration boundary; historical archives remain intact, and full-sweep growth belongs to this wish rather than a separate one.
- **Bind self-development completion to the selected issue** — Advisor, 2026-08-04. Evidence: archive tag `trial-archive/trial-002-doctor-full-fingerprint` and durable log `trials/trial-002-doctor-full-fingerprint/trial-log.md` record a Run that reached `passed` from agent-writable `artifacts/release.txt`, while fresh feature tests, candidate output, and independent review were checked only by the human driver. Desired end: a self-development Run can pass only when its guards bind the selected issue to fresh red/green receipts and independent review, so an unrelated writable marker cannot certify completion. A human still must choose the exact receipts, guard, and reviewer-authority contract.
- **Write the Engine ignore rule at initialization** — Billy, 2026-08-06. Evidence: [i-024](issue/archive/i-024-engine-namespace-split/spec.md#requirement-records) settles that `.ratmac/` holds live Run state that must never be committed, but nothing writes that ignore rule, so a fresh project can commit Run state before anyone notices. Desired end: initializing ratmac in a folder records the ignore rule for the Engine root while keeping the Machine Class and receipts tracked, and re-initializing does not duplicate or fight a rule an operator already wrote. A human still must choose which command owns it, whether it edits a shared ignore file or a local one, and what happens when the operator's rule disagrees.
- **Scope the repository audits to tracked files** — Advisor, 2026-08-06. Evidence: `test/qa/tests/t034_rat005.rs::active_reference_audit` and `test/qa/tests/t037_rat008.rs::full_rebrand_acceptance` walk the repository root and descend into ignored directories. During the t-077 landing, the nested Git worktree at `.orca/worktrees/ratmac/exp-ratmac-deterministic`, ignored through `.git/info/exclude`, exposed an older branch's `.arca/` files; its pre-rebrand command and crate spellings, legitimate on that branch, produced 24 unallowlisted active legacy references and made both audits fail. On 2026-08-06, the same commit in a clean linked checkout made with `git worktree add --detach ../ratmac-verify-t077 HEAD` passed 269 tests across 74 suites with 0 failures, while the primary checkout reported 267 passed and these 2 failed. The audits therefore judge a developer's local scratch checkout as if it were repository content. Desired end: tree-scanning acceptance tests read tracked content only, through `git ls-files` or an equivalent repository file list, so an ignored directory beside the work can never turn a green landing red or teach contributors to dismiss red suites as environmental. A human still must decide how an intentionally untracked but audited file is explicitly declared and how the audit receives that declaration.
- **Record a spawned successor before it can be retired** - Advisor, 2026-08-06. Evidence: on the respawn path the Engine mints the successor under a short root lock, releases that Run lock, retires the predecessor, and only then appends the successor's ledger entry (`src/scheduler.rs:1411-1473` at the t-074 landing; the identical sequence exists in the red baseline `01decae:src/scheduler.rs:1224-1288`, so t-074 neither created nor widened it). In that interval the successor is admitted but unrecorded, and a concurrent abandon can retire a child nobody's ledger names. Independent review confirmed the classification as inherited respawn-locking debt. Desired end: no Run is reachable before the record that owns it exists, under the same root-before-Run discipline the lock split established. No ticket owns respawn locking today.
- **Move the held fact out of the ticket file** - Billy, 2026-08-06. Evidence: `ENS-001` in `.arca/goal/spec.md` forbids the Engine writing any file under `.arca/`, and its "except through a root" exception covers reads only, but `src/blocked.rs` still rewrites `.arca/ticket/<id>.md` during `rtm hold` (path built at `src/blocked.rs:211-217`, replacement performed at `src/blocked.rs:481-493`, line surgery in `hold_ticket` at `src/blocked.rs:519-553`), and `src/completion.rs:331-349` re-reads that same ticket to learn a Run is held, so the contributor file is both a write target and the Engine's query index. `.arca/schema.md` and PGE-006 currently mechanize the opposite: "an authorized `rtm hold` marks the ticket held". Desired end: the held fact and its blocker linkage live in an Engine-owned record, every machine consumer reads it there, a declared workflow root may still read the ticket, and any ticket annotation is a shop action performed by the workflow layer. A human still must revise PGE-006, the schema sentence, and the ticket template together, and decide what happens to tickets already carrying `status: "held"`.
- **Settle who may name the pre-split `.arca` namespace** - Billy, 2026-08-06. Desired end: one ruling that says where a retired namespace's names may live and how the literal audit states that exception, so residue detection stays honest without either requirement being quietly bent. A human still must choose whether the names sit in Engine source behind a named exception, in a data file the Engine reads before any runbook, or in a migration tool outside the Engine.

- **Prove residue preflight before every public entry-point action** — Advisor, 2026-08-06. - **Trust a restore only after it re-derives frozen bytes** — Advisor, 2026-08-06. Evidence: with this repository's former `core.autocrlf=true`, `git restore --source=<checkpoint> --staged --worktree -- src/scheduler.rs` left `git status --porcelain` empty, yet restored `src/scheduler.rs` as `92e8aab61123d197...` rather than frozen `9201766f45e74c5a...`; after `core.autocrlf` was set false, a restore round-trip was byte-identical for all seven frozen files. Desired end: a restore is trusted only when it re-derives the frozen hash, and the tree setting that makes byte-identical restores possible is checked rather than assumed.
- **Use the safety commit as the only ticket restore source** — Advisor, 2026-08-06. - **Resolve each Engine root once per invocation** — Advisor, 2026-08-06. Evidence: an independent t-078 review found that `rtm status` for a child Run resolves the root in `src/cli.rs:281`, then again through `refuse_flat_residue` (`src/scheduler.rs:996,618`), `ensure_workspace_in_repository` (`src/scheduler.rs:1093`), the open path (`src/scheduler.rs:563,681`), and `Scheduler::status` (`src/scheduler.rs:3263,681`); `src/root.rs:87-145` falls back to the invoking checkout on any Git-query failure, so those answers can diverge within one report. A third independent review of t-078 on 2026-08-06 found the duplicate-resolution property untestable with any constructible fixture: swapping the root-threading call at `src/cli.rs:285` back to the path-taking `Scheduler::open_run`, or restoring a second `crate::root::resolve` in the argument-free doctor route at `src/cli.rs:667-679`, leaves every assertion green — the same reported root, findings, exit code, JSON bytes, and byte-identical tree — because both resolutions agree in every fixture that can be constructed. Only a resolver-call spy or a fixture whose resolution changes mid-invocation would go red, so the property currently rests on code shape and review alone. Desired end: an Engine invocation has one authoritative resolved root that every boundary and report must use, a route cannot compile if it resolves or renders a different root, and any repair makes a duplicate resolution either impossible to write or observable to a test. A human still must choose where that value lives across Engine entry points.
- **A runbook node that runs a skill itself powered by a ratmac runbook composes safely: each level owns its own Engine root, the parent consumes only the child Run's terminal receipt as evidence, and runaway recursion (a skill chain that reaches itself again) refuses by name instead of looping** — Billy, 2026-08-09. Evidence: .arca/schema.md names a single Engine root `.ratmac/` and defines no behavior for a node whose command is itself a ratmac Run; no depth or lineage guard exists in the Engine today. Desired end: a nested ratmac-powered program is an ordinary black-box invocation with a receipt — no shared state across levels, and a cycle or depth overrun is refused with the offending lineage named.
- **One opt-in trace channel for the decisions a debugger cannot replay** - Billy, 2026-08-10. Evidence: the Engine is a short-lived command, so the interesting moments - which edge a transition input selected, why a guard refused, which lock was taken and in what order, what the mint record read and wrote, which root a path resolved through - leave no trace unless they happen to end up in a refusal message. There are 24 direct `eprintln!`/stderr writes scattered across `src/`, each authored for one call site, and a test that wants to see a mid-operation decision has to compile in a pause point (`test-fault-injection`) and stop the process. Desired end: one module owns a trace channel that is off unless a caller asks for it by environment variable, writes to stderr only, never to stdout and never to a file, and emits one structured record per decision with the stable diagnostic code the refusal path already uses. Constraints that make it safe rather than another global: no timestamps, durations, or absolute host paths in the output, so two runs of the same input print the same bytes; no runtime state and no allocation on the off path; nothing a guard or gate may ever read - the trace is for a person reading a failure, never evidence; and the existing stderr writes move into it instead of living beside it. Open before promotion: whether the channel replaces the compiled-in pause points or stays beside them, and whether hidden lanes may assert on trace text at all (they should not - that would make prose a contract again).
- **The completion gate should not know what a ticket is either** - Billy's ruling of 2026-08-10 applied where it was not yet carried, filed 2026-08-10. Evidence: `NRR-001` took the work-item concept out of the hold, but `src/completion.rs` still parses a contributor's document to decide whether work may pass - it splits on the `## Merge Gate` heading (src/completion.rs:150), collects `HT-nnn-nn` lane ids by shape (src/completion.rs:134), and reads a `ticket-id` field from each receipt (src/completion.rs:307), while receipts live under `.ratmac/evidence/<run-id>/<ticket-id>/`. A generic runner cannot require that document to exist, and a gate that reads the file the agent under test writes is the evidence-not-claim rule inverted. Desired end: the checks a Run must prove are runbook-declared data or Engine-owned state, the evidence path is keyed by something the Engine mints, and a runbook with no work-item concept can still gate completion. Cost is real: this redesigns `PGE-005`'s contract and every receipt path, which is why it is a wish and not a repair. Partly landed 2026-08-10 by `t-089` (`PCR-007`): a receipt-class guard now addresses its item through a binding the Run carries, so no runbook holds a literal ticket id and the evidence path is keyed by what the Engine minted. What remains is the gate's knowledge of the document's shape - the `## Merge Gate` heading and the `HT-nnn-nn` lane ids it still parses.

- **Keep a landed ticket's private lanes runnable, or mark them expired** - Billy's shop, filed 2026-08-10. Evidence: nothing runs `.arca-private/` after a ticket lands, so the lanes rot invisibly. On 2026-08-10 a full sweep found `t-058` through `t-070` refusing against today's Engine because their fixtures build the pre-split `.arca/` layout; `t-071` through `t-083` failed on renames the shop authorized later (`state.toml` -> `run.toml`, the record's `phase` key -> `state`, `Phase:` -> `State:` in reports, the retired hold ticket argument) and were repaired that day; `t-078` and `t-079` refuse by their own design because they pin frozen source hashes that later tickets legitimately moved. - **A held child Run should be looked up in its own class** - found by the `t-090` hidden lanes, filed 2026-08-10. Evidence: `src/blocked.rs:261` asks `scheduler.machine()` for the blocked route, and `src/scheduler.rs:1027` builds that graph from the top-level class only, while `rtm step` resolves a child's State through `resolve_state_scope` (`src/scheduler.rs:2233`, `src/scheduler.rs:3502`). So a child Run occupying a State its class declares is looked up in the parent's transitions, and `rtm hold --run <child>` refuses with `State "work" declares no blocked route` no matter what the child class declares - a composed Run can never be paused. Want: the hold resolves the route in the same scope the step does, with a lane that holds a child and reads the pause back from the child's Run Record.
- **A gap record must never cite a commit that no longer resolves** - Billy's shop, filed 2026-08-10. Evidence: a gap record's `implementation-revision` is written before the landing commit exists, so it cites the checkpoint, and an amend or a squash then leaves it pointing at nothing. Corrected by hand four times now - `res-121` for `t-071`, `res-127` for `t-080`, `res-128` for `t-081` (`.arca/log.md:342`, `:344`), and `res-134` for `t-090` - which is past the line where a repeated fix becomes a check. Want: the record gate resolves every cited revision in the repository and refuses a gap record whose commit is unreachable, so the stamp is proved at closure instead of remembered.
- **The cycle declares no human-authorized pause** - found by the `t-093` hidden lanes, filed 2026-08-10. Evidence: `.ratmac/ratmac.toml` declares no `blocked-route = true` transition on any stage, so `rtm hold` refuses at every stage of a sprint with "declares no blocked route" (`src/scheduler.rs`, PGE-006). A sprint that must stop for an out-of-scope reason has only `rtm abandon`, which retires the Run instead of pausing it. Wanted: one authorized pause route per stage that can legitimately wait, so a blocked sprint keeps its address and its evidence.
