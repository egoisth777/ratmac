# Wishlist

Unordered ideas with zero commitment. Promotion is a human decision.

- **Use State, not Phase, for machine position** — Billy, 2026-07-30. Replace the public `Phase` term and the Runbook's `phases` vocabulary with `State`; “Phase” suggests a linear process and misstates a general state machine. Before promotion, resolve the existing collision with `State File` and its lifecycle `status` field so “state” does not ambiguously mean the graph position, the persisted artifact, and the whole runtime record. This is a product-language and schema cutover, not a local code rename. If this wish is promoted, settle it before the cycle-as-runbook issue (`i-015`), or the shop's real runbook will first be written in `Phase` vocabulary and later need a format migration; that ordering note does not promote it.
- **Authorized review before every State change** — Billy, 2026-07-30. The working agent delivers but cannot approve its own transition. A reviewer group inspects the delivery, its designated Approver or team lead alone authorizes the transition decision, and the Engine verifies that authority before it writes the next State. Keep these semantic reviewer roles distinct from ratmac's mechanical `Guard`; signer identity, group membership, quorum, and authorization mechanism remain undecided. On promotion, this explicitly revisits the revocable adopted default in [machine composition's reviewer-independence requirement](issue/archive/i-018-machine-composition/spec.md#requirement-records) that signer identity remains outside the Engine.
- **Engine-namespace split — promoted** — Billy, 2026-08-03. Move the files the Engine owns or consumes — the runbook, the runs roster, the lock, the receipts — out of `.arca/` into an engine-named root, and make the arca folder roots the contract guards read (`issue|ticket|residual|goal`) runbook data instead of Rust literals, retiring the hard-coded-path debt (R-016). Why: one folder with two writers forces a per-file ownership ledger in the schema; one folder per owner replaces that ledger with a single structural rule, and a second project can adopt `rtm` without minting a folder named after a methodology it does not run. On promotion this rewrites frozen goal text (run layout in FDC-004, receipt paths, the runbook location) and steering identity, so it enters only through a planning pass; its one ordering fact is on the Horizon — land before the cycle-as-runbook issue (`i-015`), or the self-hosting runbook welds the old paths into the shop's own loop. It deliberately leaves the concrete new root to the issue if a human promotes it. Promoted by Billy on 2026-08-06 into [i-024](issue/archive/i-024-engine-namespace-split/spec.md#requirement-records), which names the concrete root `.ratmac/` and one shared Run store per repository.
- **Make goal fingerprints stable across operating systems** — Advisor, 2026-08-03. Evidence: the goal revision hashes checked-out goal bytes, so the same text checked out with LF or CRLF gets a different fingerprint. Desired end: one canonical cross-platform serialization produces the same revision everywhere, while archived stamps remain valid under a documented forward-only compatibility rule. A human still must choose the canonical form and old-stamp policy; this wish owns line-ending policy rather than spawning a separate warning-cleanup item.
- **Give executable contributor tools a lane** — Advisor, 2026-08-03. Evidence: `tools/check_links.py`, `tools/rtm.ps1`, and `tools/trial.ps1` execute workflow behavior, but the Program and Shop lane rules give them no explicit owner or carrier. Desired end: put them in either the Program lane or a dedicated tooling lane, with red-first proof or equally durable evidence for changes. A human still must choose the lane, carrier, and evidence standard.
- **Let pending intake pass its shape check — fulfilled** — Advisor, 2026-08-03. Evidence: the schema requires a newly created or selected issue to have `pending` status, while `tools/check_links.py` rejects every intake status except `integrated` or `rejected`. Desired end: a complete pending bundle is a green shape-check state, while unresolved intake is still rejected if it rests at the proper later gate. A human still must choose that later gate and its owner. Settled on 2026-08-06: `tools/check_links.py` accepts `pending` in intake, matching schema creation rules, while the later gate stays `ratmac::contract::gate_intake`, the P1 exit guard, which still refuses an undecided bundle.
- **Automate ticket and cycle housekeeping end to end** — Advisor, 2026-08-03. Evidence: each turn or cycle manually repeats worktree opening, private-lane copying, finish/merge/copy-back, archive and link rewrites, map restamping, and sync; only the repetition and time cost are proven, not copy-back data loss. Desired end: one lifecycle with dry-run, rollback or resume, and clear ownership. A human still must choose command boundaries and recovery ownership; if promoted, compose it after the engine-namespace split and with cycle-as-runbook rather than duplicating either.
- **Consolidate hidden-lane support without erasing history** — Advisor, 2026-08-03. Evidence: private regression crates repeat fixtures, process launching, snapshots, and fault setup, while every crate lengthens the full sweep. Desired end: shared fixtures, one process runner, shared snapshots and fault injection, one aggregate runner, disciplined environment isolation, and an explicit current-versus-history policy. A human still must choose shared ownership and the migration boundary; historical archives remain intact, and full-sweep growth belongs to this wish rather than a separate one.
- **Report the complete doctor Engine fingerprint — fulfilled** — Advisor, 2026-08-04. The archived self-development trial found that argument-free `rtm doctor` exposed only a 16-character prefix, while its fresh red test and independent review proved the complete exact-executable SHA-256 behavior. Billy routed that result through [i-023](issue/archive/i-023-doctor-full-fingerprint/spec.md#requirement-records); `DFP-001` landed through [t-070](ticket/archive/t-070.md) with no trial implementation bytes copied. Retained here because the requested trial result must remain visible in the wishlist; it is historical evidence, already fulfilled, and not eligible for another promotion.
- **Bind self-development completion to the selected issue** — Advisor, 2026-08-04. Evidence: archive tag `trial-archive/trial-002-doctor-full-fingerprint` and durable log `trials/trial-002-doctor-full-fingerprint/trial-log.md` record a Run that reached `passed` from agent-writable `artifacts/release.txt`, while fresh feature tests, candidate output, and independent review were checked only by the human driver. Desired end: a self-development Run can pass only when its guards bind the selected issue to fresh red/green receipts and independent review, so an unrelated writable marker cannot certify completion. A human still must choose the exact receipts, guard, and reviewer-authority contract.
- **Write the Engine ignore rule at initialization** — Billy, 2026-08-06. Evidence: [i-024](issue/archive/i-024-engine-namespace-split/spec.md#requirement-records) settles that `.ratmac/` holds live Run state that must never be committed, but nothing writes that ignore rule, so a fresh project can commit Run state before anyone notices. Desired end: initializing ratmac in a folder records the ignore rule for the Engine root while keeping the Machine Class and receipts tracked, and re-initializing does not duplicate or fight a rule an operator already wrote. A human still must choose which command owns it, whether it edits a shared ignore file or a local one, and what happens when the operator's rule disagrees.
