| `SVE-005` | Every test that waits on a pause marker - public suites under `test/qa` and declared, non-expired private lanes under `test-hidden` - acts only on the marker's whole boundary line: its complete text, ending in its newline. A missing file, an empty read, or text without its closing newline counts as not yet published; the test keeps waiting until its time limit and never compares, parses, or proceeds on such a read, nor on the file merely existing. A wait therefore fails only when the whole line never arrives in time or arrives with other text, so a pause-seam test never fails on timing alone. A check stages empty and partial markers deterministically and proves every waiter holds until the line is whole. | accepted | Accepted under Billy's 2026-10-26 wish selection after independent contract review. | [Accepted authority](../../schema.md#sve-005--whole-pause-marker-line) |

## Assumptions
- Decision on publishers: the requirement binds waiters, not publishers. A whole-line wait already tolerates a marker that was created before it was filled, which is all the wish's desired end needs, and the checks stage empty and partial markers themselves instead of racing a real publisher, so nothing more is needed to make the rule checkable. The turn tool and the Engine pause points keep their writers. The turn tool keeps writing its marker in place with `WriteAllText`. It does not move a file over the marker path: on Windows, replacing a file that a waiter has open can fail, and the planted-marker check (`SVEV-014`) creates exactly that situation.
- Public suites are included beyond the wish's words, which name private lanes, because they wait on the same markers in the same full workspace proof.
- A pause marker is any file whose path is passed as a `RATMAC_TEST_*_MARKER` setting: the Engine's pause points, the turn tool's pause, and the edition-cut test binary's pause.
- A waiter that knows the exact line waits for that line; a waiter that knows only a prefix (a lock marker naming a path that can be spelled several ways) waits for a newline-terminated line that starts with it.
- Existence-only waits are included even where nothing reads the content afterwards: a file's existence says only that the publisher has started, and one rule for every waiter is what a source check can verify.
