# Issue design
## Proposed mechanics
Give the shared test support one whole-line wait and send every pause-marker wait through it. Add to [the shared test support](../../../test/qa/src/support.rs) a function that polls a marker until its bytes end in a newline and, when the caller knows it, equal the expected line or start with the expected prefix. It returns the line, or at its limit reports the last bytes read (or none); `fn await_marker` in the review before proofs lane (`t-131`) already has this shape.

Replace `fn await_marker` in the byte-verified restores (`t-124`), checkpoint-only restoration (`t-125`), and edition proof preflight (`t-127`) lanes, folding the review before proofs lane's copy into the shared one; `fn wait_boundary` and `fn wait_marked` in the successor ownership lane (`t-122`); the prefix waits `fn wait_for_line_starting` in the safe nested invocations lane (`t-134`) and `fn wait_for_file_prefix` in the authorized review transitions lane (`t-129`); the existence-only waits in the lock split (`t-073`), runbook States (`t-080`), Run Record file (`t-081`), one-command suite proof (`t-086`), no work-item (`t-087`), and deterministic trace channel (`t-128`) lanes; and the lock-marker wait at line 902 of the lock contention lane (`t-136`). In the public suites, replace the waits listed in the specification's evidence: `t050_blocked_route.rs`, `t086_single_engine_binary.rs`, `t122_successor_ownership.rs`, `t125_checkpoint_only_restoration.rs`, `t127_edition_proof_preflight.rs`, `t128_deterministic_trace_channel.rs`, `t130_cycle_pause_routes.rs`, `t134_safe_nested_invocations.rs`, and `t136_lock_contention.rs`. Callers that compared one read afterwards compare the returned line instead. Checks made after the publishing command has exited, that a marker is absent or still there, stay as they are.

Leave every publisher as it is. The turn tool keeps writing its marker in place with `WriteAllText`. It does not move a file over the marker path: on Windows, replacing a file that a waiter has open can fail, and the planted-marker check (`SVEV-014`) creates exactly that situation. Add a source inventory check for marker waits. No new dependency, runner, or registry.

The mechanics implement [SVE-005](spec.md#requirement-records) and are tested by the [verification plan](test-plan.md#verification).

This file is incoming evidence. Integrated mechanics remain authoritative only in the accepted forward authority.
