# Issue design

## Proposed mechanics

Each lane run builds what it runs in a folder no other run touches, and never reads the repository's shared build output.

The work falls into three changes, one requirement and one ticket each. First (`SVE-003`), `run_crate` in [the lane sweep](../../../tools/sweep_lanes.py) asks Cargo where the crate's build would go (`target_directory` from `cargo metadata --format-version 1 --no-deps --offline`, run in the crate, after dropping inherited `CARGO_` variables as today) and, unless `--target-dir` opts in, passes that crate's folder as `--target-dir` on its `cargo test --offline` command line, never in its environment, so no lane process inherits it: the crate's own `target` when Cargo already resolves it there, otherwise a folder named after the crate inside the resolved folder. A Cargo configuration file then still decides where builds are stored but can no longer merge crates. Second (`SVE-007`), the shared support gains one locked-folder helper beside the build function from the test-Engine issue (`SVE-001`): given the lane's name, it opens a folder named after the lane inside the lane's own build output folder, holds the standard library's file lock on a lock file inside it for the whole run, printing one line that names the lock file when it has to wait, and runs every `cargo build` and `cargo test` the lane needs with that folder as `--target-dir`, launching only the executable a build reported. The single-Engine-binary lane (`t-086`) builds both `rtm-qa` and `rtm` there and keeps its before-and-after and identity assertions, and the audit-consumer, lane-sweep, and shared-support lanes (`t-084`, `t-118`, `t-108`, `t-126`) run their `cargo test` through it. Third (`SVE-008`), the freeze build in [the baseline support](../../../test/qa/src/baseline.rs) extracts and builds the freeze tree in a run-private folder, and the pre-split ports lane (`t-109`) sweeps its copied crates, and the pre-split ports suite runs the pre-split crates in place, each into its own run's folder instead of `target/lanes`. The sweep keeps one `cargo test --offline` per crate; no new runner, registry, or dependency. The checks live with the lane-sweep suites, and none holds Cargo's own lock files.

The mechanics implement [SVE-003, SVE-007, and SVE-008](spec.md#requirement-records) and are tested by the [verification plan](test-plan.md#verification).

This file is incoming evidence. Integrated mechanics remain authoritative only in the accepted forward authority.
