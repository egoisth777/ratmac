## Assumptions

- Each requirement is one ticket: the sweep's per-crate output folders (`SVE-003`); private, locked folders for lanes that run Cargo on the repository or on another lane's crate (`SVE-007`); and the run-private freeze build and `target/lanes` (`SVE-008`).
- "Only its own run uses" is met by a per-lane folder held under a cross-process lock for the whole run, so a second run of the same lane waits rather than sharing it; the ticket measures full-sweep time, as the shared private test support rule (`WCP-002`) asks.
- The freeze build becomes run-private: each run extracts and builds the freeze tree in a folder only it uses, and the ticket measures the added build time.
- The sweep's explicit `--target-dir` opt-in stays; only its default changes.
- The sweep names each crate's folder to Cargo on that crate's `cargo test --offline` command line (`--target-dir`), never in its environment, so no lane process inherits it and no lane check can pass only because the sweep moved its output.
- Every lane keeps its identity, requirement, and assertion strength; the single-Engine-binary lane still proves that building the shipped command leaves the test Engine untouched, inside its own folder.
- The forced overlap is deterministic: stand-ins of different bytes fill the shared output, or a plain file takes its place, for the whole window. No check holds or relies on Cargo's own lock files, which are not a documented interface.

## Dependencies

- Depends on the test-Engine issue (`i-063-build-message-test-engine`, `SVE-001`): per-lane folders need helpers that run the reported executable. That issue moves the single-Engine-binary lane (`t-086`) onto the shared helper; this one changes only which folder it builds into.
- Boundaries, not dependencies: the scratch-folder issue (`i-066-unique-test-scratch`, `SVE-004`), which makes test scratch folders unique and leaves the freeze build folder here, and the hold-barrier issue (`i-068-case-scoped-hold-barrier`, `SVE-006`).
- Must not break: the landed-lane sweep (`LNR-001`), its expiry markers (`LNR-002`), the close guard that reads its verdict (`LNR-003`), the shared private test support rule (`WCP-002`), the single-Engine-binary rule (`DEB-001`), and the post-split ports rule (`RLR-003`).

## Open decisions

- Which lock file holds each per-lane folder inside the lane's own build output, and what removes the folders.
- How the sweep learns the configured folder (for example `cargo metadata --no-deps --offline` run in the crate), so that a Cargo configuration file cannot merge crates.

The disposition is set at integration; the linked forward authority then governs implementation.
