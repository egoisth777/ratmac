## Assumptions
- The shared helper is `TempTree` in `test/qa/src/support.rs` (with `TempRepo` built on it); a test that needs a fixed path joins it below its own helper folder instead of naming a folder in the system temporary folder.
- Deleting is allowed only for a test's own folder when it finishes, never to make room for a new one.
- Pinning the clock is a test-support seam only; no Engine code changes.
- The shared-support oracle lane (`t-126`) keeps its independent allocator unchanged: it already puts a counter in each name and creates the folder new. It stops on a taken name instead of retrying; the retry clause binds the shared helper, not this allocator, and a taken name there needs a leftover folder with the same process id, clock value, and counter.

## Dependencies
- Must not break the shared private test support rule ([WCP-002](../../schema.md#wcp-002--shared-private-test-support)): `TempTree` stays standard-library only and reachable from private lanes through the existing source-module include or the `ratmac-qa` dependency, and its check that independent fixtures run concurrently (WCPV-005 in [the test list](../../goal/test-list.md)) keeps passing.
- Boundary, not a dependency: the freeze build folder stays with the issue giving a private lane one verdict everywhere (`i-065`, `SVE-008`).
- If the ticket pins the clock through an environment setting, that setting is a test hook and must stay inside its own case, as the issue about keeping a hold barrier inside its own test case (`i-068`, SVE-006) requires; an argument passed in code avoids the question.

## Open decisions
- How the check pins the clock: a public constructor that takes a fixed stamp, which `new` calls with the real clock, or a support-only setting read inside an isolated child process.
- The order in which the one ticket that carries SVE-004 moves the suite files, the support crate, and `Pair::new`. Its inventory check (`SVEV-012`) stays red until the last folder has moved, and the ticket lands only when every test is green.
The disposition is set at integration; the linked forward authority then governs implementation.
