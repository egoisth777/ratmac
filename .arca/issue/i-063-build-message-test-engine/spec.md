| `SVE-001` | The shared test helper `today_engine()`, and every test helper that runs `cargo build` and then launches the built file itself, runs the executable Cargo reported for that build (the `executable` in its `compiler-artifact` record under `--message-format=json`), never a path joined from a fixed folder such as `target/debug`; helpers where Cargo runs what it built, such as `cargo test`, are out of scope. ## Assumptions

- Cargo reports the `compiler-artifact` record, `executable` included, for a binary that was already up to date as well as for one it rebuilt; the first lane that read build messages itself (`t-117`) already relies on this by requiring exactly one reported executable. The ticket confirms it on the pinned toolchain before the fallback in the TOML-reading lane (`t-133`) goes.
- Exactly one distinct reported path for the named binary counts; none or several refuse by name.
- A failed build's refusal includes the `rendered` text of every `compiler-message` record and Cargo's standard error.
- The helper keeps today's build arguments (offline, package, binary, features) and builds once per test process, as now.
- The shared function lives in the baseline support (`test/qa/src/baseline.rs`) as a `ratmac_qa::baseline` function; the general test support stays standard-library-only.
- The single-Engine-binary lane (`t-086`) moves in this ticket; the lane verdict issue (`i-065-same-lane-verdict`) changes only which folder it builds into.
- The scope is helpers that build from this repository's sources, the freeze tree included; fixtures and the bootstrap are not.
- Migrated lanes keep their identity, requirement, and assertion strength under the history boundary of the shared private test support rule (`WCP-002`), and the frozen before-source corpus stays byte-identical.
- The wish's stale-binary pass was not reproduced here: this checkout holds no binary at the fixed folder, and filing runs no build.
