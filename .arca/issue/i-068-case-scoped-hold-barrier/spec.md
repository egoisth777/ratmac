| `SVE-006` | A test hook that one test case arms through process-wide environment settings (`RATMAC_TEST_*`, such as the Engine's hold test barrier) reaches only that case's own commands. No other case running alongside - in the same test process or another - has its `rtm hold` or any other command wait on the hook, time out on it, or otherwise observe it. This holds in public suites under `test/qa` and declared, non-expired private lanes under `test-hidden`. The arming case still meets its hook, including today's expiry refusal, whose reason reads `hold test barrier expired before <boundary> waiting for <release file>`. A check proves deterministically that an `rtm hold` on another fixture, run while a barrier-armed `rtm hold` is parked, never sees the barrier. | accepted | Accepted under Billy's 2026-10-26 wish selection after independent contract review. | [Accepted authority](../../schema.md#sve-006--case-scoped-test-hooks) |

## Assumptions
- Arming a hook only in the environment of a child command (`.env` on a child started through `support::command`, which first removes inherited `RATMAC_TEST_*` values) is case-scoped by construction. Process-wide arming (`std::env::set_var`, `StepFault::set`, or a lane wrapper around them) counts as case-scoped only inside an isolated child process, inside a child of the test binary that runs exactly one named case, or when every case of that test binary that runs Engine commands in-process holds the hook lane, so no other such case runs at the same time.
- The check needs an in-process hold to run while a barrier-armed hold is parked, so the cycle-pause-routes suite arms the barrier only on its own child commands; serializing its cases under the hook lane cannot pass the check.
- The rule covers every test hook in public suites and current private lanes, wider than the wish's cycle-pause-routes cases, so the inventory keeps every hook inside its case.
- The Engine's seam keeps reading its process environment; no Engine change is needed.

## Dependencies
- Relies on the issue about waiting for the whole pause marker line (`i-067`, SVE-005): the check learns that the armed case is parked from its marker's whole boundary line.
- Must not break the cycle pause routes requirement (WRS-003 in [the goal specification](../../goal/spec.md)) and its checks WRSV-003-01 to WRSV-003-09 in [the test list](../../goal/test-list.md), nor shared private test support ([WCP-002](../../schema.md#wcp-002--shared-private-test-support)): `hook_lane`, `scrub`, and `isolated_test` keep their behavior for private lanes that include the support source or reach it through the `ratmac-qa` dependency, and its check that independent fixtures with conflicting environment values run concurrently (WCPV-005) keeps passing.
- If the issue about unique scratch folders (`i-066`, SVE-004) pins its clock through an environment setting, that setting falls under this rule.

## Open decisions
- Whether suites that keep process-wide hooks in-process (the rule-fix recovery and authorized review transitions suites) move them onto child commands or stay serialized under the hook lane, held to it by the inventory check.
- Whether `HookLane` itself refuses an in-process Engine command from a case that does not hold it while a hook is armed.
The disposition is set at integration; the linked forward authority then governs implementation.
