# Issue design

## Proposed mechanics

The bootstrap reads the pins where the Engine writes them, and compares by file first, then by bytes.

In [rtm.ps1](../../../tools/rtm.ps1), a new `function Resolve-EngineRoot` finds the one shared Engine root the way the Engine (`fn git_repository` in [root.rs](../../../src/root.rs)) and the issue-binding validator (`def engine_root` in [verify_issue_binding.py](../../../tools/verify_issue_binding.py)) find it, query for query, each Git query run in `$root` with `GIT_DIR`, `GIT_COMMON_DIR`, and `GIT_WORK_TREE` removed and restored after: `git rev-parse --is-inside-work-tree` must print `true`; the first record of `git worktree list --porcelain` with no `bare` line must name the primary checkout by an absolute path; and `git rev-parse --path-format=absolute --git-dir --git-common-dir` must print two absolute paths, the first not equal to that checkout. Then the root is `<primary>/.ratmac`; any failed or unsuitable query falls back to `.ratmac` under the checkout that holds the script (`$root`). A new `function Get-LiveRunPins` lists the folders under `<engine root>/runs` in ordinal name order and keeps each whose `run.toml` has a line that, trimmed, reads `status = "planned"` or `status = "executing"`; a record that cannot be read is skipped, as `fn run_is_live` in [channel.rs](../../../src/channel.rs) skips it. For each live Run it calls today's `function Get-EnginePin` on that Run's `evidence.toml` inside `try`, so an absent file, a read error, or an `[engine]` table without `resolved` or `sha256` becomes "no readable pin", carrying the error text when there is one.

The flat read at lines 301-302 goes. Each readable pin is compared with the resolved Engine: the pinned `resolved` and the resolved path, each made absolute with `[System.IO.Path]::GetFullPath` and written with `/`, name the same file when equal (`OrdinalIgnoreCase` when `$IsWindows`, `Ordinal` otherwise). A live Run whose pinned file is the resolved Engine with another hash is collected; if any is, `function Deny` refuses before any report line with today's reason, "the resolved Engine is not the pinned Engine", and for each such Run the lines `<id> pinned this file in <evidence path> [engine]`, today's four observed and expected lines, and `rebuild the pinned revision, or retire the Run with: rtm abandon --run <id> --confirm "abandon <id>"`. Otherwise, after `Engine:` and `sha256:`, the report prints for each live Run `Pin: matches the pin of <id>`, `Pin: <id> pinned another Engine: <pinned path>`, or `Pin: <id> has no readable pin in <evidence path>` (with the error text when there is one), or the one line `Pin: no live Run in <engine root>`. The script's own description of its pin check changes with it.

In [t045_bootstrap_doctor.rs](../../../test/qa/tests/t045_bootstrap_doctor.rs), `fn bootstrap_refuses_pin_mismatch` drops the flat pin for a live Run that the planted Engine starts in a fixture whose runbook has a second State, and `fn bootstrap_resolves_offline` expects `Pin: no live Run in` instead of "no pin recorded". No Engine code changes, and no new tool or dependency.

The mechanics implement [LRP-001](spec.md#requirement-records) and are tested by the [verification plan](test-plan.md#verification).
