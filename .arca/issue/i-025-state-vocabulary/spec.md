# Issue specification

Dispositions below record the author's proposed decision; P1 confirms or revises them at
integration. `SVC` expands to **State vocabulary cutover** and is this issue's stable
requirement-ID prefix, defined in [ubi-lang.md](ubi-lang.md).

## Requirement Records

| Requirement ID | Requirement | Disposition | Rationale | Accepted Forward Authority Refs |
| :--- | :--- | :--- | :--- | :--- |
| `SVC-001` | Three names carry three meanings and never trade places: **State** is where a Run sits in its machine graph, **Run Record** is the one file the Engine writes for one Run, and **Run** is the whole live instance. `status` keeps its present meaning, its five values, and its Engine ownership, and is never a position in the graph. | accepted | The rename is only safe once the word it lands on is free; without this row "state" would mean the position, the file, and the whole runtime record at once, which is the collision the wish demands be settled first. | [goal spec](../../goal/spec.md) |
| `SVC-002` | No live product surface names the machine position `Phase`. The runbook format, every message a caller reads, the doctor's findings, the Run Record's fields, Run evidence, and Engine source identifiers all name it `State`, and the prose a State declares plus its generated guard and input list is the **State Prompt**. | accepted | The written schema is the only way the format is meant to be learned, so a word that misdescribes the machine teaches the wrong model to every reader of it. | [goal spec](../../goal/spec.md) |
| `SVC-003` | The runbook declares `[states.<name>]` under a top-level `states` table, a State's children under `[[states.<name>.spawns]]`, and a child class's machine under `[classes.<name>.states]`. Transition `from` and `to` name States. No other key, guard kind, rule, or diagnostic code of the format changes. | accepted | The format is the surface an author types; leaving it spelled `phases` would keep the wrong word in the one file every adopting project writes by hand. | [goal spec](../../goal/spec.md) |
| `SVC-004` | The Run Record is the file at `.ratmac/runs/<run-id>/run.toml`, and the field naming the Run's position in its graph is `state`. Its remaining fields, its strict parse, its atomic replacement, and its single Engine writer are unchanged. | accepted | A file still named for the old term would leave the settled vocabulary contradicted by the one path an operator reads most; renaming the field without the file keeps the ambiguity alive on disk. | [goal spec](../../goal/spec.md) |
| `SVC-005` | Pre-cutover residue refuses and instructs, and moves nothing: a runbook declaring `phases`, and a Run Record carrying the old position field or sitting at the pre-cutover filename, each make the addressed entry point refuse before any read, join, parse, or write, naming the artifact and the repair. Nothing is migrated in place. | accepted | The project already rules that a stale layout refuses rather than auto-migrating (`FDC-005`, `ENS-009`); a generic unknown-key error would tell an author the key is wrong without telling them the word changed. | [goal spec](../../goal/spec.md) |
| `SVC-006` | Diagnostic identity survives the cutover: a defect that has a code keeps that exact code while its message text changes, the pre-cutover runbook residue gets its own new code, and the documented code table still equals the Engine's. | accepted | `DRD-006` promises a caller branches on the code and never on the text; a vocabulary change that renumbered codes would break every caller that already obeys that promise. | [goal spec](../../goal/spec.md) |
| `SVC-007` | The cutover changes names only. Edge selection, guard evaluation, readiness, routing, freeze and drift, locking, minting, spawning, joining, holding, abandoning, completion, receipts, and exit codes behave exactly as before, and every existing check keeps its meaning. | accepted | A rename that quietly moves behavior cannot be reviewed as a rename; separating the two is what makes the whole cutover provable by comparison against the previous behavior. | [goal spec](../../goal/spec.md) |
| `SVC-008` | Historical bytes are preserved, not rewritten. Archived issue bundles, archived tickets, archived gap records, and `.arca/log.md` keep the old wording exactly, and the audit that proves no live surface says `Phase` carries them as an explicit, enumerated allowlist rather than an unbounded skip. | accepted | The archive rules make a complete, unmodified record the proof of preservation, so an audit that forced history to be rewritten would destroy the evidence it was written to protect. | [goal spec](../../goal/spec.md) |
| `SVC-009` | The working rules and the orientation they point at speak the settled vocabulary: `.arca/schema.md`, `.arca/index.md`, `.arca/dict.md`, `.arca/runbook-spec.md`, `.arca/runbook-authoring.md`, `.arca/steering.md`, and the blank forms in `.arca/tpl/` name State, Run Record, Run, and `status`, and the glossary's `Phase` entry is replaced by entries for State and Run Record. | accepted | The working rules are what a contributor reads before touching anything; leaving them in the old words would make the binding rules contradict the running program, exactly the defect `ENS-011` was written to fix. | [schema](../../schema.md) |
| `SVC-010` | The glossary rule "delete every mention of the old term" applies to live documents only. Where it meets the archive rule that a completed record keeps its bytes, preservation wins, and the glossary says so in its own words. | accepted | The two rules already contradict each other for any renamed term; settling it once in the glossary prevents every future rename from re-litigating whether history must be edited. | [schema](../../schema.md) |

## Out of scope

Who may authorize a State change, and whether a reviewer group must sign a transition, stay
with the separate wish about authorized review; this issue changes what the position is
called, never who may move it. The `failed` outcome keeps its undecided trigger. No guard
kind is added, removed, or re-specified, and no runbook gains or loses a capability. The
two open rulings the engine-namespace sprint is waiting on — where the held fact lives, and
who may name a retired namespace in Engine source — are separate promotions and are not
settled here.
