## Acceptance criteria

- Snapshot audit is sensitive: with a clean tree, evidence recording over the declared roots succeeds and its manifest digests match an independent re-hash; creating one untracked file under a declared root makes the same recording refuse (or list the path as an explicit exception) — both directions are executable tests.
- Archive move round-trip: in a fixture repository, a complete authorized archive move of a completed issue passes the history-preservation oracle; a move that also edits one byte of preserved content fails naming the file; a partial move (one of the five files left behind) fails naming the gap; an in-place content edit without any move still fails. All four cases are executable.
- Default suite is honest on branches: on a feature branch with a pending issue folder present and no opt-in environment configured, `cargo test --workspace` passes and the release acceptance lane reports itself skipped; with the documented opt-in set in an environment that does not satisfy the lane, only that lane fails and its diagnostics name the unsatisfied fact (negative). The opt-in mechanism and its variable or flag are documented in the repository.
- The durable contributor schema (`.arca/index.md`) states the archive authorization and the reviewable-snapshot evidence rule in committed form.
- All proofs run via the QA harness in fixture repositories or the working checkout without requiring commit, push, deployment, network access in the default path, or global installation.
