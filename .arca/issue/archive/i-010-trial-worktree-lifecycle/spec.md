## Acceptance criteria

- Lifecycle round-trip: in a temporary Git repository with an experiment base, start → trial work → finish leaves the base with exactly one new commit containing only `trials/<trial-branch>/trial-log.md`, the archive tag at the terminal trial commit, no trial branch, and no trial worktree; the printed recovery commands then restore the trial branch pointing at the identical commit (positive plus recovery proof).
- Refusal honesty: each refusal case — staged, unstaged, or untracked base changes; duplicate branch, worktree, sibling directory, tag, or durable destination; malformed slug or number; dirty trial worktree; missing or invalid log; working directory inside the trial worktree; locked worktree directory; same-named tag at a different commit — exits non-zero with a named reason and leaves refs, index, working tree, tags, and worktree registrations byte-identical (negative).
- Determinism: identical repository states yield identical inferred identities in dry-run output; after a finished trial is archived, its number is never re-inferred and an explicit request for it is refused naming the surviving tag or durable directory.
- Read-only proof: status/dry-run runs before-and-after snapshot-identical both in fixtures and as a real smoke in this checkout, and its output names planned mutations and recovery commands for start and finish.
- Sync policy: in fixtures, a fix committed on `main` reaches the experiment base only through the explicit merge path from a clean base; a conflicting merge stops with conflict markers left visible and nothing auto-resolved or auto-aborted; an audit of the interface surface finds no push, network, global-install, reset, rebase, or unguarded force operation.
- All proofs run as executable positive and negative fixture tests in temporary Git repositories and worktrees, plus the one real read-only dry-run smoke; creating this issue requires no commit, push, deployment, network access, or global configuration change, and nothing is staged by its creation.
