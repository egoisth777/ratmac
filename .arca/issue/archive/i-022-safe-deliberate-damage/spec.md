# Issue specification

Dispositions below are final: planning step 1 (P1) integrated this bundle on 2026-08-03. `SDC` expands
to **Safe Deliberate-damage Checks**, defined in [ubi-lang.md](ubi-lang.md).

The accepted asks are working-authority requirements: each resolves to its requirement-ID heading in
`.arca/schema.md`, and mints no goal row, no gap record, and no ticket - the branch planning step 1
gained in this same pass.

## Requirement Records

| `SDC-001` | The working rules carry the discard guard as one findable, binding rule: no contributor runs a discard command - `git checkout -- <path>`, `git restore`, `git clean`, `git reset --hard`, dropping a stash, or any other command that throws away uncommitted changes - while the working tree holds unsaved completed work; before any discard, look (`git status`, then `git diff`), then save as a commit or park (`git stash push -m "t-<id>: <what>"`) whatever is wanted beyond what the discard removes. The rule bans discarding unsaved work, never version-control restoration. | accepted | The `t-064` loss ([incident record](../../../ticket/archive/t-064.md)) happened exactly here: the discard ran while the completed fix was unsaved and unstaged. A total restoration ban was rejected by human ruling - restoring saved bytes from a checkpoint is safer than hand-written inverse edits. | [`SDC-001` - the discard guard](../../../schema.md#sdc-001--the-discard-guard) |
| `SDC-002` | The working rules require every deliberate-damage check to run from an ephemeral safety commit - subject exactly `t-<id>: checkpoint - not a landing`; unpublished, unmerged, never a Landing, no log line - limit damage to paths the checkpoint tracks, and fix the undo as checkpoint-sourced restoration, `git restore --source=<checkpoint> --staged --worktree -- <paths>`, verified clean afterward (`git status --porcelain` prints nothing). Hand-written inverse edits are not the standard undo. | accepted | Plain `git restore <paths>` and `git checkout -- <paths>` copy index bytes that may be stale - the exact `t-064` failure mode; an explicit `--source` restore over index and worktree cannot re-lose the work, because everything wanted is already committed. | [`SDC-002` - damage only from a checkpoint](../../../schema.md#sdc-002--damage-only-from-a-checkpoint) |
