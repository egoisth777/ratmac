# Ticket: t-111 - Close turns with fresh expiry-aware verification

## Vertical Outcome

A close with passing and explicitly expired crates succeeds without manual
reinterpretation; a current failure or incomplete roster still refuses by
name. The generic turn tool executes declared policy rather than parsing
markers. Final verification can be retried after cleanup without repeating
any earlier mutation, and the old per-lane default still works.

## Worktree Scope

- **Included:** `tools/turn.ps1`; `.ratmac/turn.toml`; the new focused test
  `test/qa/tests/t111_turn_close_expiry.rs`; six lanes in `test-hidden/t-111/`;
  `.ratmac/lanes.toml` adds this new crate under RLR-004; required ticket,
  gap, receipt, snapshot, and landing records; the full verification sweep
  refreshes `.ratmac/evidence/lane-sweep/report.md` for the later cycle close.
- **Excluded:** `src/`, the Machine Class `.ratmac/ratmac.toml`, changes to the
  sweep's parser or verdict rules, marker creation/removal/renewal, migration
  of existing per-lane fixture declarations, new dependencies or a journal.
- **Mechanism:** optional `lanes-rerun-scope = "per-lane" | "root-once"`,
  defaulting to the existing per-lane behavior. The repository selects
  root-once and declares `python tools/sweep_lanes.py sweep --report
  target/turn-close-lanes.md && python tools/sweep_lanes.py check --report
  target/turn-close-lanes.md`. The ignored report leaves the tracked
  cycle-close report untouched during routine ticket closure.
- **Retry proof:** no item branch, worktree registration, or worktree folder;
  item stamp equals the current trunk short tip; supplied landing line is
  present; no unrelated tracked dirt. Only then may a branchless close retry
  the whole final verification. No per-crate exactly-once promise is made.
- **Self-upgrade:** the first close loads the old primary script/declaration
  before merge and may finish cleanup then stop at the known expired crate.
  Retry the identical close with the newly merged tool; it must prove the
  completed steps and run only the new verifier. Do not bypass closure by
  manually declaring that expected failure successful.

### Test review before implementation

The focused tests read the shipped verifier declaration rather than installing
a test-only correct profile. Fresh-report twins catch check-only verification;
a named stray catches sweep-only verification. Byte comparisons protect
markers, stamps, logs, and dry-run output boundaries. Generic commands prove
scope without relying on expiry filenames.

Review corrected one over-strict retry oracle: an existing item branch may
legitimately use ordinary interrupted-close recovery. The invalid retry twin
now leaves that branch absent and puts a detached registration at its former
worktree path. The hidden recovery check also retains a stale registration
after deleting its fixture directory, and allows an unrelated worktree.
Neither test requires active issue or ticket record locations after archive.
The parent records the actual failing runs and subsequent fault catches;
fixture-author smoke checks are not accepted as ticket completion evidence.

### Implementation-run review

Actual runs corrected fixture assumptions without changing their contracts:
Git registration paths use forward slashes on Windows; a declared value may
carry an inline comment; invalid close declarations are installed after a
valid open; an existing build-output folder is not evidence that verification
ran there; separate landings need distinct log messages. Exact registration
matching and the verifier's own output file keep those assertions strict.

The retry tests also caught a real PowerShell variable collision: the
registration loop's local name hid the caller's landing line. Renaming that
local preserves the log proof. A wrong-case scope exposed case-insensitive
acceptance and now has its own rejection check. The existing turn regression
required its established close-plan label; the tool retains that label and
adds the scope rather than weakening the older test.

All twelve runtime completion receipts pass against the same source fingerprint:
three focused checks, six hidden lanes, workspace tests, formatting, and static
checks. Documentation links pass too. An overlapping broad check initially
made the sweep refuse t-073 because Windows would not remove its running
`rtm.exe`; this was a build-lock failure, not a retired contract. No source
or marker changed: all six t-073 checks passed alone, then the serialized
verification sweep passed with 52 passing crates and two verified explicit
expiries, no red or missing crate. Keep broad checks that share these
executables separate.

The first completion submission used the QA tag reader's identities. The
Engine refused without advancing: CGD-003 remains deferred, so its reader
still needs planned IDs, backticked hidden IDs, and backticked Merge Gate
commands. The three focused checks were rerun under TCEV-001 through TCEV-003;
the full-suite receipt remains supplementary evidence outside the gate set.
The tag lists stay unchanged and the compatible prose names every check.
