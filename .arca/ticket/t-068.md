# Ticket: t-068 — The one-level recursion cap

## Vertical Outcome

Composition is capped at one level. A spawn addressed to a Run that is recorded as a child in any
spawn ledger refuses, naming the cap - before any write, so the refused boundary leaves ledger,
roster, and state byte-identical. A top-level parent keeps spawning freely: the cap is depth, not
count. The check lives at the spawn boundary so lifting it later is additive.

## Worktree Scope

- **Included:** `src/scheduler.rs` spawn-boundary cap check (is the addressed parent a
  ledger-recorded child anywhere?), `src/ledger.rs` child-membership lookup,
  `test/qa/tests/t068_recursion_cap.rs`, `.arca-private/t-068/` hidden lanes.
- **Excluded:** any depth configuration or lift mechanism (a later issue), respawn semantics
  (a superseded child's successor is still a child - the cap must hold across respawn),
  join, reviewer flow.
- **Expected merge/output:** the cap check runs with the other spawn preconditions (t-065) and
  before the ledger append (t-066); its refusal message names the one-level cap.
- **Superseded-test fate:** none expected - no prior oracle lets a child spawn.
