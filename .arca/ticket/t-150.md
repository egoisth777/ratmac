# Ticket: t-150 — endpoint release window

## Vertical Outcome

A resumed child Engine endpoint that meets a peer's release window on the child Run's lock, when it claims that lock or when it takes its terminal read under it, waits within the lock module's five-second wait bound and claims or reads once the window closes; a release window is never treated as a held lock. Only a live holder makes the resumed claim refuse, with today's message `rtm: endpoint: the child Run lock for <id> is held; retry once it frees`, and a window that outlasts the bound refuses with today's open error, `rtm: endpoint: cannot open lock <path>: <error>`. Both places already retry this way, so no product behavior changes: the work is a named check that puts a real release window at both places and fails if the window is treated as held, so a resumed child neither refuses a passing window nor launches its declared driver again on a finished Run.

## Worktree Scope

Implement only [the accepted endpoint release window issue](../issue/i-073-endpoint-release-window/spec.md).
Existing source boundaries: `src/endpoint.rs`, where `fn terminal_snapshot` and the resumed claim each gain one test-only pause at the first retry within each call, with a boundary value naming the place (`claim` or `terminal-read`), and `src/nested.rs`, where the endpoint's pause seams are declared. The pause has its own selector, so it combines with the endpoint's existing after-admission pause (`after-admit`); it follows the pause pattern there (a selector, a marker file, a release file, and a timeout) and compiles only with the `test-fault-injection` feature. Neither place's retry, the lock module's single try (`RunLock::try_acquire` in `src/lock.rs`), nor the fresh mint's single try in `src/scheduler.rs` changes; if the checks find the retry broken, the repair stays inside the two endpoint places and the single try's contract: a window is an error, and a live holder is "not acquired". The issue left two choices to this ticket, settled here: the endpoint shows it met the window through that first-retry pause, and the peer that opens the window is the child Run's own `rtm step`, run in the child's Engine root with the lock module's unlink hold (`RATMAC_TEST_LOCK_HOLD=unlink`), or with its `release` hold for the live holder, on a child that is already terminal, which that step cannot move because it claims the child Run's lock before it looks at the Run's state. Every seam setting is passed only to the child process the test starts, never set for the whole test process. The checks run on Windows, where release windows exist; elsewhere they assert the same outcome without a window. Add only the directly required module or command wiring where the accepted design calls for it; keep unrelated behavior unchanged. The implementing turn also owns its public suite, private crate, this ticket, its gap record, and the roster entry for its new private crate. Any necessary existing regression adjustment must cite the exact newly accepted contract; never weaken an unrelated assertion.
