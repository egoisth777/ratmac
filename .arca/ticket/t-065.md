# Ticket: t-065 — Authorization by motion kind

## Vertical Outcome

Authorization splits by motion kind. `rtm spawn` creates a child Run from a class the parent's
runbook declares, legal only while the parent occupies the spawning Phase - ordinary checked
motion, no confirmation phrase. `rtm respawn --run <id>` and abandon-with-run-id refuse without a
confirmation phrase naming that run id and proceed with one; the phrase is typed at invocation,
never read from a file. Every refusal is recorded behavioral evidence - exit code and message -
with state, history, and lock byte-identical.

## Worktree Scope

- **Included:** `src/cli.rs` two new verbs plus the abandon phrase surface, `src/abandon.rs`
  `required_phrase` names the addressed run id, `src/scheduler.rs` spawn entry (parent live, Phase
  declares the spawn, class declared, child minted as an ordinary flat top-level Run) and respawn
  plan (successor id minted, superseded child retired by the abandon path),
  `test/qa/tests/t065_motion_authorization.rs`, `.arca-private/t-065/` hidden lanes,
  `.arca/runbook-authoring.md` verb notes.
- **Excluded:** spawn-ledger content (t-066 - this turn spawns without writing the ledger),
  the recursion cap (t-068), join evaluation, signer identity (ORS-001 keeps it outside).
- **Expected merge/output:** spawn refuses outside the spawning Phase or for an undeclared class
  before any write; respawn/abandon phrase checks run before the first write exactly as today's
  abandon does.
- **Superseded-test fate:** every public or hidden oracle pinning the phrase literal
  `abandon <project directory name>` (t-051, t-063 lanes) gets the narrow correction to the
  run-id-naming phrase; all other abandonment oracles (append-only prefix, one event, all-or-none)
  stay intact.
