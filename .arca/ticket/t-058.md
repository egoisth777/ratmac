# Ticket: t-058 — Run residency: the plural runs layout and `--run` addressing

## Vertical Outcome

Runs reside canonically under the plural runs path: `rtm start` mints a run id in the single id
namespace and creates `.arca/runs/<id>/` holding that run's Scheduler-owned files (the durable
State File and the Run evidence), so listing `.arca/runs/` IS the roster — run identity is read
off artifacts, never off a narrated index. The run's verdict slot and per-run spawn-ledger path
are reserved under its directory by name only; their contracts (contents, when written, meaning)
stay with the machine-composition issue ([i-018-machine-composition](../issue/i-018-machine-composition/spec.md))
and are not exercised here. Every command that acts on an existing Run — `status`, `step`,
`hold`, `abandon` — requires `--run <id>`; a missing value refuses and prints the roster,
and that refusal is recorded as behavioral evidence. This supersedes `R-023` (no run-id in v1)
and its check `T-09`.

## Worktree Scope

- **Included:** `src/scheduler.rs` and `src/cli.rs` (validate a caller-supplied run id as one
  canonical minted path segment and require exact roster membership before joining it to
  `.arca/runs/`), `src/hold.rs`/`src/abandon.rs` address call sites, and QA probes that place
  valid-looking State Files behind absolute, traversing, separator-bearing, and hand-made
  non-canonical addresses. Every refusal prints the roster and leaves every candidate tree
  byte-identical.
- **Excluded:** the runbook hash pin and the flat-layout-residue refusal (t-059); lifting the
  active-Run cap, never-reissue, and respawn minting (t-060); transition-input selection
  (t-061); verdict content and live-slot lifecycle (t-062); spawn-ledger content (i-018).
- **Expected merge/output:** the prior plural residency remains, while every existing-Run
  operation accepts only a canonical id actually on the roster and never lets an id influence a
  path outside its exact `.arca/runs/<id>/` child.
- **Superseded-test fate:** the already-deleted
  `test/qa/tests/t013_r023.rs::step_and_status_target_active_run_without_run_id` proved the
  no-run-id behavior `FDC-004` superseded. The current
  `test/qa/tests/t059_run_residency.rs::runs_reside_under_the_plural_path` plus hidden
  t-058/t-059/t-060 created-file assertions still require an empty `verdict.toml`; `FDC-003`
  supersedes those assertions. Ticket t-062 replaces them with `FDCV-020` while preserving the
  verdict-slot address and the `spawn-ledger` reservation.

## P5 notes (2026-07-30)

**What landed.** Runs reside canonically under the plural runs path. `rtm start` mints the next
ordinal id off the roster, creates `.arca/runs/<id>/` under the invocation lock, writes the run's
State File and Run evidence there, and reserves `verdict.toml` and `spawn-ledger` by name only

miscounts. No flat `.arca/state.toml` is ever written. `status`/`step`/`hold`/`abandon` all

the roster (the listing of `.arca/runs/`); `status --run` is byte-provably read-only; `step --run`
advances exactly the named run. The second-live-run refusal now reads the plural roster (a live
