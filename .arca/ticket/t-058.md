# Ticket: t-058 — Run residency: the plural runs layout and `--run` addressing

## Vertical Outcome

Runs reside canonically under the plural runs path: `rtm start` mints a run id in the single id
namespace and creates `.arca/runs/<id>/` holding that run's Scheduler-owned files (the durable
State File and the Run evidence), so listing `.arca/runs/` IS the roster — run identity is read
off artifacts, never off a narrated index. The run's verdict slot and per-run spawn-ledger path
are reserved under its directory by name only; their contracts (contents, when written, meaning)
stay with the machine-composition issue ([i-018-machine-composition](../issue/i-018-machine-composition/spec.md))
and are not exercised here. Every command that acts on an existing Run — `status`, `step`,
`hold`, `abandon` — requires `--run <id>`; a missing value refuses and prints the roster,
and that refusal is recorded as behavioral evidence. This supersedes `R-023` (no run-id in v1)
and its check `T-09`.

## Worktree Scope

- **Included:** `src/scheduler.rs` (start mints an id, creates the run directory, and reads and
  writes state there; the flat `.arca/state.toml` is no longer written), `src/state.rs` (state
  path under the run directory), `src/pin.rs` (evidence path under the run directory),

  migration of every QA call site that drives `start`/`status`/`step`/`hold`/`abandon` to the
  new addressing. Safe-default reserved names, revisable in the worktree: `verdict.toml` and
  `spawn-ledger` under `.arca/runs/<id>/`.
- **Excluded:** the runbook hash pin and the flat-layout-residue refusal (t-059); lifting the
  active-Run cap, never-reissue, and respawn minting (t-060) — `start` here still refuses a
  second live Run, only the refusal now reads the plural roster instead of the flat path; any
  ledger or verdict content (i-018).
- **Expected merge/output:** one run directory per run id under `.arca/runs/`, addressed
  explicitly by `--run <id>` everywhere, with the superseded no-run-id proof retired.
- **Superseded-test fate:** `test/qa/tests/t013_r023.rs::step_and_status_target_active_run_without_run_id`
  proves the exact behavior `FDC-004` supersedes (`T-09`/`R-023`). It and its fixture
