# Ticket: t-148 — skill move retry

## Vertical Outcome

`rtm skill <folder>` finishes moving its partial folder into place when another program briefly holds a just-written file inside it open: on Windows a move refused with an access denial (raw code 5) is retried within the lock module's five-second wait bound, measured from the first denial, and succeeds with today's output once the hold ends; the written bytes do not change. A denial outlasting the bound, or any other move failure at once, a sharing violation (raw code 32) included, refuses with today's message `rtm: skill: cannot write <path>: <error>` (exit code 2), tries to remove the partial folder as today, and leaves the requested path absent. Before every attempt it checks the requested path; if something exists there, it tries to remove the partial folder and refuses with today's `already exists` refusal instead of moving or waiting. Other platforms keep the single try, and no lock is taken.

## Worktree Scope

Implement only [the accepted skill move retry issue](../issue/i-071-skill-move-retry/spec.md).
Existing source boundaries: `src/skill.rs`, where the single move in `fn write_skill_in` becomes the bounded loop, and its two test-only pauses, one before the first attempt's check of the requested path and one after the first denied move, which compile only with the `test-fault-injection` feature and reuse the pause pattern of `src/nested.rs` (a selector, a marker file, a release file, and a timeout). The two choices the issue left open are settled here. The Windows access-denial test lives in the skill module, so this ticket leaves the lock module (`src/lock.rs`) unchanged and only reads its wait bound (`WAIT_TIMEOUT`). The checks' hold opens the file for reading with read, write, and delete sharing, the least exclusive hold another program can take; if that hold does not deny the move on this host, the checks use the sharing mode that does and name it. Because the checks wait for the pause after a denied move, a hold that reproduces no denial fails them instead of passing unheld. `rtm profile`'s single-try move stays out of scope.
