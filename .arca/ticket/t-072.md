# Ticket: t-072 — One repository-wide id namespace with a durable mint record

## Vertical Outcome

All checkouts and linked worktrees of one repository see one roster and one Run identifier
namespace. Minting reserves the next ordinal in `.ratmac/mint.toml` while holding the root
lock, so removing a Run directory cannot make that identifier available again; uncapped,
explicitly addressed Runs retain the FDC-004 and FDC-006 contracts.

## Worktree Scope

- **Included:** repository-root roster access introduced by `t-071`; durable mint-record
  read, validation, advancement, and atomic persistence; use of that record for start,
  spawn, and respawn identity allocation; cross-worktree Run addressing; replacement QA
  coverage in `test/qa/tests/t072_repository_namespace.rs`; and six private lane checks.
- **Excluded:** the detailed root/per-Run lock implementation belongs to `t-073`; child
  workspace binding belongs to `t-074`; Engine logging, roots-table validation, legacy
  residue refusal, and root reporting belong to their respective later tickets. No Run
  identifier is renumbered or recycled as a migration shortcut.
- **Expected merge/output:** a Run made through any checkout is a direct member of the
  primary root's roster from every other checkout, and the high-water mark in `mint.toml`
  survives deletion of Run directories and process restarts.
- **Superseded-test fate:** roster-derived next-id assertions that rely on retired
  directories staying present are replaced with mint-record assertions; canonical
  `--run <id>` validation, uncapped starts, and independent sibling motion remain
  regression requirements.

## P5 notes (2026-08-06)

- **Change.** `src/mint.rs` owns the one-key `highest = <non-negative TOML integer>` record in
  the readable domain `0..=i64::MAX`. It rejects every malformed, missing, non-integer,
  negative, or unknown-key record by name; bootstraps a missing record from the canonical
  roster; writes a synced sibling temporary file and replaces the target; refuses an exhausted
  namespace with `mint namespace exhausted:`; and returns `run-NNN` only after recording the
  new maximum. The module documents the existing caller-held root lock as its precondition and
  takes no second lock. `Scheduler::mint_run` now reaches it for start, spawn, and respawn.
- **Durability contract.** Stated per platform in `src/mint.rs` and claimed no wider: Unix
  syncs the temporary file, renames, then syncs the parent directory; Windows syncs the
  temporary file and requests a write-through replacement (`MoveFileExW` with
  `MOVEFILE_REPLACE_EXISTING | MOVEFILE_WRITE_THROUGH`). When a Windows replacement fails and
  leaves no readable target, the synced temporary file is preserved and the refusal names both
  paths, so a failed write can never destroy the last copy of the record.
- **Regression fate.** The ticket's record assertion now reads numeric `highest` rather than
  the old `highest-issued` Run-id string. The pre-existing uncapped-runs checks remain intact:
  they assert distinct fresh identities and retained retired directories, not a next-id
  calculation derived solely from the roster. The Worktree Scope's superseded-test clause
  therefore covers the record-assertion rewrite and does not justify weakening those checks.
- **Private lanes.** All six checks in `.arca-private/t-072` passed: uncapped/addressing,
  hostile routing, sibling lifecycle isolation across a removed newest directory, durability
  and record-defect refusal, primary-only runtime output, and primary-spawn/linked-move/join
  composition. Lane strength was measured rather than assumed: against the first green source
  the extended `HT-072-04` fails by minting `run-9223372036854775808`, and against the red
  commit `1051789` two lanes fail. The other four are honest regression guards that the red
  commit already satisfied; they do not prove the mint record.
- **Mutation evidence.** From the ephemeral safety checkpoint, resolving the Engine root from
  the linked checkout made ENSV-004 reject the primary child as out of roster; discarding the
  high-water calculation made ENSV-005 reissue `run-001` after deletion. Each source file was
  restored from the checkpoint and the tree was clean before this evidence was written.
- **Independent review.** `t072-review` REJECTED the first green attempt with two source
  defects. First, `read_highest` parsed through TOML's signed integer while `persist` wrote a
  `u64`, so a record seeded at `i64::MAX` minted `run-9223372036854775808` and the following
  start could not read the Engine's own file. Second, the Windows path replaced without
  write-through and deleted the temporary file on every failure, including the ambiguous
  `ReplaceFileW` case where the target was already gone. Both are repaired in this landing and
  are now covered by `HT-072-04`. The review also recorded two findings outside this ticket:
  the root lock is held while an external command guard runs, and `abandon` removes an extant
  `root.lock` without owning it. Both belong to the lock split in `t-073` and are recorded
  there rather than silently closed here.
- **Reviewable snapshot.** `.arca/residual/manifest/2026-08-06-res-108-109.txt` records 540
  `src`, `test`, and `.arca` rows with their tracking state and SHA-256; its own output path is
  the explicit snapshot exception, so the green evidence can be reconstructed from the staged landing.
