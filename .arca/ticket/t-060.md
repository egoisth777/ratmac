# Ticket: t-060 — Uncapped runs: never-reissued ids, respawn mints a new id

## Vertical Outcome

Multi-run is uncapped: `rtm start` no longer refuses while another Run is live — the
"cannot start: an active Run already exists" check is removed, and any number of runs
coexist under `.arca/runs/`, each addressed by its own id. Within the one run-id
namespace an id is never reissued after abandon: the retired run's directory keeps its
address, minting skips every existing run directory — live or retired — so no later Run
can occupy a failed Run's evidence. A respawn mints a new id, as a namespace fact only:
the `respawn` verb and what the ledger entry records about the superseded id belong to
the machine-composition issue ([i-018-machine-composition](../issue/i-018-machine-composition/spec.md)),
at the location `FDC-004` reserves. This supersedes `R-022` (at most one active Run per
project) and its check `T-08`.

## Worktree Scope

- **Included:** `src/scheduler.rs` (delete the active-Run admission refusal; mint the next id
  against the full roster including retired directories), `src/abandon.rs` (retire the named
  run's Scheduler-owned files while its directory keeps its address on disk), and the QA
  coverage for concurrent starts, post-abandon minting, and the terminal-run refusal.
- **Excluded:** the `respawn` verb, spawn-ledger contents, and any ledger-entry contract
  (i-018); the runs layout and `--run` addressing themselves (t-058, a dependency); the
  runbook pin and residue refusal (t-059 — no technical dependency: cap lifting and minting
  read only the roster).
- **Expected merge/output:** concurrent runs on one project, a namespace that never hands an
  address back, and fresh ids for every start that follows an abandon.
- **Superseded-test fate:** `test/qa/tests/t012_r022.rs::start_refuses_second_active_run`
  proves the exact behavior `FDC-006` supersedes (`T-08`/`R-022`). It and its fixture
  `test/fixtures/t012-active-run/` (read by no other test) are deleted in this ticket's green
  landing; `PT-060-01` is its replacement.

**What landed.**

- `src/scheduler.rs` — the cap is deleted: `start` no longer checks the roster for a live run,
  so the "cannot start: an active Run already exists" refusal is gone and any number of runs
  coexist, each start minting the next id over the unfiltered roster (minting itself unchanged:
  max+1 over every run directory, live or retired, so never-reissue holds by construction). The
  now-unused live-run filter (`live_runs`) is deleted with its one caller. Ordering kept from the
  runbook-pin ticket (`t-059`): the flat-residue refusal still runs at the top of `start`, before
  any mint — its comment now says it precedes minting, since there is no cap left to precede.
  One addition, the terminal-run refusal the Worktree Scope's QA coverage names: `open_run` on a
  roster entry without a State File now refuses "run <id> is terminal: its admission state is
  retired and no transition may proceed on it; address a live run or mint a fresh one with rtm
  start" — a retired run is a normal thing to address in a multi-run world, and a raw
  file-not-found neither named the run as terminal nor stayed distinguishable from an unknown id
  (which the CLI refuses with the roster listing).
- `src/abandon.rs` — behavior unchanged; one refusal reworded out of the singular-Run world:
  "no active Run to abandon in <project>" became two honest messages — an addressed run with no
  admission state refuses as "run <id> is already terminal … nothing to retire", and the
  unaddressed leftover-lock case as "nothing to retire in <project>: no live run and no leftover
  lock". With runs plural, a project-level "no active Run" claim is false whenever a sibling is
  live.
- `src/cli.rs` — no diff: refusals thread through as Scheduler errors (t-059 precedent), and
  help/doctor wording was already cap-free and roster-plural.
