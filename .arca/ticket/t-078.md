# Ticket: t-078 — Resolved-root reporting

## Vertical Outcome

`rtm status` and argument-free `rtm doctor` report the same resolved Engine-root path that
the Engine actually uses. The report makes shared-primary runtime visible from a linked
worktree and makes the current-root fallback visible when Git is absent, without turning
these read paths into writers.

## Worktree Scope

- **Included:** one rendered resolved-root fact exposed through status and doctor; primary,
  linked-worktree, and no-Git report fixtures; preservation of existing status/doctor
  diagnostics and write-free behavior; QA coverage in
  `test/qa/tests/t078_resolved_root_reporting.rs`; and six private lane checks.
- **Excluded:** root selection implementation (`t-071`), repository-wide minting (`t-072`),
  transition logging (`t-075`), and any new machine state or command-line option. Reporting
  does not change the root it reports.
- **Expected merge/output:** status and doctor print a canonical resolved Engine-root path
  for the current invocation, agree with one another, and leave all filesystem snapshots
  unchanged.
- **Superseded-test fate:** existing status and doctor reports retain their phase, Runbook,
  identity, and finding assertions; the new root fact is additive and is checked against the
  resolver rather than hard-coded expected checkout text.
