# Ticket: t-119 — single root resolution

## Vertical Outcome

An Engine invocation resolves each distinct addressed project exactly once and carries that immutable result through residue checks, address selection, scheduler binding, workspace validation, command execution, and reports. The invoking checkout still supplies its own runbook; linked worktrees still share the primary runtime root. A context-bound handler cannot substitute a path-taking resolver or an independently rendered root. Public convenience entry points each establish one context and use context-taking internals. A test can count resolutions and make a second resolution return a different answer, proving every route uses the original value. Distinct explicitly addressed projects may each have one cached result; workspace membership checks must not re-resolve an already known Engine root.

## Observable Output

Defined before implementation. The public checks and the private lanes both judge this shape; neither needs the other's arrangement or the source.

A **resolution** is the one discovery of a project's invoking checkout and Engine root (the Git worktree query, or the no-Git fallback). Builds with the `test-fault-injection` feature - the `rtm-qa` harness binary and any crate that enables the feature - read two variables at each resolution, when it happens:

- `RATMAC_TEST_ROOT_LOG=<file>`: the resolution appends one line to `<file>`, creating it when absent: the canonical path of the project directory it resolves (`std::fs::canonicalize`, or the absolute path when that fails), with every `\` written as `/`, then `\n`.
- `RATMAC_TEST_ROOT_REPEAT=<answer>`: used only when the log already held that same line before this resolution appended it - a second resolution of one project. `fail` panics, naming the project; any other non-empty value becomes the Engine root of the answer, the invoking checkout unchanged. Unset or empty: the true answer.

A build without the feature reads neither variable and writes nothing extra.

**Counts.** An invocation resolves each distinct project it addresses exactly once, so every line of its log is distinct:

| Route | Log lines |
| :--- | :--- |
| `rtm start`, `step`, `status`, `hold`, `spawn`, `respawn`, `abandon` - success or refusal, a passed Run read as history included | the invoking checkout, once |
| `rtm doctor`, `rtm doctor --json` | the invoking checkout, once |
| `rtm doctor [--json] <runbook>` | the runbook's project (its parent directory, or that directory's parent when it is `.ratmac/` or the legacy `.arca/`, the existing addressed-project rule, which this ticket does not change), once; nothing else |
| `rtm scaffold <path>`, `rtm skill <path>` | the invoking checkout and the path's project, each once - one line when they are the same directory |
| `rtm spawn ... --workspace <dir>`, and every later command addressing that child | the invoking checkout only: a workspace is judged against the repository already resolved and is never resolved itself; a directory inside Git storage (`.git/`) is in no work tree and is refused as outside this repository, as before, with nothing written |
| bare `rtm`, `--help`, an unsupported command | none |
| One call to a public path-taking library entry: `cli::run_from`, `Scheduler::open`, `Scheduler::open_run`, `Scheduler::runs_dir`, `Scheduler::run_roster`, `Scheduler::spawn_to`, `Scheduler::spawn_to_with_workspace`, `Scheduler::respawn`, `abandon::resolve_target`, `abandon::plan_abandon`, `abandon::apply_abandon`, `blocked::plan_hold`, `blocked::apply_hold`, `doctor::diagnose`, `scaffold::write_scaffold`, `skill::write_skill`, `machine::MachineClass::load_from_project_root`, `contract::gate_intake`, `contract::work_items`, `contract::gate_records`, `contract::unproven_mechanization` | its project, once, never a workspace it is given (`cli::run_from`: what the same command line logs); a method called later on an opened `Scheduler` - `start`, `step`, `status`, `spawn*` - adds nothing |

**Divergent answers.** With `RATMAC_TEST_ROOT_REPEAT` set to another directory, or to `fail`, every route above prints, exits, and writes exactly what it does without the variable; the other directory stays byte-identical and is never named.

**Scope.** An invocation from a linked worktree resolves the linked checkout, reports and writes the primary checkout's `.ratmac/`, and reads its own `.ratmac/ratmac.toml`. Without Git, the invoking checkout's own `.ratmac/` is the Engine root. A `--workspace` outside the resolved repository - another repository, or none - still refuses with `workspace <path> is outside this repository` and writes nothing; without Git, the invoking checkout is the repository's only member.

**Interface.** The discovery constructor is `root::Roots::resolve`, private to `src/root.rs`; the public free function `root::resolve` is removed. Each public path-taking entry in the table keeps its existing path but is defined in `src/root.rs`, where it establishes one context and hands it to context-taking internals. Everything else in `src/` takes the context (`&Roots`) and cannot reach the constructor: inserting a call to `crate::root::Roots::resolve` into a handler in `src/cli.rs` or `src/scheduler.rs` fails to compile with `E0624` (private associated function), while the same call inside `src/root.rs` compiles. No file in `src/` other than `src/root.rs` names `Roots::resolve` or `root::resolve(` as a whole path segment, that is, not preceded by a letter, digit, or `_` (`ValidatedWorkflowRoots::resolve` is a different function and is not named).
