# Ticket: t-088 — The intake gate accepts a working-authority requirement

## Vertical Outcome

An accepted ask may point at either place a requirement can live. The intake gate resolves an
accepted requirement identifier against the goal's requirement rows and against the
requirement-ID headings in the working authority, passes when either place holds it, and
refuses only when neither does — naming the ask and both places it looked. This repository's
own tree stops being a tree its own gate would reject.

## Worktree Scope

- **Included:** `src/contract.rs` — the identifier set the gate resolves against gains a second
  source, the working authority's requirement-ID headings; the refusal names the ask and both
  searched places. QA coverage in `test/qa/tests/t088_intake_authority.rs` and six private lane
  checks.
- **Why now:** the gate is the first thing the cycle's intake stage runs, and as written it
  refuses the very tree the cycle governs. Two working-authority families are already in force
  and deliberately mint no goal row, so today an honest bundle citing one of them is a defect.
- **Excluded:** what makes a heading a requirement heading in the working authority is read, not
  redefined; no new working-authority rule is written here. The gate's other checks — five-file
  shape, disposition derivation, link resolution, archived-bundle rules — are untouched.
- **Expected merge/output:** `python tools/check_links.py` and the gate agree on this
  repository, and a bundle citing an identifier that exists in neither place still fails.
- **Superseded-test fate:** existing intake-gate suites keep every refusal they assert; the one
  that pins "absent from the goal authority" wording is rewritten to expect the two-place
  diagnostic and must still fail for an unresolvable ask.
