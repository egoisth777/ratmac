# Ticket: t-057 — Authoring loop: scaffold, instructions, repair by code

## Vertical Outcome

`rtm scaffold <path>` writes the smallest doctor-clean runbook and refuses rather than overwriting an existing file. `.arca/runbook-authoring.md`, routed from `.arca/index.md`, carries the loop — scaffold, edit, `rtm doctor --json <path>`, repair by code, repeat — plus one repair row per stable diagnostic code, with every schema fact a link into `.arca/runbook-spec.md` and no schema definition of its own. A scripted stand-in that reads only the JSON codes and that repair table drives a seeded-defect runbook to clean.

## Worktree Scope

- **Included:** `src/scaffold.rs` and its `rtm scaffold` dispatch, `.arca/runbook-authoring.md`, the routing row in `.arca/index.md`, and the repair drill in QA.
- **Excluded:** any change to the guard-kind vocabulary or the diagnostic-code table — both belong to `.arca/runbook-spec.md` (t-054, t-056). Scaffolding writes exactly one file and only at a path that does not exist.
- **Expected merge/output:** authoring that starts from valid and repairs by name.
