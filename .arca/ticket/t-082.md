# Ticket: t-082 — Pre-cutover leftovers refuse and instruct

## Vertical Outcome

A project still written the old way is told so, by name, and nothing is touched. A runbook
that declares the pre-cutover table refuses with its own dedicated code `RB111` — not the
generic unknown-key code — before any further parse or run work, naming the runbook file
and the repair. A Run Record that carries the pre-cutover position field, or sits at the
pre-cutover filename, makes the addressed command refuse before its first read, path join,
parse, or write, naming the artifact and the repair. Nothing is migrated in place, no Run
is created, and no evidence file is written. Every diagnostic code that existed before this
ticket still reports its own number and severity; `RB111` is the only code added, and the
documented table equals the Engine's again.

## Worktree Scope

- **Included:** the runbook loader's pre-cutover refusal and its precedence over the
  generic unknown-key code (`src/machine.rs`, `src/doctor.rs` code table), the record
  residue refusal at every public entry point (`src/state.rs`, `src/scheduler.rs`,
  `src/blocked.rs`, `src/abandon.rs`, `src/completion.rs`), and the repair table the
  authoring loop reads. Public coverage in `test/qa/tests/t082_precutover_residue.rs`;
  six private lane checks.
- **Excluded:** report wording for healthy Runs (`t-083`), the live-surface audit
  (`t-084`), and any automatic migration — the row forbids it. No pre-existing code number
  or severity changes.
- **Cross-Feature:** the two residue classes that already refuse — the pre-split folder
  layout and a pre-split live artifact — keep their own codes and wording; this adds a
  third class beside them and does not merge them.

## Merge Gate

- **Dependencies:** `t-081` is green and merged.
- **Ticket tests:** `SVCV-003`, `SVCV-005`, and `SVCV-006` all red first — no residue

- **Inherited red:** `t057_deep_doctor::emitted_codes_and_documented_codes_are_one_set`
