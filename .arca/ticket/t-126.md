## Migration mechanism and history boundary

One standard-library-only module under `test/qa/src/support.rs` owns low-level temporary directories, process setup, strict filesystem capture, and isolated fault-test execution. The existing QA crate exports it normally. A private library without a QA-crate dependency reuses the same maintained file through an exact `#[path]` module reference; a private library that already depends on the QA crate re-exports `ratmac_qa::support` instead, so its fixtures share one set of types with the QA fixtures it already uses. Neither route adds a package dependency; existing dependency, lockfile, workspace, and effective feature graphs are preserved. Domain fixtures, executable selection, assertions, and distinct snapshot projections remain with their current owners.

The live inventory is the landed private-lane roster and each crate's active library, test and binary sources. A frozen before-source corpus under `test-hidden/t-126/fixtures/before/` is historical fixture data, never another live lane or a source-migration target. Its public inventory records source hashes, test identities, requirement mappings, build declarations and preserved archive/expiry bytes. Every retained live exception is named in this ticket's migration ledger. The two existing expired crates remain byte-identical.

The public sweep suites may share genuinely executed observations within one process, with source freshness and the existing assertions retained. Keep ordinary sweeps distinct from expiry verification, each private crate's Cargo workspace/process boundary, legacy explicitly named public test targets, and fresh retry fixtures. No blanket parallel sweep or persistent result cache is authorized by this implementation choice.

The QA package manifest may change only its test-target declarations: one default aggregate integration binary includes the existing sweep suites, while their named standalone targets remain explicitly runnable. No package dependency or feature declaration changes. This avoids repeating identical observations within one workspace invocation; the aggregate still executes each existing assertion and retains separate ordinary and expiry observations.

### What moved to the shared module

- **Temporary folders.** Each crate's own unique-name, pre-clean, and remove-on-drop code became a `support::TempTree` owner field. Public fixture fields such as `root` stay, so tests are unchanged. Folders that a test used to remove by hand (t-095, t-100, t-108) are now also removed when the test panics.
- **Child processes.** Direct `Command::new` launches became `support::command`, which clears inherited Git, Cargo test-harness, and fault settings for the child only. Settings a test sets on purpose are applied after that, so they still reach the child (t-073, t-086, t-090, t-104, t-108, t-118).
- **Output joining.** Local stdout-then-stderr helpers became `support::text`.
- **Tree walks.** Local recursive walkers became `support::capture` plus a projection that keeps the old key shape; t-089 to t-093 and `aged::snapshot` still key files by their full path under the root, with native separators. Where the old walker treated a missing folder as empty, the capture sets `missing_root_is_empty` to keep that (t-058 to t-074, t-076, t-077, t-080 to t-083, t-086 to t-093, t-101, t-102, t-112, `aged::snapshot`). Everywhere else a missing folder stays an error, as before.

### Tightened behavior

Tree walks in t-058 to t-074, t-076, t-077, t-080 to t-084, t-086 to t-093, t-101 to t-106, t-108, t-112 to t-114, and t-118 now use the shared strict capture. It never follows a link and stops with a named error on anything it cannot read, where some old walkers quietly skipped unreadable entries.

Most old walkers followed links and read through them. A file-only projection of the capture would drop a link without a word, so wherever the old walker followed or listed links the new code calls `Snapshot::refuse_links` first: a link or special file now fails the test by name (t-058 to t-074, t-081 to t-083, t-086 to t-093, t-101 to t-106, t-108, t-112, t-113, `aged::snapshot`); in t-081 that covers both `files_under` and `records_under`. t-076, t-077, and t-080 keep links visible in their tagged projection, and t-076's source scan skipped links before as well. t-084 still ignores links on purpose, t-114 still treats a link or special file as a failure by its own rule, and t-118 still records links by type. t-108's `walk_files` skips only folders named `target`, as before, so a stray file named `target` is still reported. t-101 and t-102 skip every top-level entry named `.git*` before looking at it, links included, as their old walkers did. No fixture read through a newly guarded file-only projection contains a link or an unreadable entry, so no verdict changes; a future broken fixture fails loudly instead of passing. Fixtures that make links or unreadable entries on purpose (t-084, t-114, t-118) keep their own rules, listed above.

### Other recorded changes

- **One sweep process.** `lane_sweeps` runs the t-108, t-109, and t-110 suites in one test binary. Every step over the real lanes or the tracked sweep report holds `lane_runs::exclusive()`. A suite reuses a lane run it already executed in the same process only through `lane_runs::Observations`: the whole checkout (all files except `.git` and folders named `target`, plus Cargo configuration found above the checkout, in the home `CARGO_HOME` names, and in the default home that a child without `CARGO_HOME` reads) must hash the same before the run, after it, and now. A run whose inputs moved while it ran is returned but never reused. Nothing is kept on disk. t-108's real sweep also needs the tree and that outside Cargo configuration unchanged across the run and since, and the report unchanged since. `wcpv_004` proves reuse, a fresh run after a new build script, Cargo configuration inside or above the checkout, or a file named `target`, and no reuse after a mid-run edit.
- **After-inventory binding.** Until this ticket carries its landing stamp, `wcpv_006` and `ht_126_06` require every `files` and `preserved` row of `migration-inventory.toml` to match the current bytes, with a changed-expired-source control and its unchanged twin. - t-074 `combined()` now joins stdout and stderr without the old `stdout:`/`stderr:` labels. `output_id()` and the success and refusal checks read it; they look for content, not the labels, so no verdict changes.
- t-109 copies crates byte for byte as sweep fixtures, then rewrites only the one support include in each copied `src/lib.rs` to the repository's absolute path, as it already did for the `ratmac` dependency, so migrated copies still build. A copy without exactly one such include fails by name.
- Automatic formatting rewrapped older lines in edited files (t-069, t-072, t-075, t-088, t-091, t-094 to t-096, t-101 to t-103), so some line counts grew. Behavior is unchanged.
