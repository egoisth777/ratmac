# Ticket: t-061 — Input-routed transition selection

## Vertical Outcome

A branching Phase declares one closed legal transition-input list, every ordinary outgoing edge
carries one unique value from that list, and the Engine selects exactly the matching edge. Exit
Guards remain readiness checks over the Phase and never choose a destination. A straight-line
Phase keeps one unlabelled ordinary edge and consumes no transition input. Blocked routes remain
outside selection and completeness. The Phase Prompt shows the legal values but no hidden graph.

## Worktree Scope

- **Included:** `.arca/runbook-spec.md` (canonical `inputs` and `input` syntax plus RB208–RB213),
  `.arca/runbook-authoring.md` repair guidance, `src/machine.rs` typed phase/edge parsing and
  exhaustive validation, `src/graph.rs` exact input lookup, `src/scheduler.rs` input-aware route
  selection and prompt rendering, `src/doctor.rs`/`src/scaffold.rs` diagnostic and example updates,
  and public/hidden parser, routing, and prompt tests.
- **Excluded:** who writes a verdict, the live record format, record consumption/archive, crash
  recovery, lifecycle terminal values, blocked-route authorization, and machine composition.
  Those belong to t-062 or later issues.
- **Expected merge/output:** one format spelling and one deterministic route function: no input
  means the sole unlabelled ordinary edge; one legal value means the uniquely labelled edge.
- **Superseded-test fate:** first-edge-wins tests that construct ambiguous ordinary branches are
  replaced by explicit input-labelled branch tests. Straight-line tests remain unchanged.
