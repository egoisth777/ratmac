# Ticket: t-089 — A per-item gate addressed by a binding

## Vertical Outcome

A receipt-class or completion-class guard can name what it judges without the identifier being
written in the runbook. The guard declares a binding name; the caller supplies the value when
the child Run is spawned; the Engine reads that value back from the append-only spawn ledger
and grades against it. A value written once at spawn cannot go stale, the runbook file stays
free of work-item identifiers, and the Engine still handles an opaque string.

## Worktree Scope

- **Included:** `src/machine.rs` — the two per-item guard kinds accept a bound address beside
  the literal one, and parsing refuses a guard that declares both or neither.
  `src/scheduler.rs` — guard dispatch resolves a bound address through the spawn ledger entry
  for the Run being judged, and refuses under its own diagnostic when the binding name was
  never supplied. `src/doctor.rs` — the bound form is diagnosable like the literal one. QA
  coverage in `test/qa/tests/t089_bound_address.rs` and six private lane checks.
- **Why now:** the cycle's ticket turns cannot be declared at all until a gate can be addressed
  without a literal, and the spawn ledger already records binding values, so this connects two
  built halves rather than inventing a mechanism.
- **Excluded:** the literal address form stays exactly as it is — nothing is migrated and no
  existing runbook changes. The completion gate's habit of parsing a contributor's document for
  the checks it declares is untouched; that is a separate wish. The Engine learns nothing about
  what the value means.
- **Expected merge/output:** every existing runbook and Run behaves identically; the new form
  is exercised only by the new tests.
- **Superseded-test fate:** no existing test is superseded. Suites asserting the literal form
  must still pass unchanged, which is itself the proof that the form was added and not replaced.
