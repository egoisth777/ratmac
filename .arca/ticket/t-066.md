# Ticket: t-066 — The spawn ledger

## Vertical Outcome

The spawn ledger exists and is load-bearing. At the per-run location FDC-004 reserves under the
parent Run's directory, the Scheduler - and only the Scheduler - appends one entry per spawn
carrying the recorded fields (child run id, class, binding values, git revision at spawn,
workspace path when one is created). The ledger is append/annotate-only: confirmed abandonment
flips only that entry's abandoned mark; confirmed respawn appends the successor entry naming the
superseded id; prior entries are never rewritten. The join guard reads the ledger as its expected
set: an entry whose child Run is missing on disk makes the join refuse loudly, naming that child.

## Worktree Scope

- **Included:** new `src/ledger.rs` (typed entry, append, annotate, strict read), `src/scheduler.rs`
  spawn appends its entry in the same turn that mints the child, join-guard evaluation reading the
  ledger plus the children's Engine-written terminal facts, `src/abandon.rs` annotate hook,
  respawn successor entry, `test/qa/tests/t066_spawn_ledger.rs`, `.arca-private/t-066/` hidden
  lanes, `.arca/runbook-spec.md` ledger-contract note.
- **Excluded:** the recursion cap (t-068), child-as-reviewer routing (t-069), any human courier
  path, signer identity.
- **Expected merge/output:** ledger writes ride the verbs that cause them - spawn, abandon,
  respawn - all-or-none with those verbs' existing write disciplines; no agent-facing write path
  exists (PGE-004 posture).
- **Superseded-test fate:** t-065's "spawns without writing the ledger" interim oracle is the one
  expected correction: spawn now appends its entry. Everything else stays intact.
