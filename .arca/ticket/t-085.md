# Ticket: t-085 — Prove the rename changed names only

## Vertical Outcome

The cutover is closed with a proof, not a claim: edge selection, guard evaluation,
readiness, routing, freeze and drift, locking, minting, spawning, joining, holding,
abandoning, completion, receipts, and exit codes behave exactly as they did before the
first rename landed. Every check that existed at the freeze still means what it meant —
none was deleted, none was weakened to fit a new word, and each one that changed changed
only the word it names. The evidence is one command's output, not a stitched-together set
of package-scoped runs.

## Worktree Scope

- **Included:** a regression comparison across the behavioral suites named in
  [res-122](../residual/res-122.md); an inventory proving no check was dropped or loosened
  between the freeze commit and this ticket; public coverage in
  `test/qa/tests/t085_rename_is_behavior_free.rs`; six private lane checks.
- **Excluded:** any further rename — every renaming ticket is landed before this one — and
  any new behavior. If this ticket finds a behavior change, it does not adjust the check,
  it reopens the owning ticket.
- **Cross-Feature:** the comparison runs against the same fixtures the freeze used, so a
  fixture edit shows up as a difference rather than hiding one.

## Merge Gate

- **Dependencies:** `t-080` through `t-084` are green and merged.
- **Blocker:** the one-command evidence rule depends on
  [i-027](../issue/i-027-duplicate-engine-binary/index.md). Until that issue is folded in
  and its repair lands, a full-repository test run picks its engine binary by build order,
  so this ticket's own evidence cannot be taken honestly. If i-027 is still open when the
  four dependencies are green, hold this ticket against it rather than passing it with a
  package-scoped run.
- **Ticket tests:** `SVCV-008` reds first — no before-and-after comparison exists at the
  freeze.
- **Hidden manifest:** `HT-085-01` through `HT-085-06` cover all six required lanes.
- **Quality and closure:** the whole suite plus workspace quality gates pass in one
  command; `landed-commit` stays empty until the green ticket landing is merged.
