# Ticket: t-132 — rule fix recovery

## Vertical Outcome

An explicitly authorized Engine recovery can continue a nonterminal Run stopped by a corrected rule without changing its Run address, owning class, bindings, workspace, or current State, deleting its proof, retiring it, or rewriting its original pins. Authorization is verified under the prior trusted policy or a previously enrolled recovery authority, never the proposed replacement policy. The signed authorization binds the Run, full old and new authority identities, and every enumerated change; a confirmation phrase alone cannot authorize replacement. Recovery cannot enroll its own approver. A Run lacking previously enrolled recovery trust requires explicit independent external enrollment before recovery is eligible. The recovery durably records the identities, affected rule, verified authorization, and evidence boundary as a forward-only amendment. It validates the corrected class and State and independently rechecks all affected prerequisites and proof; stale receipts or agent-authored claims never establish success. Missing authorization, incompatible corrections, terminal Runs, corrupt evidence, and interruption leave the old authority effective or one complete recoverable amendment, never a partial silent repin. An amendment does not resume a paused Run or approve a transition.

**Durable order, the commit point, and reconciliation.** Recover is one
Run-locked decision; it takes no root lock, mints no id, reserves no

after it the new verified head is effective even if every later step
fails. Original pins remain byte-identical; the seven-field Run Record,
the pause records, the spawn ledger, `evidence.toml`, and every receipt
and verdict archive keep their bytes. (3) **Archive.** Append one record

<nnnnnn>.toml` (`write_archive`, `src/review.rs:1987-2031`, filename

highest existing index - a strict-TOML document holding exactly

`policy_sha256`, `enrollment_sha256`, `decision_signature_sha256`,
`from_state`, `to_state` (both the current State), `amendment_sequence`,
and `origin` (`host-enrolled`, or `test-injected` under the seam below),
with zero `[[reviews]]` rows. (4) **Record history.** Append the uniquely

| Head `<n>` committed, event missing (archive present or absent) | Reconciles: appends the missing archive record and the one missing event, prints the success lines naming `<n>`; no second amendment. |
| Head `<n>` committed, event complete, same decision presented | The replay refusal above; the operation is finished. |
| Head `<n>` committed, event complete, fresh decision bound to head `<n>` | A new amendment at `<n>+1>` through the full order. |
| Head `<n>` committed, decision bound to an older head | The stale-tip refusal above; nothing written. |
| Chain malformed, noncanonical, or torn beyond a prefix | The strict-chain families above; everything as found; human repair outside the Engine. |

**Success output.** A completed recovery - fresh, or finished by
reconciliation - prints two LF-terminated stdout lines, exit 0, stderr
empty:

```
rtm: run <id> amended at sequence <n>; the corrected authority is effective
The Run keeps its address, State, class, bindings, workspace, and original pins; an amendment neither resumes a paused Run nor approves a transition.
```

A fully authorized amendment preserves blocked status, hold history, and
original pins, consumes no verdict, and creates no passing receipt: stale
proof from a removed or changed guard never counts as current completion
evidence, and fresh checks under the corrected authority are the only path
to new passing receipts.

**Readers report, never repair.** `rtm status --run <id>` of a pending Run
renders its ordinary report from the records unchanged and appends one
LF-terminated line after the `next:` line, exit 0: `Amendment pending:
sequence <n> for this Run is committed with its history event missing; a
repeated rtm recover --run <id> reconciles it exactly once.` `rtm doctor`
reports one warning finding per pending Run, code `RB902` at location
`run "<id>"` - `amendment pending: <Engine
root>/runs/<id>/amendments/<n>.toml is committed with no history event; a
repeated rtm recover reconciles it` - and exits 1 with no other finding
changed (warning-only exits 1, `src/doctor.rs:306-317`). A malformed chain
at a reader refuses with the strict-chain families above through that
reader's own hard-error rendering, and `rtm doctor` reports it as an
error finding, code `RB903` at location `run "<id>"` carrying that
strict-chain text, exiting 2; neither writes anything. Both codes come
from the Run scan alone, like `RB901`: `.arca/runbook-spec.md` names them
in the amendments prose row, never as `## Diagnostics` code rows (that
table equals the codes runbook diagnosis emits). The roster, history
views, and every other reader keep today's bytes.

second waits under the 5 s deadline and on expiry refuses today's

- never a duplicate live amendment. No deadlock: recover takes exactly one
lock, root-before-Run order is untouched, and the root lock is never held
while recover runs (its checks are file reads and signature
verification). Readers are lock-free.
