# Ticket: t-122 — successor ownership

## Vertical Outcome

A spawned replacement becomes available to public Run operations only after its owning parent ledger durably records its identity, class, bindings, workspace, and superseded Run. Concurrent step, spawn, hold, abandon, join, and roster reads must never observe an admitted successor without that ownership. Root-before-Run lock order and root-lock-free guard evaluation remain unchanged. Failed or interrupted replacement preserves the predecessor or records a complete recoverable replacement; an ambiguous write never causes deletion of potentially owned evidence, and identifiers are never reused.

Existing source boundaries: `src/scheduler.rs`, `src/ledger.rs`, `src/abandon.rs`. Add only the directly required module or command wiring where the accepted design calls for it; keep unrelated behavior unchanged. The implementing turn also owns its public suite, private crate, this ticket, its gap record, and the roster entry for its new private crate. Any necessary existing regression adjustment must cite the exact newly accepted contract; never weaken an unrelated assertion.

The main coordinator opens and closes the registered ticket worktree, invokes the Engine, records actual receipts and snapshots, and owns shared authority and history. Agents own disjoint source, public-proof, and private-proof paths assigned at turn start. Review exact source and oracle bytes before expensive private proof. No goal edit is allowed during the frozen build batch.
