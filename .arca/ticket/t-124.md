# Ticket: t-124 — byte verified restores

## Vertical Outcome

Before deliberate damage, record the exact bytes and effective checkout conversion settings for every declared tracked mutation target. A restore is accepted only after recomputing each restored target's digest and matching its frozen digest, with index and tracked-tree state also verified. Refuse before damage when effective line-ending or checkout filters cannot reproduce those frozen bytes; never silently change global or repository Git settings. A clean Git status alone cannot pass a restore whose bytes differ, and a refusal names the affected path and corrective action.

## Observable Output

Defined before implementation. The public checks (WCPV-013, WCPV-014,
WCPV-015) and the private lanes HT-124-01..06 both judge this shape; neither
needs the other's arrangement or the source. Every sentence below is
observable through the process exit code, stdout/stderr bytes, files under
the addressed checkout, or Git state (refs, index, worktree, configuration)
in the addressed repository. The operator is `tools/turn.ps1`, invoked as
`pwsh -File tools/turn.ps1 <verb> ...`; this ticket adds the verbs
`checkpoint` and `restore` beside today's `status`, `open`, `close`. Paths
in messages use the tool's one displayed spelling (forward slashes,
repository-relative); `<checkout>` below is that spelling of the root of the
working tree the invocation stands in - for a ticket's damage run, the ticket
worktree, and that is deliberate: damage happens there. Nothing here reads
or writes anything under the Engine root (`.ratmac/runs/`, locks, mint, or
the Engine transition log); no `rtm` invocation, no `src/` byte, and no
goal-fingerprint surface is involved.

**Terms.** The *addressed checkout* is the working tree the invocation
stands in, linked or primary. A *declared target* is one repository-relative
path passed to `checkpoint` through `-Target`. Several targets use
PowerShell's array syntax, `-Target <path>,<path>`; under `pwsh -File` that
arrives as one string, so the tool splits every `-Target` value on commas
and drops empty pieces. A declared path therefore cannot contain a comma,
and a value with no non-empty piece counts as no `-Target`. The *recorded checkpoint
commit* is the commit `checkpoint` freezes from: the addressed checkout's
`HEAD`, spelled as its 40-hex object id. The *frozen manifest* is the one
file `checkpoint` writes, `<item-records>/<item>-checkpoint-manifest.txt`
(the declared item-records root that already resolves `<item>.md`; no new
declared key exists). The *round-trip proof* is the pre-damage evidence that
the recorded checkpoint commit's bytes and the addressed checkout's effective
attributes and configuration reproduce each other for every declared target,
in both directions. A *clean tracked tree* is a `git status --porcelain`
output whose every row starts with `??` (untracked rows exist or not; no
tracked path differs from the index and nothing is staged). An *unrelated
file* is every path under `<checkout>` other than the declared targets and
the frozen manifest. *Damage* is the working rules' deliberate mutation of
declared targets between `checkpoint` and `restore`. `<40-hex>` in a
checkpoint refusal is the recorded checkpoint commit's full object id,
i.e. `HEAD` at validation time.

**Success order - `checkpoint`.** `pwsh -File tools/turn.ps1 checkpoint
-Item <item> -Target <path>...` runs, in this order, and performs exactly
one durable step:

1. **Validate.** In order: the repository fact (today's refusal `this
   directory is not a Git repository`, `tools/turn.ps1:264`); the item
   guards (today's `checkpoint needs an item: -Item <string>` and
   `the item '<item>' is malformed` shapes, `tools/turn.ps1:320` and
   `tools/turn.ps1:325`, the verb name substituted as today's template
   does); the turn declaration (today's `.ratmac/turn.toml` refusals
   unchanged, `tools/turn.ps1:176-224` - no new required or optional key);
   at least one `-Target`; each target a repository-relative regular-file
   spelling without a drive, a leading `/`, a backslash, a `..` component,
   a TAB, or a newline (duplicate spellings collapse to one; `pwsh -File`
   itself refuses an argument holding a newline before the script runs, so
   that rule guards in-process callers only); the declared
   item-records root present; each target tracked as a regular file at
   `HEAD`; a clean tracked tree. Each failure refuses below, writing
   nothing.
2. **Prove.** The round-trip proof (its own paragraph below) runs read-only
   against Git's own checkout and clean machinery; any target that fails it
   refuses before anything is written.
3. **Freeze.** Write the frozen manifest beside ticket evidence: the whole
   file is written to `<manifest>.tmp` and renamed onto
   `<item-records>/<item>-checkpoint-manifest.txt` in one step, so a reader
   that finds the manifest always finds its whole content - it never appears
   partially. This is the verb's only durable step and its only write
   anywhere: no ref, tag, registration, index entry, configuration file, or
   file outside the manifest is created, moved, or deleted.

**Success order - `restore`.** `pwsh -File tools/turn.ps1 restore -Item
<item>` takes no `-Target`: it restores exactly the targets the frozen
manifest carries. Passing `-Target` to `restore` (or `-Line`/`-Obsolete`
to either new verb) binds and is ignored, exactly as today's verbs ignore
parameters they do not use; no refusal row exists for a bound-but-unused
parameter. In this order:

1. **Validate.** The repository, item, and declaration guards as above; the
   manifest present and parsing to its exact format; the manifest's
   `item <item>` row equals `-Item`; the recorded
   checkpoint commit resolving in the addressed repository; every manifest
   row's path carried by that commit; every row's recorded blob id equal to
   the recomputed `git rev-parse <commit>:<path>`.
2. **Restore.** Two git invocations, each one call for all targets, in this
   order. First `git update-index --add --cacheinfo <mode>,<blob>,<path>...`
   (one `--cacheinfo` per target in manifest order, its mode and blob read
   from the recorded commit) sets every target's index entry to the
   checkpoint blob with no cached file facts; worktree bytes are untouched.
   Without it Git trusts a stat cache that still matches bytes an earlier
   setting wrote and skips that target, so restoring the settings a
   digest-mismatch refusal names and running `restore` again would refuse
   the same way forever. Then exactly today's working-rules undo:
   `git restore --source=<commit> --staged --worktree -- <path>...`
   (the command the damage safety rules fix byte-for-byte), which now
   writes every target fresh from the commit through the effective
   settings. A non-zero exit of either refuses through today's shared
   git-failure refusal `git <arguments joined> failed: <text>`
   (`tools/turn.ps1:136`).
3. **Verify.** Recompute the SHA-256 of every target's worktree bytes and
   compare to its frozen digest; then require a clean tracked tree. Both
   must hold: a clean tracked tree alone cannot pass a target whose bytes
   differ, and matching digests alone cannot pass a dirty index or tracked
   tree. Nothing is deleted on failure and no unrelated file is touched:
   the restore's writes are limited to the manifest's own target paths.

**Success output.** Exit 0, stderr empty, stdout exactly these lines (one
Write-Report line each, the tool's existing console newline; `<n>` renders
the target count; the checkpoint report renders `(<n> target, round-trip

**The frozen manifest's exact bytes.** UTF-8 without a BOM, every line
LF-terminated including the last: the four header lines in the printed
order, then the target rows sorted by path bytewise ascending:

```
item <item>
commit <40-hex>
setting core.autocrlf <effective value or unset>
setting core.eol <effective value or unset>
target <path>	<worktree-sha256>	<blob-sha-1>	<text>	<eol>	<filter>
```

`<worktree-sha256>` is 64 lowercase hex - the tool's existing digest
spelling (`Get-FileHash -Algorithm SHA256`, lowercased,
`tools/turn.ps1:381`), the same digest family `snapshot.rs` emits
(`test/qa/src/snapshot.rs:141-152`). `<blob-sha-1>` is
`git rev-parse <commit>:<path>`. The three attribute fields are the
effective `git check-attr` values for `text`, `eol`, and `filter`
(`unspecified` when unset); the two setting lines are the effective
`git config` values (`unset` when not configured). The manifest records
facts; it never contains a command, an absolute path, or a timestamp.

**The round-trip proof.** For every declared target, both directions are
proved through Git's own machinery, never by conversion logic reimplemented
in the tool: checking the recorded blob out through the effective
attributes and configuration reproduces the current worktree bytes (for
example `git checkout-index --temp`, whose index equals `HEAD` under the
clean-tracked-tree precondition), and cleaning the current worktree bytes
reproduces the recorded blob (for example `git hash-object --path <path>`
against the file's bytes). A filter command that fails makes the proving
git call fail and refuses through the shared git-failure refusal; a filter
or line-ending behavior that mangles bytes in either direction refuses
through the round-trip row above. The proof writes nothing into
`<checkout>`; its temporary bytes live outside the repository tree and are
removed before the verb ends.

**Recovery and restart.** Killing the invocation at any point is the
interruption fixture; the damage protocol is single-operator and the verbs
hold no lock, so nothing waits and nothing deadlocks. An `index.lock` left
by a killed git child makes the next git call fail with Git's own text
through the shared git-failure refusal; removing it is the operator's act -
the tool never deletes a lock, a ref, or a directory.

| State found after a kill | The repeated command |
| :--- | :--- |
| No manifest (kill before the freeze rename) | `checkpoint` runs fresh from the same clean tree; an inert `<manifest>.tmp` may remain and is replaced. |
| Manifest durable (kill after the freeze rename) | `restore` may proceed; a repeated `checkpoint` from the same clean tree rewrites byte-identical manifest bytes. |
| Restore killed before the index reset | Nothing was written; `restore` runs fresh. |
| Restore killed after the index reset, before `git restore` | Each target's index entry holds its checkpoint blob with no cached file facts, its worktree bytes untouched; `restore` re-runs both commands and verifies. |
| Restore killed during or after `git restore` | Targets hold checkpoint bytes, unverified; `restore` re-runs the identical commands and verifies - it is idempotent and never claims success without verification. |
| Restore killed after verification | The operation is complete; a repeated `restore` re-verifies and prints the success report. |

**Settings are never changed.** No verb writes global or repository Git
configuration: `.git/config`, the global configuration file, and
`git config --global --list` are byte-identical before and after every
invocation, success or refusal - both suites hash them. Effective-settings
drift is detected (round-trip refusal before damage; digest-mismatch
refusal after restore), never repaired. The historical counterexample is
the contract's own fixture: under `core.autocrlf=true` a
`git restore --source=<checkpoint> --staged --worktree --` left
`git status --porcelain` empty while the restored bytes differed from the
frozen digests - exactly what the digest-mismatch refusal now catches by
path.

**No operation log.** The turn tool writes no operation log and gains
none; the ordered stdout lines above are the observable order, and a
refusal prints no success line. The Engine's operation-log feature and its
kinds are untouched.

**Test-only seams.** One pause seam so the durability boundaries are
observable. Unlike the Engine's compile-gated seams (`#[cfg(feature =
"test-fault-injection")]`, absent from production builds), the script's
seam is environment-gated only and ships dormant - it is not a dict.md
Pause point - and it activates only when the QA harness sets
`RATMAC_TEST_*` variables explicitly on the child
(`test/qa/src/support.rs:139-167`):

- `RATMAC_TEST_TURN_PAUSE`, one of `after-freeze` (checkpoint: the
  manifest rename done, before the success report), `after-validate`
  (restore: manifest proven against the commit, before the index reset),
  `after-restore` (git restore returned 0, before verification), or
  `after-verify` (verification green, before the success report). Each
  name belongs to exactly one verb; a name on the other verb is an invalid
  request. Requires `RATMAC_TEST_TURN_PAUSE_MARKER` and
  `RATMAC_TEST_TURN_PAUSE_RELEASE` (file paths) and a positive integer
  `RATMAC_TEST_TURN_PAUSE_TIMEOUT_MILLIS`; a set-but-unrecognized value or
  a missing or invalid companion refuses
  `turn refused; the test pause request is invalid: <fact>` with guidance
  `set RATMAC_TEST_TURN_PAUSE to a known boundary with its marker, release, and timeout companions, or unset it.`
  - checked after the item guard and before any write, so the refusal
  writes nothing. Unset or empty changes nothing. At the boundary the verb
  writes the boundary name and a newline to the marker path in one step
  holding the whole line, then waits until the release path exists; on

  the paused process is the interruption fixture; the recovery table
  decides the repeat.
- No fault-injection seam exists or is added: every failure boundary above
  is reachable through real inputs (a tampered or deleted manifest, a
  target deleted from the commit, a fixture-local filter or
  `core.autocrlf` that converts bytes, a read-only path), so both suites
