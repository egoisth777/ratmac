# Ticket: t-059 — Runbook pin stays hash-only; flat-layout residue refuses

## Vertical Outcome

The runbook pin is a recorded hash and nothing more: `rtm start` records the SHA-256 of the
canonical `.arca/ratmac.toml` in the run's evidence, every later Scheduler read of the class
compares against it, and a mismatch refuses naming observed and expected identity — the same
shape as the Engine-pin refusal — while no code path ever copies the runbook anywhere. Meeting
a flat-layout residue — a pre-plural `.arca/state.toml` on disk — the Engine refuses, names the
observed fact and the repair, and modifies nothing: the lock-refusal precedent, never an
auto-migration.

## Worktree Scope

- **Included:** `src/pin.rs` (a runbook hash entry in the run's evidence), `src/scheduler.rs`
  (record the pin at start, compare on every class re-read, and the residue check on opening a
  project that carries a flat `.arca/state.toml`), `src/cli.rs` (the refusal wording for both:
  observed-vs-expected for the pin, fact-plus-repair-instruction for the residue), and the QA
  fixtures that plant a residue and drift a runbook.
- **Excluded:** any per-run runbook copy (forbidden by `FDC-005` until a drift case is
  demonstrated); any automatic migration or deletion of residue files; the runs layout itself
  (t-058, a dependency); cap lifting and id minting (t-060).
- **Expected merge/output:** a pinned runbook hash beside each run's evidence, drift met by a
  naming refusal, and flat residue met by an instructing refusal that writes nothing.
- **Superseded-test fate:** none — no existing test proves a behavior `FDC-005` supersedes;
  the no-per-run-copy half already holds by construction and stays enforced by `PT-059-01`.

## P5 notes (2026-07-30)

**What landed.**

- `src/pin.rs` — Run evidence gains one field: `runbook_sha256`, the SHA-256 of the canonical
  `.arca/ratmac.toml` recorded at Run start. Rendered as `[runbook] sha256 = "<hex>"`, parsed
  back on load; hash only, no path, no bytes, no copy.
- `src/scheduler.rs` — three additions. (1) `refuse_flat_residue`: a flat `.arca/state.toml`
  (any bytes, existence-checked) refuses at `Scheduler::open` and `Scheduler::open_run` and
  again at the top of `start` before the active-run cap, so the refusal names the residue,
  never the cap; wording follows the legacy-lock precedent — "refusing to run: flat-layout
  residue <path> exists; … explicitly migrate that file into its run's directory or remove it,
  then retry; it was not modified". (2) `start` hashes the runbook under the invocation lock
  and records the pin in the run's evidence beside the Engine pin and goal baseline. (3)
  `verify_runbook_pin`: every Scheduler read of the class with an addressed run — `open_run`,
  `step` (before any guard of the drifted class is evaluated), `status` — compares the on-disk
  runbook hash against the recorded pin; a mismatch is a hard error naming observed and
  expected identity (`observed sha256=<hex>; expected sha256=<hex>`, lowercase hex, the
  repo-wide pin convention) plus the repair, and writes nothing. A run whose evidence records
  no runbook pin predates the pin and is not checked (hand-seeded fixture runs keep working).
- `src/cli.rs` — no diff this turn: both refusals are single-sourced as Scheduler errors and
  the existing `{command}: {error}` threading already carries the wording to the CLI surface
  (exit 1, non-success). The ticket's wording responsibility is met in `src/scheduler.rs`
  instead of split across two files.
- Residue-vs-class-read order: `open`/`open_run` read the class first, then check residue, so
  the TRP-005 contract (a missing/unreadable runbook refuses naming `ratmac.toml` at open)
  is preserved; on a valid runbook the residue refusal is the first project-state refusal and
  precedes the cap.
