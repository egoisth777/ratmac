# Ticket: t-032 — Route diagnostics and CLI through rtm

## Vertical Outcome

Users can invoke the canonical `rtm` executable for help, start, status, step, and refusal/error paths; every user-facing command and diagnostic identifies `rtm`, while scheduler behavior remains unchanged and `schd` is not advertised.

## Worktree Scope

- **Included:** `src/cli.rs`, `src/bin/rtm.rs`, command parsing, usage/help, diagnostics, direct executable dispatch, and focused canonical CLI smoke proof.
- **Excluded:** package metadata/source rename (t-031), QA-wide migration (t-033), lock-path policy (t-036), and final quality audit (t-037).
- **Expected merge/output:** end-to-end canonical command routing for all existing routes with old-name rejection under clean cutover.
