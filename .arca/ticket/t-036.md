# Ticket: t-036 — Enforce clean-cutover lock and legacy policy

## Vertical Outcome

The runtime enforces the recorded clean-cutover policy: `rtm` is the only command/package surface, persistent `.arca/ratmac.toml`, `.arca/state.toml`, and `.arca/log.md` semantics remain intact, and a pre-existing `.arca/schd.lock` is refused safely rather than deleted or bypassed while `.arca/rtm.lock` arbitrates invocations.

## Worktree Scope

- **Included:** transient lock path, legacy lock detection/refusal, command/package/diagnostic compatibility behavior, focused concurrent/interrupted-run tests, and the explicit migration report.
- **Excluded:** package target rename (t-031), ordinary CLI routing (t-032), broad QA migration (t-033), generated Cargo assets (t-035), and final repository audit/gates (t-037).
- **Expected merge/output:** deterministic clean-cutover behavior with preserved persistent data and no alias, shim, silent deletion, or arbitration bypass.
