## Vertical Outcome

Clean, staged, and modified files keep their current tracking meanings; ignored files are never labeled tracked. An allowed untracked or modified path is visibly marked as the exact exception on the same manifest row as its path, tracking state, and SHA-256. A missing or unreadable declared root refuses by name instead of producing a successful incomplete manifest. The existing `record_snapshot(repo_root, roots, exceptions)` call shape and `snapshot-manifest <out-path> <root>... [-- <exception>...]` command surface remain unchanged, as do all frozen t-039 assertions.

### Included behavior

- Keep the four existing tracking states. A clean path is `Tracked` only when Git confirms it is tracked; an index-only change is `Staged`; any unstaged worktree change remains `Modified`; an ordinary or ignored path unknown to Git is `Untracked`.
- An ignored untracked path refuses like any other untracked path unless its exact repository-relative path is listed in `exceptions`.
- A successful exception row carries an explicit exception marker beside its existing path/state/digest evidence. Exact matching remains exact: no prefix, directory, or neighboring-path exception expansion.
- A declared regular-file root contributes that file. Overlapping file and directory roots still sort and de-duplicate by repository-relative path. Existing `.` and `./src` root spellings retain the same file identity and tracking classification; the roots header preserves the supplied spelling. Do not canonicalize symlinks or normalize exception arguments.
- A missing root, a root that cannot be read, or a directory-entry/metadata failure encountered while traversing a declared root returns a named `SnapshotViolation`; it never becomes an empty successful contribution. An existing readable empty directory may remain empty.
- The command keeps its current arguments, success/refusal exit behavior, and destination. On any content or traversal refusal it must not create a new manifest or overwrite an existing one.
- Keep `.git` and `target` traversal exclusions, stable row sorting, lowercase SHA-256, rename/space/Unicode handling, and current clean/staged/modified assertions.
