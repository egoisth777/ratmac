# Ticket: t-131 — review before proofs

## Vertical Outcome

The build order obtains an independent review of the proposed source and tests before executing the expensive private-lane and deliberate-damage proof set. The accepted review identifies the exact reviewed snapshot. A rejected review returns to repair without running that proof set. Later source or oracle changes invalidate the affected review and proofs rather than claiming a once-only guarantee over changed bytes. A clean reviewed snapshot earns one complete private/damage proof set after review. This once-only rule applies to earning that unchanged proof, not to mandatory restored-green checks after each mutation or the declared post-merge verification from main; both remain required. Later source or oracle repair still requires renewed affected proof.

**Success order - `review`.** `pwsh -File tools/turn.ps1 review -Item
<item> -Verdict <accepted|rejected>` runs, in this order, and performs
exactly one durable step:

1. **Validate.** In order: the repository fact (today's refusal); the item
   guards (today's shapes, the verb name substituted as today's template
   does); the turn declaration (today's refusals - no new key); the
   declared item-records root present (t-124's row, byte for byte);
   `-Verdict` present and exactly `accepted` or `rejected`; the pause
   request valid (before any write; the order above fixes its exact
   position). Each failure refuses below, writing nothing.
2. **Digest.** Compute the reviewed inputs: every work row (a path the
   index lists but the working tree does not carry refuses the incomplete
   row below; an unreadable path refuses the digest-failure row below,
   its guidance naming `review`) and every lane row, then the snapshot
   digest over the sorted rendered rows.
3. **Record.** Write the whole review record to
   `<record>.tmp` and rename it onto
   `<item-records>/<item>-review-record.txt` in one step, so a reader that
   finds the record always finds its whole content. An existing record -
   any verdict, any generation - never blocks a fresh review; the freeze
   replaces it in the one rename. This is the verb's only durable step and
   its only write anywhere: no ref, tag, registration, index entry,
   configuration file, commit, or file outside the record is created,
   moved, or deleted.

**Once-only, invalidation, and the three event kinds.** One accepted
review snapshot earns one complete proof set: the receipt's existence at
that digest refuses a second `proofs` run (the already-earned row), and
nothing else ever re-earns it - the restored-green rerun after each
mutation and the main verification from close step 7 are mandatory,
ungated, and never consumed by the once-only claim. Any later byte change

every gate that recomputes refuse the stale row naming the changed paths,
which is exactly WCPV-012: an edit after review or proof invalidates the

replaced). During the damage run the mutations are such edits on purpose:

mutations sit uncommitted in tracked targets - each restore
returns the bytes to the recorded digest, and the same receipt still
binds them - no re-earn is needed or possible until real repair changes
bytes. A missing private lane refuses through the declared command's own
failure (the command row), so no receipt is written and `checkpoint`
keeps refusing. The three command-order events a fixture distinguishes
