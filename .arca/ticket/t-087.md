# Ticket: t-087 — The Engine has no work-item concept

## Vertical Outcome

Pausing a Run is Engine work end to end. `rtm hold --run <id> --blocker <ref> --confirm
"hold <run-id>"` writes the paused mark and the blocker reference into the Run Record,
appends one entry to the Engine transition log, and touches no file under any workflow
root. The blocker is an opaque reference: the Engine checks that it exists and resolves
beneath a declared root, and nothing about its shape. The completion gate refuses a paused
Run by reading Engine-owned state. A runbook that has no notion of a work item can hold,
route, and refuse completion exactly like this repository's own.

## Worktree Scope

- **Included:** `src/blocked.rs` - drop the ticket path, the ticket-file read, the `status`
  field parse, `hold_ticket`, and `held_against`; address the hold by Run; write
  `status` and `blocker` into the Run Record under the existing lock and rollback discipline;
  reduce `verify_blocker` to existence plus containment beneath a declared root. `src/cli.rs` -
  the `--run`-addressed hold and its confirmation phrase. `src/completion.rs` - the paused
  verdict reads the Run Record. `src/model.rs`/`src/state.rs` - the paused mark, if the
  existing `blocked` status and `blocker` field do not already carry it. Refusal and
  transition-log wording that names a Run, never a document. `.arca/index.md` and
  `.arca/runbook-spec.md` prose that describes the old behavior. QA coverage in
  `test/qa/tests/t087_no_work_item.rs` and six private lane checks.
- **Why now:** `res-106` recorded this write as a gap for two sprints and could not be
  repaired, because `.arca/schema.md` and `PGE-006` required the Engine to make that exact
  write. Billy ruled on 2026-08-10 that `rtm` is a generic state-machine runner and some
  runbooks have no concept of a ticket at all, so the rule is gone and the repair is
  ordinary work.
- **The shop keeps its mark:** a contributor still writes `status: "held"` and `blocker-ref`
  into the ticket by hand, in the same landing as the hold. That mark is human-readable
  history; no Engine code and no gate reads it back.
- **Excluded:** the completion gate's other ticket knowledge - it still parses a declared
  `## Merge Gate` section, collects `HT-nnn-nn` lane ids, and keys receipts by `ticket-id`.
  That is the same leak in a different place, filed as its own wish on 2026-08-10 because
  removing it redesigns `PGE-005`'s receipt contract. Also excluded: `rtm abandon`, guard
  kinds, and the roots table itself (`t-076`).
- **Expected merge/output:** a full hold leaves every file under every workflow root
  byte-identical, and the Run Record and transition log carry the whole fact.
- **Superseded-test fate:** existing hold suites that assert the ticket file was rewritten
  are rewritten to assert the Run Record instead, and they must additionally assert the
  ticket file is byte-identical. Their refusal and rollback assertions stay.
