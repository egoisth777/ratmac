# Ticket: t-123 — portable goal fingerprints

## Vertical Outcome

Goal baselines and freezes for newly started Runs use one versioned, deterministic serialization: relative paths use forward slashes, path ordering is bytewise and case-sensitive, records are length-delimited, and CRLF pairs in valid UTF-8 text without NUL bytes become LF while all other content bytes retain their meaning. Identical relative paths and canonical content produce identical revisions across platforms; added, removed, renamed, or semantically edited files change the revision. Binary content is hashed unchanged. Existing unversioned fingerprints keep their original algorithm and semantics for live Runs, including a legacy baseline first frozen after the upgrade; archived stamps stay byte-identical and parseable. An unknown version or an unrepresentable path refuses by name without updating evidence. No existing pin is silently upgraded or accepted merely because it matches either of two algorithms.

## Observable Output

Defined before implementation. The public checks and the private lanes both
judge this shape; neither needs the other's arrangement or the source. Every
sentence below is observable through the process exit code, stdout/stderr
bytes, files under the Engine root or the goal root, or the operation log the
crate feature `test-fault-injection` writes. Paths in messages use the
Engine's one displayed spelling (forward slashes); `<Engine root>` below is
that spelling of the resolved shared `.ratmac/`.

**Terms.** The *goal root* is the runbook's declared `goal` root role,
resolved exactly as today (`src/roots.rs` role resolution is untouched).
Where a message below shows `<goal root>`, it prints today's text at that
site: the goal drift line prints `goal_address()`
(`src/scheduler.rs:3430-3435`), and a text inside `read declared goal root: `
prints the directory `goal_directory` hands the producer, displayed as
today's `RevisionError` renders it (`src/goal.rs:44-53`). A
`<displayed relative path>` is the entry's path below the goal root in the
Engine's one displayed spelling (`crate::root::displayed`, forward slashes;
invalid UTF-8 shows as U+FFFD). A
*revision string* is the text a revision carries: the *legacy revision* is
exactly 64 lowercase hexadecimal digits (what `goal::revision` on `main`
emits today, `src/goal.rs:82`); the *v2 revision* is exactly `v2:` followed
by 64 lowercase hexadecimal digits. The *fingerprint version* is selected by
the revision string's own form - `v2:` selects the new calculation, a bare
64-digit digest selects the legacy calculation - and by nothing else; no
field is added to any record to carry it. *Canonical goal bytes* are the
specified serialization below. A *newly started Run* is one whose baseline is
recorded by an Engine build carrying this contract; a *legacy Run* is a Run
whose recorded baseline is a legacy revision. The *baseline* is the revision
`start` records in `<Engine root>/runs/<id>/evidence.toml` under
`[goal] baseline` (`src/pin.rs:54-57`, rendered `src/pin.rs:194-204`); the
*frozen* revision is the one the intake-completing transition records under
`[goal] frozen` and in the Run Record's `goal_revision`
(`src/scheduler.rs:3027-3047`). *Drift* is the mismatch refusal between the
frozen revision and a later recomputation (`src/scheduler.rs:2967-2983`). A
*compound citation* is a residual record's `frozen-goal-bundle-revision`
value, whose value today embeds `goal-sha256:` by substring containment
(`src/contract.rs:735-749`); this contract tightens the goal token to exact
equality (below). An *archived stamp* is any
`frozen-goal-bundle-revision` value in a record under
`.arca/residual/archive/`.

**The two revision strings and which Run uses which.** A newly started Run's
baseline is a v2 revision; a legacy Run's baseline stays its recorded legacy
revision byte-for-byte. A Run whose recorded baseline is absent or empty
recorded no version - an Engine start with an absent goal root writes no
`[goal]` table at all (`src/pin.rs:194-204`) - so its freeze and every later
comparison use the legacy calculation: the fingerprint version is the marker
that selects one calculation, and with no recorded marker the existing
raw-byte calculation stays selected, so no live Run's algorithm changes
under this contract. The version used at every later comparison is the one
the Run already recorded: a legacy Run's freeze computes the legacy revision
(the legacy baseline first frozen after this upgrade stays legacy), and a
newly started Run's freeze computes the v2 revision. The legacy calculation
is exactly today's (`src/goal.rs:62-83`): gather every file under the goal
root, sort by relative path, hash `path bytes, LF, content bytes, LF` per
file, render 64 lowercase hex. No existing pin is silently upgraded, and no
comparison accepts a match under the other algorithm: a legacy Run compares
against the legacy recomputation only, a v2 Run against the v2 recomputation
only, whatever the other algorithm would say.

**Canonical goal bytes - the v2 serialization.** The hashed bytes begin with
the ASCII bytes `ratmac-goal-v2`, then one NUL byte, then the file count as
an unsigned 64-bit big-endian integer. Each file entry follows in ascending
bytewise order of its relative-path bytes, and contains, in order: an
unsigned 64-bit big-endian path-byte length, the UTF-8 relative-path bytes
with forward-slash separators, an unsigned 64-bit big-endian
canonical-content-byte length, and those content bytes. No delimiter,
terminator, or padding byte is added, so adjacent names and contents cannot
bleed into each other (the length framing, not a separator, draws every
boundary). Case and Unicode code points are preserved; names that differ are
never equated. A reader inside the Engine rejects any count or length that
cannot fit its unsigned 64-bit field; that bound is serializer-internal and
not reachable through this contract's observables. Relative paths that are
not valid UTF-8 refuse rather than converting lossily (today's producer
converts lossily, `src/goal.rs:97-100`). A file is *text* exactly when its
bytes are valid UTF-8 and contain no NUL byte; for text, every CRLF byte
pair becomes LF and nothing else changes - lone CR, byte-order marks, and
final-newline presence are preserved. Every other file is *binary* and
contributes its raw bytes unchanged, including any CRLF pairs. An empty goal
directory yields the zero-file serialization; an absent or non-directory
goal root keeps today's absent behavior (`src/goal.rs:63-70`: absent and
non-directory are `Ok(None)`, never an error). The four fixed vectors below
are part of this contract (file contents as hexadecimal; the text vector
also applies when its input is `68656c6c6f0d0a`, and the two-file vector
must match even if `b` is created before `a`):

**Success paths and their bytes.** `rtm start` in a project whose goal root
holds only representable entries prints today's one LF-terminated stdout
line `rtm: started run <id> at .ratmac/runs/<id>/`, exit 0
(`src/cli.rs:428`), and writes evidence whose `[goal]` table carries the v2
revision in `baseline` and `frozen = ""` exactly as today's shape renders it.
A freezing `rtm step --run <id>` prints today's State report; its Run Record
now shows `Goal revision: v2:<digest>` (`src/state.rs:276`) where a legacy
Run shows the bare digest, and the transition event appended to
`<Engine root>/log.md` carries the same string wherever it names the goal
revision (the abandon event renders it at `src/abandon.rs:355-364`).
`spawn` and `respawn` read the child or successor workspace's goal root with
today's text (below) and record the same v2 baseline shape. The record gate
accepts a compound citation `goal-sha256:v2:<digest>` for a v2-frozen Run
exactly as it accepts `goal-sha256:<legacy digest>` today: the citation's
`goal-sha256:` marker is followed by one revision string, read up to the end
of the field value or the next `+`, and that token must equal the Run's
frozen revision - substring coincidence no longer suffices. Archived stamps
are provenance: they are never recomputed, rewritten, or compared against
today's algorithm, and they stay parseable wherever they live.

**Goal drift.** After a freeze, `rtm step --run <id>` recomputes the
revision under the Run's recorded version and, on mismatch, keeps today's
exact bytes: stdout `rtm: step refused; goal drift: <goal root>: observed
<observed>; expected <frozen>` followed by `next: rtm step --run <id>`, exit
0, stderr empty, Run Record and `log.md` byte-identical
(`src/scheduler.rs:2967-2983`, failure rendering `src/scheduler.rs:252-260`
and `268-282`, CLI render and exit `src/cli.rs:446-452`, next line
`src/teach.rs:35-43`). `<observed>` is the recomputed revision in the Run's
own version, or today's literal `absent` when the goal root is gone. The
line-ending asymmetry is observable: on a v2 Run, converting every CRLF
pair in a text goal file (valid UTF-8, no NUL byte) to LF changes no
revision, so the step proceeds; the same edit inside a binary file - whose
CRLF pairs are raw content - and the same text edit on a legacy Run are both
drift and refuse with the line above. A semantic edit on either version
refuses the same way.

`rtm: spawn: read declared goal root: <detail>` (`src/cli.rs:423,426`,

**Locks, waits, and restart.** Nothing new waits and no lock order changes.
`start` reads the goal root before the root lock is taken
(`src/scheduler.rs:1492` precedes `admit_run`'s `RootLock::acquire` at `1539`), so
every read-side refusal above at start precedes all locking and every write;
`step` evaluates drift and freeze under only the addressed Run lock, exactly
today (`src/scheduler.rs:2896-2923`); the record gate's citation reads stay
inside today's guard evaluation. Restart behavior at each durable step is
today's, unchanged by this contract because the revision computation writes
nothing: an interrupted freeze leaves evidence and Run Record either fully
frozen or byte-unchanged (rollback texts today's: `snapshot evidence.toml
before freezing goal revision: <error>` and `freeze goal revision: write
evidence.toml: <error>`, `src/scheduler.rs:3108-3124`), and the retry
completes with the same revision string, because the computation is
deterministic in the recorded version. A killed start after the goal read
but before minting leaves no Run, as today.

**Operation log.** With `test-fault-injection` and
`RATMAC_TEST_OPERATION_LOG` set, this contract adds no operation kind and no
call site: the fingerprint computation and version selection mark nothing,
and the existing marks around them, among today's kinds (`runbook`,
`record`, `ledger`, `lock`, `roster`, `target`, `blocker`), keep today's
positions - a goal-read refusal at `start` therefore logs only the marks
that preceded the goal read and always precedes the first `lock` mark; a
drift refusal logs exactly today's marks up to the drift check.

**Fault injection**, compiled only with feature `test-fault-injection`;
unset, empty, or unrecognized values - or a build without the feature -
change nothing, and each fires at most once per invocation:

- `RATMAC_TEST_GOAL_FAULT`, one of `unrepresentable-path` (the v2 producer
  reports the non-UTF-8 refusal row above as if the next enumerated entry's
  path were unrepresentable) or `non-regular-entry` (it reports the
  non-regular refusal row the same way). The *next enumerated entry* is the
  first file in ascending bytewise order of displayed relative-path bytes;
  a goal root holding no file leaves the seam with nothing to name, so it
  changes nothing. When real entries refuse, the refusal names the first
  offending entry in that same order. Both host conditions are
  privilege-dependent to create for real (Windows symlink creation, raw
  non-UTF-8 directory entries), so the seam makes both suites able to prove
  the exact refusal bytes deterministically; on platforms where the real
  entry can be created, the public suite creates it for real and the seam is
  a no-op twin.
- Existing seams stay reusable unchanged: `RATMAC_TEST_STEP_FAULT` at its
  landed boundaries for interrupting the freeze's durable writes;
  `RATMAC_TEST_OPERATION_LOG` for the marks above; and the real-I/O device
  of blocking the evidence path with a directory (the `t043` fixture
  pattern) to fail the freeze write without any feature.
