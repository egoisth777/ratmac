# Ticket: t-054 — Runbook specification: the written authority

## Vertical Outcome

`.arca/runbook-spec.md` exists, is routed from `.arca/index.md`, and is the single written authority for the Machine Class: top-level shape, phase and transition fields, the closed guard-kind vocabulary with per-kind required and forbidden fields, the ownership rules with their enforcers, the diagnostic-code table the doctor will emit, and a back-reference table tying every statement to the requirement that decided it. Nothing else in the tree defines a schema term.

## Worktree Scope

- **Included:** `.arca/runbook-spec.md` ownership paths and enforcer table; the existing QA
  agreement test plus a regression that rejects superseded flat Run-file paths and requires the
  canonical per-Run State/evidence paths while retaining project-level Machine Class, Transition
  Log, and invocation lock ownership.
- **Excluded:** parser changes (t-055), doctor changes (t-056), authoring guidance (t-057), and
  transition-input format/lifecycle (t-061/t-062). This ticket corrects the written authority to
  match already-integrated run residency.
- **Expected merge/output:** one current ownership table: no stale flat State/evidence path, every
  ownership rule tied to its real enforcer or explicitly marked prose-only.
