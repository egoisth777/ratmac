# Ticket: t-107 - One repo-local lifecycle opens and closes a work item's turn in the fixed order

## Vertical Outcome

One repo-local lifecycle entry point under `tools/` - a PowerShell sibling of
the trial lifecycle, per ADR-0018's command-boundary ruling: not an Engine
subcommand, not a runbook-declared lifecycle the Engine drives - carries `open`,
`close`, and a `status` dry run. `open` checks every precondition (clean trunk,
no colliding branch or worktree registration, lanes root present) before the
first Git write - a failed precondition refuses with a named reason and zero
mutation - then creates the item-named branch with its registered sibling
worktree and copies the declared untracked lanes root in, skipping each lane's
declared build output. `close` runs the working rules' fixed order - merge,
verified copy-back, stamp, log line, removal, trunk rerun - each step refusing
on its own failure and blocking every later step, an interrupted close resuming
from the last completed step without redoing a landed mutation. A destructive
removal refuses while the worktree holds the only copy of any artifact, naming
the artifact and the copy-back that would release it, with no flag or force
variant; the dry run reports each verb's planned mutations and recovery commands
while changing nothing observably. The lanes root, trunk branch, skip list,
stamp field, and landing log are declared data in the runbook's `[roots]`-table
shape, so the mechanism learns no ticket concept and the item stays the opaque
binding string a Run already carries.

## Worktree Scope

- **Included:** the lifecycle entry point in `tools/` (PowerShell, the trial
  lifecycle's sibling); precondition checks and the `open` choreography (branch,
  registered sibling worktree, lanes copy with declared build outputs skipped);
  the `close` order with per-step refusal, recorded per-step completion for
  exact resume, and printed recovery commands under the trial lifecycle's
  ownership table - human or Main-Agent from the primary checkout, a Subagent
  invokes no lifecycle verb; the only-copy inventory refusal with
  obsolete-by-name declaration as the one explicit release; the `status` dry
  run; the close's stamp step deriving the landed-commit hash by `RCR-001`'s
  stamp-landing order (the t-106 rule); the schema.md Units-and-git revision
  landing the mechanized prose duty as its specification; focused tests; six
  hidden lane checks.
- **Excluded:** any Engine `src/` change - ADR-0018 keeps the Engine free of
  work-item and Git-worktree knowledge; any change to the trial lifecycle's own
  verbs; any change to guard evaluation; the citation checker (t-106).
- **Why now:** the close's stamp step mechanizes the stamp-landing order `t-106`
  fixes, so that rule must land first (route edge 1); and the destruction risk
  it guards - removal before copy-back destroying the crate's only copy, the
  t-076 shape - is prose discipline alone today (res-156).
