# Ticket: t-137 — test Engine from build messages

## Vertical Outcome

Every test helper that builds one of this repository's binaries and then launches it runs exactly the executable Cargo reported for that build - the `executable` in the binary's `compiler-artifact` record under `--message-format=json` - and never a path joined from a fixed folder such as `target/debug`. One shared function in the baseline support (`built_executable`) gives that answer for a build root, the caller's `cargo build` arguments, and a binary name. The shared helper `today_engine()`, the freeze Engine build, the edition proof preflight suite's `edition-cut` build, the two building tests of the single-Engine-binary suite, and the private lanes all go through it; the lanes drop their own build-message readers, the refusal in the refusing lane (`t-116`), the fallback in the TOML-reading lane (`t-133`), and their fixed joins, keeping each lane's identity and assertions. With output redirected by `CARGO_TARGET_DIR`, `CARGO_BUILD_TARGET_DIR`, `build.target-dir` in any Cargo configuration, or `CARGO_BUILD_TARGET`, the fresh build still runs and an older binary at the fixed folder never runs. A build that reports no such executable, or several, refuses naming the binary, the build command, and what Cargo reported, and runs nothing; a failed build's refusal carries the compiler's messages and Cargo's standard error. Helpers where Cargo runs what it built (`cargo test`), fixtures, and the bootstrap, which belongs to the Cargo-built bootstrap Engine requirement (SVE-002), stay out of scope; the general test support stays standard-library-only, and the frozen before-source corpus stays byte-identical.
