# Ticket: t-112 - Completion reads runbook-mapped declarations, never prose shape

This ticket is the sole owner of [`res-168`](../residual/res-168.md).

## Vertical Outcome

When this ticket closes, `completion_gate` receives one typed, all-or-none
runbook mapping that selects three front-matter string lists. One shared generic
reader returns their opaque entries in focused, hidden-lane, then quality order;
the Engine knows the receipt kinds but no project field name, Markdown heading,
lane-id shape, backtick convention, file suffix, or ticket concept. Declaration
shape failures refuse before receipt loading or mutation, while the existing
receipt format, Run-keyed paths, target binding, sensitivity behavior, receipt
safeguards, and receipt-defect wording remain unchanged.

The capability and its fixtures land while stable `edition-007` continues to
drive `run-030` with the frozen, unmapped live runbook. Only after that Run
reaches rest does the recording/activation landing apply the already-tested
mapping and switch the traversal fixture back to exact shipped bytes. That
post-rest landing adds no Engine behavior.
