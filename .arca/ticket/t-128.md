# Ticket: t-128 — deterministic trace channel

## Vertical Outcome

One module owns Engine stderr output and an environment-enabled decision trace. The trace is off by default, writes only to stderr, creates no file or persistent state, and performs no formatting or allocation per disabled event. Enabled events cover root selection, transition-input edge selection, guard refusal, lock acquisition/release order, and mint read/write decisions. Each structured record carries a stable event/diagnostic code, reusing the refusal code where one exists, and deterministic fields with no timestamps, durations, absolute host paths, arbitrary child output, secrets, or nondeterministic identifiers. The same normalized input/state/decision sequence produces identical structured trace bytes; these restrictions do not erase or rewrite the established mandatory-error text. Existing stderr sites are routed through the owning module; mandatory errors remain visible when tracing is off. No guard, gate, receipt, or hidden behavioral lane consumes trace text as evidence.

## Observable Output

Defined before implementation. The public checks WEBV-025 through WEBV-028
(`test/qa/tests/t128_deterministic_trace_channel.rs::webv_025` …
`::webv_028`) and the private lanes HT-128-01 through HT-128-06 both judge
this shape; neither needs the other's arrangement or the source. Every
sentence below is observable through the process exit code, stdout/stderr
bytes, files under the Engine root or the invoking checkout, the operation
log the crate feature `test-fault-injection` writes, or the one in-process
library seam this contract names. Paths in messages use the Engine's one
displayed spelling (forward slashes); `<Engine root>` below is that spelling
of the resolved shared `.ratmac/`.

**Terms.** The *owning module* is the one new source file `src/diag.rs`,
public as `ratmac::diag`; it is the only code in `src/` (including
`src/bin/`) that touches the standard error stream. A *mandatory diagnostic*
is a byte sequence the Engine already owes the operator on stderr today: the
entry-point error render `rtm: {error}` (src/bin/rtm.rs:23), the
current-directory failure `rtm: current directory: {error}`
(src/bin/rtm.rs:8), and the sixteen `warning:` lines inventoried below. A
*trace record* is one LF-terminated structured line the Engine writes to
stderr only while tracing is enabled; the *record sequence* is the ordered
list of those lines of one invocation. The *toggle* is the environment
variable `RATMAC_TRACE`; tracing is *enabled* when its latched value is
exactly `1` and *disabled* when the variable is unset, empty, or exactly
`0`. The *latch* is the single read of the toggle at the first
invocation-context construction of a process (the binary constructs exactly
one); the latched flag is transient in-process state - no file, no
environment mutation, no persisted Engine state, no global mutable event
log. *Value escaping* is this one rule, used by every quoted field value in
this contract: inside double quotes, a backslash renders `\\`, a double
quote `\"`, line feed `\n`, carriage return `\r`, tab `\t`; every other
byte below 0x20 and byte 0x7F renders `\u00XX` with two lowercase hex
digits; every other byte renders verbatim. A *refusal code* is the stable
code a refusal already carries - here a guard failure's `kind` string (the
first field of every `guard_failure(...)` call,
e.g. `files_exact`, `terminal`, `goal drift`, `verdict`, `transition`,
`scheduler`); this contract assigns no new one and renames none. The *durable
lock domains* are the root and Run lock files under `<Engine root>/locks/`;
the *transient policy claim* is the ignore-policy lock `start`/`init` take
in the Engine root. A *gate child* is a program the Engine spawns to
evaluate a `command_exit` guard.

**The toggle.** The latch reads `RATMAC_TRACE` once, when the invocation
context is first built - in the binary, after the current-directory read and
before any command dispatch. Nothing later in the process re-reads it, so a
mid-invocation environment change is invisible. `cli::run_from` and every
other library entry never read the toggle: called in process they neither
refuse an invalid value nor emit records - the invalid-toggle refusal and
the latch belong to the binary alone, so binary/`run_from` parity is
unchanged for every toggle state.

| `RATMAC_TRACE` value | Behavior |
| :--- | :--- |
| unset, empty, exactly `0` | Tracing disabled. Every observable - stdout bytes, stderr bytes, exit status, files before/after, operation-log bytes, every fault and pause seam - is byte-identical to today's build on this repository. |
| exactly `1` | Tracing enabled: stderr additionally carries the trace records defined below, in decision order, interleaved with mandatory diagnostics at their occurrence positions. Nothing else changes: stdout bytes, exit codes, all files, and the operation log stay byte-identical to the disabled run of the same command over the same fixture. |
| any other value (`true`, `01`, `" 1"`, `2`, non-UTF-8 bytes, …) | Refusal before any work: exit 2, stdout empty, stderr exactly one LF-terminated line `rtm: RATMAC_TRACE="<value>" is not a valid trace setting; set it to 1 to enable the decision trace or 0 to disable it; nothing was run`, where `<value>` renders with value escaping; the value's byte view is its `OsString` bytes on Unix and its WTF-8 bytes on Windows, so a non-UTF-8 value renders every byte either verbatim or as `\u00XX`, and a test constructs such a value with the platform's native `OsString` constructor. No `next:` line. This refusal precedes help rendering, the t-120 residue preflight, every lock, and every write, so it writes nothing; only the current-directory failure (src/bin/rtm.rs:8) can precede it. This is the one deliberate predecessor to t-120's preflight and help rules: t-120's three-things list and its pure-help exit-0 rows hold for every invocation that does not set an invalid toggle, and no t-120 fixture sets the variable, so its pinned orderings are unchanged where they are observed. |

Disabled is the default for every process that never builds a CLI invocation
context - library entries, gate children, every in-process caller that did
not latch: they emit no records.

**Record grammar.** One trace record is one LF-terminated stderr line:

```
rtm-trace: <fields>
```

The line begins with the eleven bytes `rtm-trace: ` (`rtm-trace:` plus one
space); the Engine's own composed mandatory texts never contain that byte
sequence, so a line beginning with it is always a record. `<fields>` is one
or more `key="value"` pairs separated by single spaces, in the fixed order
of the record's code below; keys are bare lowercase identifiers. Every value
is double-quoted and renders with value escaping, so a State name, input
value, or guard path containing quotes, spaces, or newlines round-trips
byte-exactly. The first field is always `code`. The whole line, prefix
through LF, is produced by exactly one write to stderr, so a reader never
observes a partial record. Nothing else is ever prefixed `rtm-trace: `.

**Event vocabulary.** Fixed and closed; each row pins the fields after
`code`, in order, and the decision that fires it. Placeholders: a Run id
renders the canonical minted spelling `run-NNN` (`run-` plus the zero-padded
`{:03}` ordinal, widening past 999 exactly as the mint does); an integer
renders as plain decimal ASCII, no sign, no padding; an absent optional
field is omitted entirely, never rendered empty.

| `code` value | Fields after `code`, in order | Fires when, with what |
| :--- | :--- | :--- |
| `root_selection` | `resolution` | Each distinct project resolution of the invocation (the first resolution per project, matching the context cache): `resolution="repository-primary"` when Git's worktree listing supplied the shared Engine root, `resolution="checkout-local"` when resolution fell back to the invoking checkout. The record carries no path. |
| `edge_selection` | `run`, `from`, `input` (present exactly when the addressed State - the Run's current State, the `from` State whose live verdict carries the input - declares inputs), `to` | One `rtm step` (top-level or child) whose guards all passed and whose route resolved: `run` the addressed id, `from`/`to` the State names, `input` the exact transition-input value the live verdict carried. A refused step fires the refusal codes below instead and never this code. |
| a refusal code (a guard failure's `kind`, verbatim) | `run`, `path` (omitted when the failure's path field is empty, and always omitted for `goal drift`, `intake_contract`, and `record_contract`) | Once per failure of a refused `rtm step`, in the refusal's failure order - guards in declaration order, then the synthetic checks in today's order - reusing that failure's refusal code unchanged (`files_exact`, `file_contains`, `command_exit`, `sensitivity_receipts`, `completion_gate`, `intake_contract`, `join`, `record_contract`, `scheduler`, `terminal`, `goal drift`, `verdict`, `transition`, `authorization`, `authorization: enrollment`, and the six verification kinds today's governed step spells as `authorization: <kind>` - `authorization: signatures`, `authorization: reviews`, `authorization: approval`, `authorization: replay`, `authorization: engine`, `authorization: review`). `path` is the failure's path field verbatim (a declared relative path, a State name, or `verdict.toml`); the three kinds named above carry resolved absolute root locations in that field today, so their records omit `path` rather than leak the host layout or differ across fixture locations; observed/expected text is never copied into a record. No runbook-parse refusal fires a record; only a refused step's guard failures do. |
| `lock_acquire` | `domain`, `run` (present exactly when `domain="run"`) | Each successful acquisition of a durable lock domain or the transient policy claim: `domain` one of `root`, `run`, `policy`; `run` the canonical id for a Run lock. Contended attempts and non-owning waits emit nothing. |
| `lock_release` | `domain`, `run` (as above) | Exactly once per acquired lock, when its guard is dropped - first write of the drop, before any cleanup warning the drop may also produce. |
| `mint_read` | `recorded`, `roster` | Each mint attempt, after both reads succeed: `recorded` the `highest` integer the mint record held, or `absent` when no `mint.toml` existed; `roster` the greatest roster ordinal as an integer (`0` when `runs/` is absent). |
| `mint_write` | `reserved` | After the mint record durably holds the new ordinal: `reserved` the canonical id minted (e.g. `run-005`). A failed read or write emits no record; the refusal carries it. |

No other code exists; no record carries a field this table does not name for
its code. Records never wait: the channel takes no lock and holds no state;
each record is attempted once at its decision point.

**Firing points and order.** Records appear in decision order on stderr.
`rtm start` with tracing enabled, on a fresh repository, produces this
record sequence: `root_selection` (`checkout-local` for a fixture
outside any Git repository; any Git repository - including a
single-checkout one whose primary is the invoking checkout itself -
reads `repository-primary`, because Git's worktree listing supplied the
root); `lock_acquire` `domain="policy"` for the ignore-policy step and
its `lock_release`; `lock_acquire` `domain="root"`; `mint_read`
(`recorded="absent"`, `roster="0"`); `mint_write` `reserved="run-001"`;
then the Run-mutation `record` work; then `lock_release` `domain="root"`.
`rtm step` on a Run whose guards refuse produces `root_selection`,
`lock_acquire` `domain="run"`, one refusal-code record per failure in
failure order, `lock_release` `domain="run"` - and the step's refusal render
on stdout and exit code stay exactly today's (a refused step is stdout plus
exit 0, unchanged). Root-before-Run order is observable as bytes: wherever
the Engine takes root then Run (`spawn`, `respawn`, `abandon`), the
`lock_acquire` `domain="root"` record precedes the `lock_acquire`
`domain="run"` record of the same decision; a contended Run claim that makes
`acquire_root_then_run` release and retry emits the actual release and
re-acquire records of the sequence that happened. Hold, abandon, spawn,
respawn, and intent emit lock and mint records at their own acquisitions
and mint attempts exactly as the table names them; this contract pins the
codes and their per-decision meaning, not per-command counts. Warnings
stay mandatory diagnostics, unchanged, interleaved at their occurrence
positions.

**Disabled is today's baseline, proven cheap.** With the toggle unset, empty,
or `0`, the two suites compare stdout, required stderr, exit status, and a
full filesystem snapshot before/after against today's build and find zero
differences; no record prefix appears anywhere. The no-work proof: the
public seam `ratmac::diag::event(code: &'static str, build: impl
FnOnce(&mut ratmac::diag::Record))` - the same entry every internal site
uses - returns immediately when tracing is disabled: `build` is never
called, so allocating field expressions never evaluate, and the call itself
performs no formatting and no heap allocation. The unit test (in the owning
module's `#[cfg(test)]`, part of the workspace run WEBV-025 names) installs
a counting global allocator and asserts three budgets separately: zero
allocations across a disabled `event` whose closure allocates and sets a
flag (and the flag never set); zero allocations for the latch when the
variable is absent; and, measured on its own, the explicitly-present read
(`0` or `1`) may allocate for its environment copy - that budget never
excuses the disabled-event budget. The counting allocator observes only the
asserting thread's allocations (a thread-checked counter), so the crate's
parallel unit tests cannot perturb any budget; each budget is the delta of
that thread's count across the measured call. `Record` exposes only field
insertion; nothing in the public API writes when disabled.

**stderr failure.** A failed or closed standard error never changes a
decision: every trace record is attempted once and its write error, if any,
is discarded; a guard verdict, transition, mint, lock outcome, exit code,
stdout byte, and file byte are exactly what they would have been with the
write succeeding. Mandatory diagnostics keep today's ignored-error
semantics (the entry point's `let _ =` discipline, src/bin/rtm.rs:8 and :23).
No trace write retries, blocks, or panics.

**Determinism and privacy.** Two invocations of the same command over
byte-equivalent isolated fixtures - different absolute locations, different
clocks - with tracing enabled produce byte-identical record sequences. No
record ever contains a timestamp, a duration, an absolute host path, a
process id, an environment variable's value, a lock owner token or nonce, or
free-form child output; external paths appear only through a declared role
or redacted marker, and this vocabulary needs none. Run addresses and
declared State and input names appear only as the durable input state
determines them. The contended-lock retry sequence is part of the decision
sequence, not the fixture: isolated fixtures without contention have none.
Mandatory errors keep their established actionable text and paths
byte-for-byte - for example `lock wait expired: <path>; <owner-token
diagnostic>` still names the absolute lock path - and WEBV-027 asserts that
separately from the record checks.

**Children and guards never consume the channel.** Every child process the
Engine spawns - the Git queries of root resolution and canonicalization,
ignore-policy classification, spawn-time ledger provenance, and channel
resolution; every gate child of a `command_exit` guard; and the pinned
`ssh-keygen -Y verify` signature verifier child that authorizes governed
motions - runs with `RATMAC_TRACE` removed from its environment and every
other inherited variable unchanged. A gate child therefore cannot
inherit the Engine's trace channel as a proof input, and its captured bytes
reach only the existing bounded refusal diagnostics - never a record field,
never a receipt channel, never accepted evidence. Guards, gates, receipts,
and every hidden behavioral lane judge real state, receipts, exits, and the
outputs already in the product contract; none parses `rtm-trace: ` text, and
the skill folder, every `--help` text, the route table, and every refusal
text are unchanged by this ticket.

**Fault seams and the operation log.** The operation log keeps exactly its
existing kinds (`roster`, `record`, `ledger`, `runbook`, `target`, `lock`,
`blocker`); this ticket adds no kind and moves no mark, and with tracing
enabled the log's bytes are byte-identical to the disabled run. Every
compiled seam keeps working beside tracing - `RATMAC_TEST_OPERATION_LOG`,
`RATMAC_TEST_LOCK_HOLD` with its marker, release, and timeout companions,
`RATMAC_TEST_LOCK_FAULT`, `RATMAC_TEST_ROOT_LOG`/`RATMAC_TEST_ROOT_REPEAT`,
the respawn and hold pause seams with their one-step marker writes - and any
of them may be set together with `RATMAC_TRACE=1`; the combination adds
records to stderr and changes nothing else. Trace never replaces a pause
point: pauses still control timing, trace only observes.

**Interruption and recovery.** The trace channel creates no file and no
persistent state, so there is nothing to recover: killing a traced
invocation at any durable step of any command leaves exactly the bytes the
same kill leaves today (a lock file left behind compares by name; its
owner-token contents differ between any two processes today and are not
part of the comparison), and the repeated command behaves identically with
tracing on or off. The latch never survives the process.
