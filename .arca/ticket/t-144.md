# Ticket: t-144 — Cargo-built bootstrap Engine

## Vertical Outcome

The project-local bootstrap (`tools/rtm.ps1`) takes the Engine from Cargo's answers. After a build it uses the executable Cargo reported for `rtm`; when it reuses a binary, it takes one only from the build root's Cargo-resolved output folder. A stable build always uses its build checkout's own `target` as both Cargo's output folder and its build folder; with no channel or the nightly channel, a resolved folder outside the project root means building first. The bootstrap hashes, reports, and pin-checks that binary and never one at another path, such as the checkout's `target/release` or `target/debug` under a redirect. If Cargo reports or resolves no Engine, it refuses by name, stating what it searched and the repair. Its declared build output becomes the output and build folders Cargo resolves, and `Cargo.lock`; channel choice, stamping, the offline build, no global writes, and the clean-tree rule stay as they are.
