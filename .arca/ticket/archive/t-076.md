# Ticket: t-076 — Roots table

## Vertical Outcome

A runbook declares repository-relative guard roots in one top-level `[roots]` table, and
all guards address those roots by role name. Static validation gives different diagnostic
codes for an undeclared name, missing path, and Engine-root overlap. Engine source names the
retired pre-split folder exactly once, in a declaration that states its own name and owner,
and a check fails on a second literal or on a rename of that declaration.

## Worktree Scope

- **Included:** typed `[roots]` parsing and validation; root-name resolution for every guard
  consumer; documented diagnostic codes and doctor rendering; replacement of Engine-source
  `.arca` path literals with the root/resolver model; fixture/runbook updates; QA coverage
  in `test/qa/tests/t076_roots_table.rs`; and six private lane checks.
- **Released, 2026-08-10:** this ticket was held against the two contradicting
  engine-namespace rows ([i-026](../../issue/archive/i-026-namespace-row-rulings/index.md)).
  Billy ruled both. `NRR-002` admits the one named exception, so `res-113` (ENS-008) is
  satisfied at re-judgment - the roots table was already green at `b213ad5` and the clause
  that held it open is superseded. `NRR-001` moves the whole held fact into Engine-owned
  state; the write this ticket inherited as `res-106` is that ruling's work, not the roots
  table's, so `res-106` moves to `t-087` with `res-126`.
- **Remaining work (`res-127`, NRR-002):** the exception declaration
  (src/scheduler.rs:26) names itself and the refusal that consumes it, but assigns its
  owner as "`t-077` owns retiring it" - a ticket that has landed. The ruling makes the
  exception permanent for as long as `ENS-009` stands, so the declaration must state its
  real owner, and the check that pins the declaration must fail when that owner clause
  goes missing.
- **Excluded:** Engine-root resolution itself (`t-071`), pre-split residue detection
  (`t-077`), workspace binding (`t-074`), and changes to guard kinds or their existing
  readiness semantics. The table is repository-relative data, not a way to grant arbitrary
  absolute-path access.
- **Expected merge/output:** a valid named root resolves only within the repository, each
  named static defect returns its own stable diagnostic before Engine motion, and an audit
  of `src/` finds exactly one `.arca` literal, in the declaration that names its own owner.
- **Superseded-test fate:** hard-coded workflow-path fixtures are converted to root-name
  fixtures; existing guard pass/refusal behavior remains required after its filesystem
  address is data-driven.
