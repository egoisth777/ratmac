# Ticket: t-019 — Keep guard failure out of blocked

## Vertical Outcome
When an Exit Guard fails during `schd step`, the Scheduler refuses and preserves the existing Status; it never changes that Status to `blocked` (which is reserved for missing entry prerequisites).

## Worktree Scope
- **Included:** Distinguish guard-failure refusal from entry-prerequisite blocking and preserve the current Status on guard failure.
- **Excluded:** Entry-prerequisite detection itself (t-006), general refusal transaction semantics (t-018), and report wording (t-020).
- **Expected merge/output:** Status classification and `T-05` test merge after t-006/t-018; guard failures cannot enter the blocked path.
