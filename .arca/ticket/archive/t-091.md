# Ticket: t-091 — Open work items are decided by machine

## Vertical Outcome

Whether work remains open is computed, not read. A check over the declared roots distinguishes
an item still being worked from one that has taken the authorized archive move, using only what
is on disk and never prose a contributor wrote. Seeding one unproven gap record flips exactly
one item to open, and nothing else moves.

## Worktree Scope

- **Included:** `src/contract.rs` — the open-against-landed predicate over the declared ticket
  root and the gap records it owns, and its diagnostic when the two disagree. QA coverage in
  `test/qa/tests/t091_open_work_item.rs` and six private lane checks.
- **Why now:** the cycle's build loop has to know when to keep going, and today that answer is
  a person applying a rule by eye. It shares the contract module's root reading with `t-088`,
  so it follows that ticket rather than colliding with it in the same file.
- **Excluded:** the Engine learns nothing about what a work item contains — the predicate reads
  location and the gap records, never a document's fields or shape, so `NRR-001` holds. The
  record gate's existing ownership and dependency checks are unchanged.
- **Expected merge/output:** on this repository the predicate agrees with the lookup a person
  performs today, and the disagreement case is a named refusal rather than a silent pick.
- **Superseded-test fate:** none superseded; the record-gate suites keep every check they have,
  and gain the predicate's own cases.
