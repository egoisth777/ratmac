# Ticket: t-075 — Engine transition log

## Vertical Outcome

The Scheduler alone appends the Engine transition history at `.ratmac/log.md`. The
contributor history `.arca/log.md` becomes human-only: Engine start, step, refusal, and
recovery paths do not write it. The relocated transition log retains the existing one-record
on successful transition and append-only failure-recovery guarantees.

## Worktree Scope

- **Included:** transition-log path relocation through Scheduler and failure rollback paths;
  explicit separation of Engine and human history writers; updates to log-related diagnostics,
  fixtures, and tests; QA coverage in `test/qa/tests/t075_engine_transition_log.rs`; and six
  private lane checks.
- **Excluded:** the root resolver itself (`t-071`), lock split (`t-073`), runbook root
  mappings (`t-076`), and any human-history editing policy. This ticket adds Run identity to
  transition records because byte equality previously let one Run read another Run's record as
  its own; agents still do not write the Engine log.
- **Expected merge/output:** every successful transition appends exactly one Scheduler-written
  record to `.ratmac/log.md`; a failed append restores the addressed Run's exact prior State
  when comparison proves it safe; `.arca/log.md` is byte-identical across all Engine invocations.
  An incomplete Engine record, if any, remains for human resolution.
- **Superseded-test fate:** R-026 tests referring to `.arca/log.md` become `.ratmac/log.md`
  tests with the same prefix, refusal, and recovery oracles; a separate snapshot now proves
  the human log remains untouched.

## Documented limits

- **Path aliases:** Path aliases below the Engine root are outside the cooperative threat model.
  A hard link is indistinguishable from an ordinary file by path, and the only complete defense
  would require naming `.arca/log.md` in `src/`, which ENS-008 forbids. Whoever can create one
  can already write the human log directly.
- **Partial records:** A partial transition record is never removed. The
  failed writer classifies zero bytes, a proper prefix, or a complete record
  from its own write count; it never re-reads shared history to infer that
  outcome. Another Run can append at any time, so replacing the shared log
  could discard that record. The Engine restores the addressed Run only under
  its exact-byte comparison; a human resolves any incomplete record.

- **State-first interruption:** A process death or equivalent interruption between the State
  rename and the history append leaves a transition that happened with no record. This ordering
  deliberately chooses a missing true record over a false one, because a history that can lie is
  worse than a history with a gap. `inject_step_fault("after-state-replace")` and the T-062
  assertion demonstrate the successor State File in that window.

## Shared-writer repair notes

- **Separator provenance:** The non-newline concatenation of `- Hold:` and
  `- Abandoned:` predates this funnel: those caller records lacked a leading
  newline and their former direct appenders wrote them unchanged. It is an
  inherited defect, not a funnel regression. The funnel now prefixes a
  newline whenever its caller did not supply one; step already supplies one,
  so its bytes remain unchanged. Hold and abandonment records now use the
  same blank-line spacing as steps, including at the start of a fresh log.
  No public assertion pinned the prior hold or abandonment spacing;
  `ENSV-008` now observes their shared-writer prefixes.
- **State parent sync:** `StateStore` now reports a durable replacement
  separately from a completed replacement whose parent sync warned. Step and
  hold consume that warning, surface it, and continue to append history
  because the State File is committed. The other direct callers are
  `mint_run`, which cleans an incomplete mint, and the state-only
  `initialize_state` and `record_missing_prerequisite` APIs. They retain their
  pre-existing strict parent-sync abort behavior; they do not append a
  transition record and are outside this ticket.
- **Shared record identity:** Ordinary transitions, holds, and abandonment
  records each name their addressed Run. Hold now extends its preserved
  `- Hold:` record with `Run <id>`; the public oracle checks that exact Run
  identity rather than reducing the record check to a substring route match.
