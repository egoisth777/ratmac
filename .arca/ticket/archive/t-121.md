# Ticket: t-121 — engine ignore initialization

## Vertical Outcome

A documented, idempotent initialization command installs the Engine-root tracking policy before any Run can be admitted: runs/, mint.toml, locks/, and log.md beneath the resolved Engine root are ignored, while ratmac.toml and evidence/ remain eligible for tracking. Initialization preserves unrelated bytes and compatible operator rules, refuses an incompatible effective rule with the exact path and repair, and leaves no partial initialization on failure. Already-indexed runtime files and failures inspecting an available repository's index or effective ignore rules refuse without mutation; they are not treated as absent Git. Repeating it with the same effective policy is a byte-identical no-op. Linked worktrees protect the shared runtime root and their own tracked authoring surfaces. A fresh project's first start cannot create unprotected runtime; no command silently stages, commits, changes global Git configuration, or overwrites a runbook.

## Observable Output

Defined before implementation. The public checks and the private lanes both judge this shape;
neither needs the other's arrangement or the source.

**Command and route.** `init` joins the route table first: the general usage's `Commands:` line
reads `Commands: init, start, status, step, hold, abandon, spawn, respawn, doctor, scaffold,
skill`. `rtm init` takes no arguments and addresses only the invoking checkout with its Engine
root (the t-120 target scan gains `init` in its none group). The t-120 preflight covers it like
every operational command: with retired-layout residue present, `rtm init` with any arguments
refuses `rtm: init: <residue refusal>`, exit 1, stdout empty, tree byte-identical, before init's
own validation. `rtm init --help` and `rtm init -h` are the only pure help forms (the help below,
exit 0, nothing resolved, inspected, read, or written); `--help` or `-h` among other arguments
behaves exactly as t-120 defines for an operational request. Any other argument form - `rtm init
extra` - is init's ordinary usage error: `rtm: init accepts no arguments`, exit 2, stdout empty,
nothing written. Paths inside messages use the Engine's one displayed spelling (forward
slashes).

**`rtm init --help`.** stdout is exactly, exit 0, stderr empty:

```
Usage: rtm init

Install the Engine-root tracking policy before any Run is admitted: .ratmac/.gitignore carries the four runtime lines /runs/, /mint.toml, /locks/, and /log.md, each exactly once, while the runbook and evidence/ stay trackable. Existing bytes are preserved; a conflicting effective rule, a runtime file already in Git's index, or a failed repository inspection refuses and changes nothing. Idempotent and concurrency-safe: repeating it writes nothing, and no Run, runbook, commit, or configuration is created. rtm start runs the same policy step before admitting a Run.
```

The general usage lists no per-command descriptions, so its only change is the `Commands:` line
above. The operator skill (`src/skill.rs`) enumerates no commands and `README.md` lists none, so
no line of either changes.

**The installed policy.** The policy file is `<Engine root>/.gitignore` (Engine root = the
resolved shared `.ratmac/`, the primary checkout's in a linked worktree). The policy lines are
exactly, in this order, one per line: `/runs/`, `/mint.toml`, `/locks/`, `/log.md`.

- A fresh file (absent) is created holding exactly those four lines, LF-terminated, ending in
  one `\n`, nothing else. The Engine root directory is created first only when absent.
- An existing file keeps every byte. A policy line counts as present when the file holds a line
  whose text, after removing one trailing `\r`, equals that pattern exactly. Only the missing
  policy lines are appended, in the order above, each `<pattern>\n` (always LF); when the
  existing bytes are non-empty and do not end with `\n`, exactly one `\n` precedes the first
  appended line, so no existing byte changes and the last operator line stays its own line. A
  zero-byte file receives exactly the fresh bytes.
- Nothing else is ever written: no blanket `.ratmac/` or `.ratmac/*` rule, nothing outside the
  Engine root, no `runs/`, `mint.toml`, `locks/`, `log.md`, runbook, Run, index change, staging,
  commit, or Git configuration. After any outcome, no staging file or lock artifact that init
  itself created remains; a pre-existing `locks/` and its contents are untouched.

**Git verification.** Classification first, cwd the invoking checkout: `git rev-parse
--is-inside-work-tree`. Git absent (the executable cannot be spawned), or Git establishing the
directory is outside a repository - exit 0 answering other than `true`, or a nonzero exit whose
stderr says `not a git repository` - is **no verification** (the not-verified line below).
Exit 0 answering `true` means inside a repository: the policy bytes are made effective
(installed, or already in place), the effective result is verified, and a failed verification
rolls the policy bytes back so the tree stays byte-identical. Any other failed Git query - a
nonzero classification exit for another reason, or an index or ignore-rule query that fails
inside an established repository (a corrupt index, for example) - refuses as class D below;
never a downgrade to no-Git.

Inside a repository the verified effective result is exactly:

| Probe path | Must be |
| :--- | :--- |
| `<Engine root>/runs/run-001`, `<Engine root>/mint.toml`, `<Engine root>/locks/root.lock`, `<Engine root>/log.md` | ignored |
| `<Engine root>/.gitignore` | not ignored |
| `<invoking checkout>/.ratmac/ratmac.toml`, `<invoking checkout>/.ratmac/evidence/run-001` | not ignored |

The index check: Git's index names nothing under the four runtime paths (`git ls-files --` over
them outputs no row). Compatible rules are not conflicts: pre-existing rules that already ignore
a runtime path - this repository's root `.gitignore` Engine-root lines, for example - neither
refuse nor change a byte; only the effective verdict above and the index content decide.

**Refusals.** Every refusal: exit 1, stdout empty, stderr `rtm: init: <text>`, tree
byte-identical (a file or directory init alone created is removed), text ending
`nothing was modified`.

| Class | Text |
| :--- | :--- |
| A - a runtime probe stays visible | `refusing to install the ignore policy: the runtime path <path> would stay visible to Git (<source>:<linenum>:<pattern>); remove or repair that rule, then retry; nothing was modified` |
| B - an authoring probe is ignored | `refusing to install the ignore policy: the authoring path <path> would be ignored (<source>:<linenum>:<pattern>); repair that rule so ratmac.toml and evidence/ stay trackable, then retry; nothing was modified` |
| C - runtime already indexed | `refusing to install the ignore policy: the runtime path <path> is already in Git's index; untrack it with git rm --cached <path>, then retry; nothing was modified` |
| D - a repository query fails | `refusing to install the ignore policy: cannot inspect the repository: git <arguments> failed: <first line of its stderr>; repair the repository, then retry; nothing was modified` |
| E - policy file unreadable | `refusing to install the ignore policy: cannot read <path>; make it a readable UTF-8 file (not a directory), then retry; nothing was modified` |
| F - destination unwritable | `refusing to install the ignore policy: cannot create or write <path>; make the Engine root a directory and the policy file writable, then retry; nothing was modified` |

`<source>:<linenum>:<pattern>` is the effective rule exactly as `git check-ignore -v` reports it
(a root or nested `.gitignore`, `.git/info/exclude`, or `core.excludesFile`); class A's pattern is
typically a negation. `<arguments>` in class D names the failed query, for example `ls-files --
<paths>` or `check-ignore -v -- <path>`.

**No Git.** With no verification, init installs the local policy, exit 0, and its stdout carries
`rtm: repository-level ignore rules were not verified: Git is absent or the directory is not
inside a Git repository` - never a verified claim.

**Success stdout.** exit 0, stderr empty, exactly three LF-terminated lines:

| Line | Forms |
| :--- | :--- |
| 1 | `rtm: installed the Engine-root tracking policy at <Engine root>/.gitignore` (a fresh file or an append), or `rtm: Engine-root tracking policy already present at <Engine root>/.gitignore` (all four lines already present; the run writes nothing) |
| 2 | `rtm: verified: runs/, mint.toml, locks/, and log.md ignored; .gitignore, ratmac.toml, and evidence/ trackable`, or the not-verified line above |
| 3 | `next: rtm scaffold .ratmac/ratmac.toml` when no `.ratmac/ratmac.toml` exists at the invoking checkout, otherwise `next: rtm start` |

**`rtm start`.** After its residue preflight and its own argument check, and after runbook
validation (the runbook parse, the initial State, and the goal baseline all succeed), but before
any runtime write - before the Engine root lock is acquired, before `log.md`, `mint.toml`,
`locks/`, or `runs/` is touched - `rtm start` runs the same policy step with init's exact bytes,
verdicts, and refusal classes. A policy refusal refuses start as `rtm: start: <the same refusal
text>`, exit 1, no Run admitted, tree byte-identical. When start refuses for any other reason
after the step installed policy bytes (a held root lock, a mint or guard failure, a runbook pin
drift), those bytes are rolled back: the tree is byte-identical, including removing a policy
file or Engine-root directory the step alone created. A successful start keeps the policy bytes
and its stdout is unchanged - it prints nothing about the policy.

**Concurrency.** Concurrent `rtm init` (and `rtm start`) policy steps in one checkout are
serialized: after all complete, the policy file holds the operator's bytes with each of the four
policy lines exactly once - never duplicated, never dropping operator content - and no staging
or lock artifact remains after any outcome.

**Fault injection**, compiled only with feature `test-fault-injection`:
`RATMAC_TEST_INIT_FAULT=staged-write` fails the write of the staged copy;
`RATMAC_TEST_INIT_FAULT=replace` fails the final replacement. Each refuses with
`rtm: init: injected init fault at staged-write; nothing was modified` (or `at replace`), exit 1,
tree byte-identical, no staged copy or lock artifact left. Unset, empty, or any other value - or
a build without the feature - has no effect, and a run that would install nothing is not
faulted. The same fault applies inside start's policy step as
`rtm: start: injected init fault at <boundary>; nothing was modified`, with start's rollback.

**Library surface and observer.** No new public path-taking library entry exists; module
internals are `pub(crate)`. `cli::run_from` answers `init` exactly as the binary does (t-120's
rule). The t-120 operation observer gains init's footprint: an exit-0 `rtm init` (installed or
already present) appends exactly `lock` (the policy step's serialization) then `target` (the
runbook existence check that picks the `next:` line), in that order; the residue and usage
refusals and the pure help forms log nothing; any other refusal logs at most `lock`. Git queries
and policy-file reads log nothing. `rtm start`'s clean control keeps at least `runbook`, `lock`
(t-120 allows repeats); the policy step adds no new observer kind.

**This repository initializes itself in the same landing.** The tracked file
`.ratmac/.gitignore` holds exactly init's fresh policy bytes, and the root `.gitignore` keeps its
Engine-root runtime lines (`.ratmac/runs/`, `.ratmac/mint.toml`, `.ratmac/locks/`,
`.ratmac/log.md`) as compatible operator rules. The primary checkout's first `rtm init` (and
`rtm start`'s policy step) under the new Engine is therefore a byte-identical no-op - the
already-present line, no write, no untracked file - and stays one because those root rules merely
ignore the same runtime paths: this contract refuses only an effective verdict (a runtime path
visible, an authoring path ignored) or an indexed runtime file, never the coexistence of
compatible rules.
