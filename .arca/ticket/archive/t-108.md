# Ticket: t-108 - Landed lanes sweep on demand, expire by dated marker, and gate the close

## Vertical Outcome

One sweep command under `tools/`, in the shape of `tools/check_links.py`,
enumerates `test-hidden/t-*/` in id order against the declared roster of landed
crates and runs every crate from the primary checkout, writing one report
artifact under a declared root: exactly one verdict per crate - `pass`,
`expired`, or `red` with the failing lane ids - plus a total, naming a crate
the roster expects and the folder lacks rather than skipping it. The expiry
marker lives inside the crate it marks and names the edition the lane last
passed at; the sweep counts an expired lane as neither `pass` nor `red`, so a
`red` verdict always means a live regression, and marking or unmarking is the
same explicit act the 2026-08-10 repair was; expired lanes are skipped by
default, with an explicit verify mode that runs them anyway so a marker cannot
quietly outlive its lane's recovery. The close wiring is expressed in the
existing guard vocabulary - one `command_exit`-class guard beside `EDN-002`'s,
refusing only on a `red`, unexpired verdict, no new guard kind, the Engine
learning nothing about lanes - and it is prepared here, wired at the next cycle
boundary: the runbook pin (`FDC-005`) makes every later operation on a live Run
refuse on drift until the pinned bytes are restored or the Run retired, so a
runbook edit landing mid-cycle would wedge the cycle's own Run rather than gate
its close.

## Worktree Scope

- **Included:** the sweep command in `tools/` (a Python sibling of
  `tools/check_links.py`; id-order enumeration against the declared
  landed-crate roster, per-crate run from the primary checkout, one report
  artifact under a declared root, missing crates named); the in-crate expiry
  marker format - names the last-good edition, travels with the crate, a
  tracked summary may cite it but never replaces it - with marking and
  unmarking as explicit acts, and the verify mode; the first sweep's recorded
  decisions (`t-102`..`t-105` read `pass`; the markers the first run's findings
  call for, beginning with `t-078` and `t-079` expired naming their last-good
  edition; every remaining verdict `red` with lane ids - never a bare,
  unexplained failure); the close wiring authored as a single-purpose Machine
  Class diff - one `command_exit`-class guard beside the edition guard,
  refusing only on a `red`, unexpired verdict, nothing else - proven on fixture
  classes and applied to the tracked `.ratmac/ratmac.toml` at the next cycle
  boundary when no Run is live; focused tests; six hidden lane checks.
- **Excluded:** any Engine knowledge of lanes or new build target (ADR-0020);
  any standing schedule - when the sweep runs stays a human decision recorded
  where the working rules keep it; any tracked summary replacing the in-crate
  marker; any change to the close State's existing guards beyond the one added.
- **Why now:** rot is a silent class confusion today - the 2026-08-10 findings
  and the 2026-08-21 rebuilt crates are indistinguishable in the tree (res-162),
  nothing sweeps the 48 landed crates (res-161), and the close has no verdict to
  read (res-163).
