# Ticket: t-062 — Durable transition-input delivery

## Vertical Outcome

One strict live verdict record at `.arca/runs/<id>/verdict.toml` delivers exactly one legal
transition input for the addressed Run and current Phase. It contains only `phase`, `input`, and a
non-empty `rationale`; absence means no input, and `rtm start` creates no placeholder. `rtm step`
evaluates guards first, then validates the record against the current Phase and its closed legal
list. A valid record is atomically renamed into collision-free immutable Run evidence and removed
from the live slot before the successor State File is replaced. Refusal consumes nothing; replay
requires a fresh record. Straight-line movement rejects a stray record and otherwise needs none.

## Worktree Scope

- **Included:** `src/verdict.rs` strict parsing/validation and archive rename, `src/scheduler.rs`
  guard-before-read and consume-before-state ordering, `src/model.rs`/`src/pin.rs` Run evidence
  address helpers where needed, `src/lib.rs` exports, removal of the start-time empty verdict
  placeholder, current QA fixtures/tests, a test-only fault boundary for both archive/state crash
  windows, and hidden durability/adversarial lanes.
- **Excluded:** who authors or signs the verdict, judge independence, terminal lifecycle values,
  spawn-ledger content, recursive composition, network delivery, and a `failed` terminal.
- **Expected merge/output:** a live record is either untouched, or archived exactly once before a
  state advance; no code path can advance from a branching Phase without a valid current record.
- **Superseded-test fate:** remove only the `verdict.toml` existence assertions from
  `test/qa/tests/t059_run_residency.rs`, `.arca-private/t-058`, `.arca-private/t-059`, and
  `.arca-private/t-060`; replace them with `FDCV-020` (absent after start). Keep every
  `spawn-ledger` assertion and the FDC-004 verdict-slot address contract.

## P5 notes (2026-07-30)

**What landed.** Start now represents an empty Verdict slot by absence. At a branching Phase,
`Scheduler::step` runs every retained guard first, then `verdict::load_live` accepts only one strict
current-Phase record with exactly `phase`, `input`, and a non-empty `rationale`. Its `input` selects
the already-validated labelled edge. `verdict::archive_live` atomically renames the exact live bytes
to the next six-digit file under `.arca/runs/<id>/verdicts/` before the successor State File is
written. Straight-line Phases need no record and reject a stray one without consuming it.

**Failure and interruption review.** Missing, malformed, extra, wrong-type, blank, stale, and
off-list records all use the ordinary step-refusal surface and leave the Run byte-identical. A
pre-rename failure leaves old state plus the live record. A post-rename/pre-state failure leaves old
state plus one immutable archive and requires fresh judgment. A post-state failure exposes the
advanced state plus that same one archive. The feature-gated test hooks surround those three
boundaries only; no path writes `failed`, reinterprets a guard refusal, or changes `abandoned`.
Goal-freeze evidence is resolved before consumption, then written after consumption and before the
State File, preserving both ETB-003 and consume-then-advance. If the later history append fails, the
error states that the advance stands and identifies the missing transition line for repair.
