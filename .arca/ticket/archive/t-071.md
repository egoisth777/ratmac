# Ticket: t-071 — Engine root and resolution

## Vertical Outcome

The Engine has one runtime root, `.ratmac/`, rather than an Engine-owned corner of
`.arca/`. A linked Git worktree shares the primary checkout's runtime root but reads its
own tracked Machine Class; a checkout without Git uses its own `.ratmac/`. State retains
its Scheduler-owned fields and Run-scoped location beneath that resolved root, and the
runtime/tracked-file boundary prevents live Run state from entering ticket branches.

## Worktree Scope

- **Included:** a single Engine-root resolver and its use by Scheduler, State, pin,
  ledger, command-line, and doctor paths; moving Engine-owned Machine Class, Run state,
  runtime evidence, locks, and transition-log addresses under `.ratmac/`; the Git
  worktree and no-Git resolution cases; `.gitignore` tracking rules; replacement QA
  coverage in `test/qa/tests/t071_engine_root.rs`; and six private lane checks.
- **Excluded:** durable mint semantics and repository-wide Run identity (`t-072`), the
  lock split (`t-073`), child workspace binding (`t-074`), the Engine log behavior
  change (`t-075`), runbook roots (`t-076`), pre-split refusal (`t-077`), and root
  reporting (`t-078`). This ticket does not auto-migrate legacy artifacts.
- **Expected merge/output:** start, step, and status use only the resolved `.ratmac/`
  Engine root; a linked invocation shares runtime while its edited Machine Class still
  participates in the existing pin-drift refusal; and Git ignores runtime while tracking
  the Machine Class and run-scoped receipts.
- **Superseded-test fate:** the `.arca/` layout expectations in the reopened R-024 and
  R-025 coverage are replaced with `.ratmac/` root assertions while their State File
  shape, Scheduler-only writer, and no-flat-state assertions remain required.
