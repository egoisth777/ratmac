# Ticket: t-103 - Status and step teach what each guard reads and what comes next

## Vertical Outcome

`rtm status` and `rtm step` render, for each pending guard, what it expects -
derived from the parsed guard declaration - and every outcome ends in one truthful
`next:` line or deliberately omits it. An agent on any project learns the loop from
the engine's own output.

## Worktree Scope

- **Included:** guard-expectation rendering derived from the typed guard
  declaration (`src/machine.rs` types, rendered through `src/state.rs`/`src/cli.rs`);
  a `next:` line on every status/step rendering path with refusal repairs mapped
  from their stable codes; golden tests pinning both; six hidden lane checks.
- **Excluded:** the skill subcommand (t-104); any new guard kind; any change to
  guard evaluation itself.
- **Why now:** the operator protocol's runtime half; the t-104 skill points at this
  output for everything current, so it must exist first (sprint route edge 1).
