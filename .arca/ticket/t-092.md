# Ticket: t-092 — The Plan-Build Runbook

## Vertical Outcome

This repository's Machine Class declares the process this repository runs. Its States are the
cycle's stages — intake, gap check, cutting the work items, the ticket turns, close, rest — with
agent-facing prompts and Exit Guards drawn only from the closed vocabulary. A Run started on it
advances from intake to rest by starting and stepping alone, with no rule supplied from outside
the file, and `rtm doctor` exits `0` on it with no guard whose verdict rests on content the
agent under test can write.

## Worktree Scope

- **Included:** `.ratmac/ratmac.toml` — the demonstration machine is replaced by the cycle: the
  roots it names, one State per stage with its prompt, the Exit Guards between them, the child
  class for the ticket turns with its bound per-item gates, the declared transition input that
  routes out of the gap-check stage, and the checkpoint guard before the damage step. QA
  coverage in `test/qa/tests/t092_plan_build_runbook.rs` and six private lane checks.
- **Why now:** every piece it consumes is landed by its dependencies, and the engine has never
  run a real process.
- **Excluded:** no engine behavior changes here — this ticket writes data and proves it runs.
  File-shaped guards over paths outside the Engine's own tree are excluded by construction,
  because they raise the warning that would make the doctor exit non-zero. The landing line
  stays a human act. The runbook is authored under the manual cycle one last time and governs
  the sprint after it; a machine cannot bootstrap its own first Run.
- **Expected merge/output:** `rtm doctor` exits `0`, and a Run started on the file reaches rest
  by stepping.
- **Superseded-test fate:** every suite that depends on the shipped demonstration machine is
  repointed at a fixture copy of it, so those tests keep testing the engine rather than this
  repository's process, and the demonstration machine survives as a fixture rather than as the
  shipped file.
