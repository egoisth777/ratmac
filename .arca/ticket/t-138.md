# Ticket: t-138 — sweep crates build apart

## Vertical Outcome

By default the lane sweep (`tools/sweep_lanes.py`) runs each crate's `cargo test --offline` with a Cargo output folder no other crate builds into, even when a Cargo configuration file sends every build in the repository to one folder. Before testing a crate, the sweep asks Cargo, in that crate and with inherited `CARGO_` variables dropped as today, where the crate's build would go, and names the crate's folder to Cargo on that crate's command line only, never in its environment: the crate's own `target` when Cargo already resolves it there, as today, otherwise a folder named after the crate inside the configured folder, which still decides where build output is stored. A crate for which Cargo cannot answer reads red with Cargo's error, as a build refusal does today. The explicit `--target-dir` opt-in to one shared folder stays as it is; the sweep keeps one `cargo test --offline` per crate with its report, roster, and expiry rules, and its own description of where each crate builds changes to match.
