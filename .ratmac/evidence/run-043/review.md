# Independent review before full proof

Accepted on 2026-09-27, before executing the full workspace proof.

- Two independent reviewers split the work; neither edited, built, or ran anything. One reviewed the source change (the new `src/ignore_policy.rs`, and `src/cli.rs`, `src/lib.rs`, `src/lock.rs`, `src/root.rs`, `src/scheduler.rs`), the new tracked `.ratmac/.gitignore` against the root `.gitignore`, the public oracle, the adjusted public checks `test/qa/tests/t120_residue_refusal_precedence.rs` and `test/qa/tests/t108_lane_sweep.rs`, and the ticket's two added regression entries. The other reviewed the new private crate `t-121`, which a separate agent wrote without reading the public oracle or the source, and that agent's adjustments to the landed private crates `t-104`, `t-120`, `t-071`, and `t-058`, judged from the ticket and the lane bytes alone.
- The source review accepted in its first round with one low note: a failure to take the policy step's own serialization lock (a directory planted at its lock path, or a wait that expires) refuses with its own text, `cannot serialize the policy step`, rather than one of the six classes. The shape still holds - exit 1, empty stdout, a tree left byte-identical, the text ending `nothing was modified` - and the ticket names no class for that cause, the way start's root-lock wait expiry keeps its own text, so it stays.
- The private review took two rounds. The first asked for two repairs: the fault inside start ran only the `replace` boundary, although its oracle says both faults refuse inside start, so it now runs `staged-write` and `replace`, each on a fresh fixture with its own operation log; and an already-present `rtm init` never had its operation log armed, so the rule that every exit-0 init logs exactly `lock` then `target` is now checked there too. A third finding, that `git check-ignore -v` exits 1 when the last matching rule is a negation, was refuted by running it: with `-v` it prints the negation rule and exits 0. The second round accepted, with the six oracle comments unchanged.
- Before review, three private assertions and one public fixture were found wrong against the ticket and corrected by their own writers, never by the implementer: the library twin compared the absolute Engine-root line across two different fixture roots, so each side's own root spelling is now replaced by one placeholder before the byte comparison; a start refused by the policy step was held to init's "at most `lock`" bound although the ticket runs the step after the runbook is read, so start refusals now log only `runbook` and `lock`, with `runbook` present; the faulted start never passed its operation log to the Engine, so it read absent for any Engine; and the public linked-worktree fixture wrote into a folder it never created.
- The workspace run surfaced two landed checks the contract changes but the ticket had not listed; each was added to the ticket's regression paragraph before its writer changed it: a first start's exact created-file set in `ht_058_05_output_filesystem` gains `.ratmac/.gitignore`, and the close-guard fixture in `t108_lane_sweep.rs` ignored all of `.ratmac/`, which the verified table forbids, so its blanket line became the four runtime lines this repository's own root `.gitignore` carries.
- The first full proof then failed in seven landed private crates, and each failure was traced before anything changed. Six were fixtures the contract now refuses or checks that must see the new file, so each was added to the ticket's regression paragraph before its writer changed it: `ht_059_05_output_filesystem` gains `.ratmac/.gitignore` like `t-058`; the fixtures in `t-090`, `t-092`, and `ht_108_06` ignored all of `.ratmac/`, so each blanket line became the four runtime lines, other lines kept; the `t-077` linked fixture committed `.ratmac/log.md`, so it now leaves that file out of the commit and keeps its bytes on disk; and the shared freeze comparison in `test/qa/src/baseline.rs`, which `t-085` uses, sets aside the new `init` verb beside the existing `skill` one and a new `.ratmac/.gitignore` only when its bytes are exactly the fresh policy. The seventh was an Engine defect: the policy step's own lock fired the test-only release hold that `t-073` sets for the root lock, before that lock existed; the implementer limited that hold to the root and Run locks, with no test changed. The source reviewer accepted all three in a second round, keeping the same low note; the private reviewer accepted the five lane changes in a third round. A fresh lane sweep reported 63 pass, 2 valid expiries, 0 red, 0 missing.
- The second full proof stopped at the first failing public test file, so the whole workspace was then run without stopping: exactly five tests failed, all in three public fixtures, `t090_damage_checkpoint.rs`, `t092_plan_build_runbook.rs`, and `t094_edition_guard.rs`, whose root `.gitignore` ignored all of `.ratmac/`. They were added to the ticket's regression paragraph, their writer gave each the four runtime lines with no assertion changed, and the source reviewer accepted them in a third round.
- The deliberate-damage run then caught a real Windows race in the accepted source: rerunning the public check green after restoring a probe, one concurrent `rtm init` in `webv_008` refused with `cannot open lock ... gitignore.policy.lock: Access is denied`. Windows removes a lock by delete-on-close, so while a peer releases, the name is delete-pending and every open is denied; the shared lock code read that as a hard refusal. A stress driver of 30 rounds of parallel `rtm init` failed 5 rounds before the fix and none after. The implementer changed only `src/lock.rs`: for the policy step's transient lock alone, a denied open of a name that is not a directory now counts as a peer still releasing and waits within the lock's existing deadline; a directory at the lock name still refuses at once, and the durable root and Run locks are untouched. The source reviewer accepted it in a fourth round, keeping the same low note, which now covers two texts of that one lock-failure family. The damage run was then repeated from a fresh safety commit.
- The fourth full proof then failed one landed public check, `t056_typed_parser.rs::the_runbook_has_exactly_one_reader`, only because `src/ignore_policy.rs` became indexed at the safety commit and that check scans indexed Engine source: every module that names the runbook file must take the name from `MachineClass`, its one reader. The implementer changed only the probe list to use `MachineClass::FILE_NAME`, the same bytes at run time, and the source reviewer accepted it in a fifth round, keeping the same low note.
- `.ratmac/lanes.toml` gains only the `t-121` roster entry in sorted order, which the schema requires in the same change as the crate; the lane sweep proves it mechanically.
