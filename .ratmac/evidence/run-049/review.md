Accepted on 2026-10-02, before executing the final full workspace proof.

One reviewed the source change (`src/`, `Cargo.toml`, `.arca/runbook-spec.md`, `.arca/runbook-authoring.md`) against the ticket. The other reviewed the new private crate `test-hidden/t-129` and the public suite `test/qa/tests/t129_authorized_review_transitions.rs` against the ticket, plus the regression adjustments in five public suites and three private ones.

Every verification refuses when the enrollment manifest is missing; there is no trustless fallback. For `rtm hold`, the plan's existing checks run before the verification boundary. In `rtm step` and `rtm hold`, enrollment failures compose as `authorization: enrollment: observed <detail>; expected the enrolled trust origin`. In `rtm intent`, they stay the bare `rtm: intent refused; <detail>`. The ticket gained three regression adjustments. In `t057` and `t058`, the code catalogue and seed table gain `RB701`-`RB705`, and `.arca/runbook-authoring.md` gains five `restore-file` rows. In `t044`, the source scan drops the four authorization words. That last one resolves a goal clash between `ORS-001` and `WRA-001`, recorded as a `conflict-resolved` line in `.arca/log.md`.
- The implementer's runs exposed test defects, and each was fixed by its owner rather than by bending the Engine. Two signing helpers signed one payload twice, but the host `ssh-keygen` will not overwrite a signature. One public section looked up reviewer keys it never generated. Several public lanes signed at a branching State with no live verdict. A private lane expected the run lock at `.ratmac/locks/run-001.lock` instead of today's `.ratmac/locks/runs/run-001.lock`. A refused step's `record` count was compared for equality against a successful twin.
- The source review took three rounds. The first asked for two high, ten medium, and five low repairs. The mediums: an intent render's verification boundary logs no `record` mark, and Windows protection is now judged by `AccessCheck` against the builder's effective token instead of trusting any deny entry. The lows: the step help description is restored; three intent hard errors gain today's next line; intent resolves the verdict and route before the enrollment; the inside-Engine-root check normalizes `..`. The third round accepted with no findings. It judged three choices the ticket leaves open as consistent with it: a repeated `--approve` refuses at the authorization boundary, beside the ticket's duplicate-label refusal, while an ungoverned repeat still refuses at argument validation; the reparse check walks the whole path before any ownership fact; an intent on a terminal Run renders today's step guard text.

The second round asked for one high, two medium, and six low repairs, and every one gained a lane. The new lanes cover: a table omitting `approver-may-review`; a real builder-owned manifest refused as `not protected against the builder actor`, both at `rtm start` and through a governed step; a directory-junction manifest refused as `cannot be verified as protected`; four mutated manifest families (actor, project scope, reviewer set, unknown key); the stale-approval digest value; a single-file publish; terminal and already-blocked intent refusals; a repeated `--approve`; a spawn from a governed parent; one root resolution per render; the verdict before enrollment on intent; and an `--out` escaping through `..`. That proof was discarded and the full proof rerun.
- The second full workspace proof failed one landed check, `t110_post_split_ports`: the lane sweep run inside the workspace tests reported the `t-124` lane red on `ht_124_04_durability_recovery`, a test that drives the turn tool through pause points and waits up to 45 seconds for each marker file. The suite runs the Engine in the test process, and `wrav_004` turned on the step-fault switch for the whole process while the other tests ran unguarded; the focused proof missed it because it runs one thread. The public owner made each test hold the shared test lane for its whole body, as the private crate already does, and removed the now-nested locks; no assertion changed. The private reviewer accepted the change, and the suite then passed six parallel runs and one single-threaded run before the proof was rerun.
- After the fourth full proof passed, the deliberate-damage run found one hole: no private lane reached `rtm intent`'s Run-open failure, so a change that dropped that hard error's next line survived. The private owner added one control to `ht_129_02`: a governed Run whose runbook drifts after start, with `rtm step` on the same Run as the twin, and `rtm intent`'s refusal pinned byte for byte to the step's with only the command word changed. The private reviewer accepted it and confirmed the one remaining survivor, the hold's redundant outer record-quiet scope, is unobservable. The new lane passed on the unchanged source and caught the change, and the full proof was rerun.
