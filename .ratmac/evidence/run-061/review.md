# Independent review before full proof

Accepted on 2026-10-27, before executing the final full workspace proof.

- Three independent reviewers worked from the implementation as reviewed. None of them edited, built, or ran anything in either checkout; any probe of behaviour ran only inside a fresh temporary folder that was deleted afterward. The source reviewer took the shared function `built_executable` and the rest of `test/qa/src/baseline.rs`, the single-Engine-binary suite's two building tests, the edition proof preflight suite's `edition-cut` build, and the seventeen private lanes moved onto the shared function. The public reviewer took `SVEV-001` to `SVEV-003`, and the private reviewer took the new private lane crate, HT-137-01 to HT-137-06. All three read the ticket worktree, never the primary checkout's sources.
- Before red, the coordinator accepted two exceptions the issue does not name - the `t-101` and `t-102` private lanes, fixed joins only, for the same reasons as their public suites - and recorded the known gaps in the red landing: the inventory sees a redirect refusal only as a presence call and misses joins built through a variable, only `SVEV-001`'s configuration case and HT-137-06 catch a `CARGO_TARGET_DIR` fallback, and the freeze case reads today's `ratmac-freeze-<commit>` layout.
- The implementation runs `cargo build --message-format=json` with the caller's arguments in the given build root and the test process's own environment, sets or clears no variable, and answers with the one distinct non-empty `executable` among the `compiler-artifact` records whose target name is the binary; up-to-date records count. With no such record, or several distinct paths, it refuses naming the binary, the build command, the build root, and every record Cargo reported, or `nothing`; a failed build refuses with that same listing, then the `rendered` text of every `compiler-message` record in Cargo's order, then Cargo's standard error. `today_engine()` builds once per test process through it. The freeze build keeps its own `--target-dir` and `--features test-fault-injection` and takes the `rtm` path Cargo reported. Moving `t-086` and `t-113` off `support::command` means their builds now see the test process's environment, redirect variables included, which is what the ticket asks for. The new private lane crate gained an empty `src/lib.rs`: the build-target audit reads every roster lane as `Cargo.toml` beside `src/lib.rs`, and refused the crate as a whole without it.
- The first reviews all rejected. The source review found that a failed build's refusal left out what Cargo reported, the shape the ticket pins, and that HT-137-05's failed-build case never checked for that listing; it also noted the freeze build's panic escaping the refusal text, a start failure saying no `Cargo reported` part, and the `t-116` header comment. The public review found that the `SVEV-003` inventory saw a redirect test only as a direct presence call, so `if let Some`, `let Ok ... else`, `while let`, `match`, and the `_and`/`_or` tests went unflagged. The private review found that HT-137-05 never checked a failed build's listing, that HT-137-01 let a `today_engine()` that rebuilds on every call pass, and that HT-137-06 tied neither `t-116` run to the Engine Cargo reported and reused one output folder for both.
- The repairs changed only the refusal text in the implementation: a failed build's refusal now lists what Cargo reported, or ` nothing`, before the compiler messages, the freeze build panics with the refusal as written, and a build that did not start says `Cargo reported: nothing`. The public writer widened the inventory's redirect and fixed-join matchers with fifteen new controls and none removed, made `SVEV-001` also compare `today_engine()` with Cargo's report in cases (a), (b), and (d), made `SVEV-002` require the compiler's own `-->` location line, and made the configuration case compare the checkout's own Cargo configuration byte for byte before and after instead of requiring it absent. The private writer added the listing check and the word `nothing` to HT-137-05, moved HT-137-01 into a child process whose builds go to a fresh folder, where a stand-in replaces the first answer and later callers must leave it alone, gave each HT-137-06 run its own fresh folder that must already hold the Engine Cargo reported, and tightened HT-137-03.
- The renewed reviews all accept, with no high or medium finding left. Their notes stay open as recorded: the inventory still misses a variable read on one line and tested on a later one, and a build profile held in a variable, and no such form exists in this repository; a cache with no lock still passes HT-137-01, because no caller overlaps the first build; a `today_engine()` that never builds passes HT-137-01's child and is caught by HT-137-06; and the first line of a refusal can stand in for the requested record's own listing line in HT-137-02.
- Every repaired check was re-proven in both directions. Against the implementation all three public checks and all six private lanes pass. The red receipts under this Run were recorded again with the final oracle files, in a fresh clone of the red commit `a9d7a98`, so each receipt's command runs the oracle that lands: `svev_001` fails all five redirect cases with the fixed-folder answer, `svev_002` returns the planted older `rtm-qa`, and `svev_003` finds 59 sites in 322 sources - 46 build-message reader lines, 12 fixed joins including the red stub's own, and `t-116`'s refusal. The private writer saw all six lanes fail at that commit for their missing behaviour after their controls pass.
