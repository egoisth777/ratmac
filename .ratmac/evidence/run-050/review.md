# Independent review before full proof

Accepted on 2026-10-03, before executing the final full workspace proof.

- Two independent reviewers split the work; neither edited, built, or ran anything in either checkout, and each probed `git` and `pwsh` behavior only in scratch folders under the system temp directory. One reviewed the source change (`tools/turn.ps1`) and the public suites (`t125_checkpoint_only_restoration.rs` and the regression adjustment in `t124_byte_verified_restores.rs`) against the ticket. The other reviewed the new private crate `test-hidden/t-125` and the adjustment to private `t-124`.
- Before red, the contract points the test writers raised were settled in the ticket, never by the implementer: round-trip refusal fixtures commit under the safety subject so their refusals stay reachable, and `t-124`'s dirty-restore twin moves to the new unrelated-work refusal, which now fires before the first write instead of after it. During the build the subject was settled as the first line of `git log -1 --format=%s`, compared byte for byte.
- The implementer's runs exposed test defects, and each was fixed by its owner rather than by bending the tool: the public suite's paused child process inherited pipes it never drained; private `ht_125_04` compared a world that included the pause seam's own marker and release files; private `ht_124_06` expected a porcelain row that line-ending settings never produce for that fixture.
- The source review took two rounds; so did the private review. In the first round both asked for the same medium repair: the unrelated-work guard compared `git status --porcelain` rows byte for byte against the manifest's spellings, so a damaged target with a non-ASCII name (which Git prints quoted) or a target given as `./a.txt` was refused as unrelated work. The private review added one low: no suite drove a rename row through the guard. The ticket's Terms were extended: a row's paths are read as Git names them, with Git's quoting decoded; each manifest spelling is compared in its plain repository form; a row that cannot be read that way counts as unrelated; refusals still print rows exactly as Git does; the manifest keeps the given spellings; and the restore's two git calls name targets in plain form (Git's `update-index --cacheinfo` rejects `./`), byte for byte `t-124`'s for plain spellings. The private owner added the matching cases; the test writer showed that a staged rename between two targets prints as a `D` row and an `M` row, never an `R` row, so `R` and `C` rows only ever reach the refusal.
- In the second round both reviews accepted. The source reviewer found one low: the rename-row splitter compared a five-character window against the four-character ` -> ` separator, so it never split. No verdict changed on this host, since every `R` row refuses either way and `>` cannot appear in a Windows file name. The implementer fixed it and proved the split with plain, quoted, and quoted-arrow rows in a scratch folder.
- The deliberate-damage probe writer, working ahead of the final suites, flagged four faults no lane would catch: a case-only subject difference on the restore side, the stale check reading the trunk tip instead of `HEAD`, the guard moved after the index reset, and only the first path of a rename checked. The private owner added a case for each: a restore at a `HEAD` whose subject differs only by case, a verified restore with a stale twin on a work branch ahead of the trunk, staged damage beside unrelated dirt with the index as found, and a rename to an outside path refused by its own row.
- Behavior no lane can reach, judged by reading only: the decoder's branches for backslash, tab, newline, and double-quote escapes and for malformed quoting, since none of those bytes can appear in a Windows file name and Git always prints valid UTF-8 here; the splitter on a quoted side that itself contains ` -> `, for the same reason; dropping empty path components, since `checkpoint` already refuses such a spelling with `t-124`'s untracked-target refusal (Git cannot resolve `sub//b.txt` at a commit) and a hand-edited manifest fails the restore's blob check; and the plain form in the `ls-tree` and `git restore` path lists, which Git normalizes on its own.
- Before review, the implementer reported green: public `t125` 3/3 and `t124` 3/3, private `t-125` 6/6 and `t-124` 6/6, private `t-107`, `t-111`, and `t-090`, public `t107`, `t111`, `t090`, `t034`, `t037`, `t118`, and `t126`, `cargo clippy` (one existing warning in an unchanged file), and `python tools/check_links.py`. After the splitter fix, public `t125` and `t124` and private `t-125` and `t-124` ran green again.
- The first full workspace proof failed one landed check, `t110_post_split_ports`: its nested lane sweep reported the `t-086` lane red on `ht_086_05_the_shipped_command_keeps_its_path_name_and_identity`, a test that hashes the shipped command in the shared build folder. No reviewed input had changed since this review, and that lane reads none of this ticket's files. Run alone in the worktree, it passed 3/3. The proof was discarded and rerun with nothing changed.
- The second full workspace proof failed a different landed check, `t022_r026`: two of its parallel tests, `log_open_failure_leaves_state_unchanged` and `non_newline_log_gets_separator_before_record`, failed with each other's damage (access denied writing the log, an empty roster). Each test names its temporary folder from the process id and the clock in nanoseconds, and the Windows clock advances in 100-nanosecond steps, so two tests that start in the same step share one folder. That suite tests only the Engine, which this ticket does not change; run alone, it passed 5/5. The proof was discarded and rerun with nothing changed.
