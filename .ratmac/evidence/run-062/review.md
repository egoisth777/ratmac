Accepted on 2026-10-29, before executing the final full workspace proof.

- Independent reviewers worked from the implementation as reviewed. None of them edited, built, or ran anything in either checkout; any probe of behaviour ran only inside a fresh temporary folder that was deleted afterward. The source reviewer took the sweep change in `tools/sweep_lanes.py`, the public reviewer took `SVEV-019` in `test/qa/tests/t108_lane_sweep.rs`, and the private reviewer took the new private lane crate, HT-138-01 to HT-138-06. - By default the sweep now asks Cargo where a crate's build would go before testing it: `cargo metadata --format-version 1 --no-deps --offline`, run in the crate with the environment its test gets - inherited `CARGO_` variables still dropped - read for `target_directory`. When that is the crate's own `target`, compared after giving both one spelling (the Windows long-path prefix taken off, links and short names resolved, letter case and separators made the same), the crate builds there, as before; otherwise it builds in a folder named after the crate inside the resolved folder. The folder reaches Cargo only as `--target-dir` on the crate's `cargo test --offline` command line, never in its environment, so no lane process inherits it. When Cargo cannot answer - `cargo metadata` fails, times out, or prints no usable absolute `target_directory` - the crate reads red with the reason, Cargo's first error line as a build refusal when it printed one, and the sweep goes on. The explicit `--target-dir` opt-in is unchanged: it still reaches every crate through `CARGO_TARGET_DIR` and skips the question. The sweep's help text and `run_crate`'s description now say where each crate builds.
- The source review accepted with no high or medium finding. Its probes ran a copy of the sweep over five fixture crates with `CARGO_TARGET_DIR` and `CARGO_BUILD_TARGET_DIR` set on the sweep as decoys: an unconfigured crate built in its own `target`, a crate whose own configuration names `TARGET/` built there and not one level deeper, a crate whose configuration names an outside folder built in that folder's `t-003`, a crate whose `target` is a junction built directly in it, and a broken configuration read red with Cargo's error while the next crate still ran; the decoy folders were never created and no lane process saw a build-folder variable.
