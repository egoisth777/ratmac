# Independent review before full proof

Accepted on 2026-09-29, before executing the final full workspace proof.

- Two independent reviewers split the work; neither edited, built, or ran anything in either checkout, and each confirmed Git and PowerShell behavior only in scratch folders under the system temp directory. One reviewed the source change (`tools/turn.ps1`) and the public suite `test/qa/tests/t124_byte_verified_restores.rs` against the ticket. The other reviewed the new private crate `test-hidden/t-124`, written without reading the public suite or the new script code, judged from the ticket and the unchanged script bytes alone.
- Before red, three test-writer questions were settled in the ticket, never by the implementer: several targets pass as one PowerShell array-syntax token, `-Target <path>,<path>`, which the tool splits on commas and drops empty pieces; the digest-mismatch guidance renders the settings the manifest recorded, never the checkout's current ones; and the newline rule for target spellings guards in-process callers only, because `pwsh -File` refuses such an argument before the script runs.
- After red, the implementer's one dispute was settled against the ticket: the public check `wcpv_014` expected seven tab-separated pieces in a manifest target row, while the ticket's row, the check's own exact-bytes oracle, and the private oracle all have six. The public owner corrected the count and its message; nothing else in that check changed.
- The source review took two rounds. The first asked for three medium repairs: attribute reads matched Git's echoed path, which Git quotes for non-ASCII names, so a legal non-ASCII target could not be frozen (the tool now reads `git check-attr -z` as NUL-separated fields); a target spelled with a leading `-` was read by `git hash-object` as an option (a `--` now precedes it, and every path-taking Git call was audited); and the manifest rows were sorted in UTF-16 order, which differs from byte order for characters outside the Basic Multilingual Plane (the rows now sort by their UTF-8 bytes). It also raised two low ones: a pause-seam marker path that cannot be written now refuses with the seam's invalid-request shape instead of an unhandled error, and an explicitly empty configured setting is still recorded truthfully while the manifest reader now accepts it, so the pair round-trips. A single-target crash the sort repair introduced was caught by both suites and fixed. The second round accepted with no finding.
- The private review took two rounds. The first asked for one high repair, a vacuous pass: the restore lane bound `-Target` to the manifest's only target, so a tool that obeyed `-Target` on restore passed. The lane now binds a second, untracked path the checkpoint commit does not carry and proves it stays damaged; the reviewer's literal repair left a tracked file dirty, which the ticket's verify step refuses, so the untracked form was used and the reviewer agreed. Three medium repairs followed: the forced `status` run's whole report is pinned; the restore now gets the same full before-and-after node comparison as the freeze; and every child runs with its temporary folder inside the lane's owner tree, which is compared byte-for-byte around each verb, so proof bytes left behind are caught. One low was declined because landed `t107` pins those bytes. The second round accepted with no finding.
- The damage plan found one coverage gap before any fault ran: the ticket says a filter that mangles bytes in either direction refuses, but only the checkout direction was exercised. Within the existing WCPV-015 row, the public check gained a twin whose filter is attached through `.git/info/attributes` after the commit, so the tracked status stays clean while only cleaning the current bytes fails to reproduce the recorded blob. This was confirmed with Git in a scratch folder before it was written, and both reviews judged it inside the row.
- The damage plan then showed the source review's three medium repairs had no lane protecting them. The private owner added, within the existing HT-124-02 and HT-124-05 rows, a freeze of a tracked `-dash.txt` and a tracked `café.txt`, each pinned to exact manifest bytes, and a freeze of two names whose UTF-16 and UTF-8 orders disagree, declared in reverse, asserting UTF-8 byte order; its oracle now reads attributes with Git's path quoting off, so it sees the raw spelling. A third private round accepted these with one low note, a case-insensitive sort passing every private lane; it was declined because the public `wcpv_014` freezes `README.md` and `items/item-1.md`, whose byte order a case-insensitive sort reverses.
- The first full workspace proof found a real defect, and that proof was discarded. After a drifted restore, once Git's cached file facts for the converted bytes were old enough that Git stopped re-checking the file, restoring the settings and running `restore` again refused forever: `git restore` keeps an index entry whose blob and mode already match and skips a file whose cached facts match, so the refusal's own guidance could never succeed. The private cross-feature lane had passed only because it ran fast enough that Git still re-checked the file. The ticket now resets each target's index entry to its recorded blob, with no cached file facts, in one `git update-index` call before the unchanged restore command, and names that call's failure and kill boundaries. The private owner made the lane settle Git's cache deterministically (an old modification time and a refresh while the drift is in force); it failed against the earlier script and passes against the repaired one. A third source round and a fourth private round accepted the change with no findings.
